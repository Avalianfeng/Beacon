# 操作坑（短条目）

按症状检索。机制讨论见 [系统设计债.md](系统设计债.md)。

## 入口与播种

| 症状 | 原因 | 怎么动 |
|---|---|---|
| 注入后仍进 basic→improved | 默认 `stage_target=basic` | `--plan` 播种必须 `final`（产品已做；手改 state 别改回去） |
| 第一枪 `blueprint_critic` 7 分停 | plan 空字段 / coverage 空泛 / Q4 写成 maximize | 补 `plan.json`，**新开** `--out`，禁止 restart |
| `plan check` 绿但仍被 blueprint 打回 | check 挡不住 critic 的语义分 | 按交棒 `edit_plan`；check 只挡一半 |

## 代码与血缘

| 症状 | 原因 | 怎么动 |
|---|---|---|
| 血缘：未观察到对声明附件的真实读取 | `_entry` 只读 `研究/data`，没 `open` `source/附件*.xlsx` | 改 `_entry` 真读附件 → `reference add --force` → `restart --from coder` |
| figure 任务失败、无 PNG | 冻结脚本没把研究图 copy 到 cwd | `_entry` 落盘 PNG，或 figure 任务能找到的路径 |
| `restart --from coder` 拒、哈希变了 | `reference add` 后还带了 `--problem` | **不要**带 `--problem`；manifest 已钉死 problem sha |
| `RESULT WD90 仅含 1 个指标，至少需要 3 个` | 旧口径：同 stdout 对照行也过主方案 `min_metrics` | **已修**：下限只约束 `ours`（或 baseline 任务的 expected id） |
| `figure 未产出 png` 但目录里已有图 | `copy2` 保源 mtime，runner 差集为空；旧 attempt 残留 | **已修（冻结）**：冻结 figure 若差集空则回认工作目录 `*.png`；非冻结仍要求本次新写出 |

## inject 敏感性

| 症状 | 原因 | 怎么动 |
|---|---|---|
| inject `SyntaxError`（`from __future__`） | 把 `data_dir=...` **拼到源码开头** | 必须 `exec` 注入命名空间，不能文本拼接 |
| inject 找不到附件 | 跑的是 `workdir/_run.py`，`__file__` 不是题目录 | wrap 注入 `data_dir` 指向 `problems/<题>/source` |
| `--plan` 缺 `source/inject/sensitivity.py` | 正式路径真停 | 写脚本；参数名与 plan `sensitivity_relevant` 钉死的中文名一致 |
| 无 `--plan` 缺 inject 却继续 | 旧路径 `phase=done` 滑走（兼容） | 正式做题必须 `--plan` |

## writer / paper_critic

| 症状 | 原因 | 怎么动 |
|---|---|---|
| paper_critic：「正文未引用图表」 | 评的是 `state.paper` 字段，**不是**后来插图的 `paper.md`；LLM 章节常常不写「图 n」 | 写作侧强制「如图N所示」+ 装配前确定性补引；不要指望插图语法被评委看见 |
| 连 restart writer 仍 8 分、issues 换一批 | 评委把「代码没做的方法」当否决（分位数回归、缺货惩罚） | 收紧否决门槛；建议进 suggestions。不要让 writer 编造未执行算法 |
| 假设里出现 `cost_shock` / `q2_week_profit` | plan 假设正文带了 inject 协议尾巴 | 写作前消毒；plan 机读名不要进论文 |
| `restart --from writer`：checkpoint 未停机 | 同 `--out` 已有 worker 在写（`next=writer_section`） | 等它结束；不要并行 restart |
| 假设模板写出拆分配送 / 单车载重 | 旧物流口径残留在 assumptions 模板 | 已改成通用「依据口径」；新题不要再写死他题约束 |

## 运行时

| 症状 | 原因 | 怎么动 |
|---|---|---|
| 网关 `/health` 500，模型却能调 | 健康检查路由不是业务路径 | 探 `GET /v1/models`；长跑前确认 `start.ps1` 还活 |
| `.beacon-worker.lock` 里 PID 已死 | 文件可残留；真正互斥是 OS 锁 | 以 `RunLockedError` / `Get-Process` 为准，不要只看 PID 字段 |
| `--no-interrupt` 后 restart 仍跳过人审 | manifest `no_interrupt` + 已播种的 `human_decision` | 要人看稿就不要用这条；跳过人审 **≠** 已验收 |
| 改 plan/brief 后 restart | manifest `plan_sha256` 不变性 | **新开** `--out` |
| `watch`/`status` 不带 `--out` 指向旧 run | `runs/.beacon-active.json` 只记最近一次启动（结束时不保证回写，可能残留 `running` + 死 pid） | 显式 `--out`；或删 `runs/.beacon-active.json` 再 watch |

## 终态

| 症状 | 原因 | 怎么动 |
|---|---|---|
| `completion.json` `degraded` 仍有 PDF | 质量警告：页数、对照方案数、Overfull hbox | 不等于 `paper_critic` 没过，也不等于可以交；交卷前按警告清单补 |
| `review-check --strict` exit 1 但 RESULT 都在正文 | 旧口径会把年份/图题/口头禅当失败；现口径只核关键 RESULT | 升级后应绿。仍红则是缺 RESULT 或红线 |
| paper_critic **9 分通过**但 issues 非空 | 否决门槛收紧后，风格/未实现方法进列表仍可通过 | 人决定要不要再 `edit_paper`；不要当成「没过闸」 |
| `evaluation` 综评 7.x | 人评维度，不挡 finalizer | 16 验收看人，不看这一分 |
