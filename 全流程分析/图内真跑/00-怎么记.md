# 怎么记（后续会话保持）

主会话在 **Beacon 真跑**（`run --plan` / `restart` / 门禁交棒）结束后，把可复用的东西写进本夹，不要只留在对话框。

## 写哪里

| 发生了什么 | 写 |
|---|---|
| 某题一次完整或半完整图跑 | 新建 `案例-YYYY-MM-DD-<题>.md`，**按节点时间序** |
| 可复用的机械坑（命令拒、哈希、锁、网关） | 追加 [操作坑.md](操作坑.md) 一条 |
| 机制该改、或已经改了 | 改 [系统设计债.md](系统设计债.md) 表格状态 |
| 用法本身变了 | **改定稿 00**，这里只留一句指针 |
| 改了代码或定稿（本轮落地） | 新建/追加 `落地修改-YYYY-MM-DD.md`（一句话指向，不复制长文） |

不要把本夹写成第二套 00。不要写进 `docs/current/`（那是看板，且常故意不提交）。

## 一条案例至少要有

1. **run 目录**、命令、是否 `--no-interrupt`
2. **真实调用**：节点名、模型、大约耗时、是否短路（0ms）
3. **停机/交棒**：`handoff_action`、critic 分数、issues 的**类型**（不必粘全文）
4. **改了代码还是只 restart**：`edit_code` / `edit_plan` / `edit_paper`
5. **终态**：`paper_critic` 分、`completion.json` status、有没有 PDF
6. **未完**：`review-check --strict`、页数/对照门、人验收

证据优先：`runs/<id>/insights/`、`critic-handoff.md`、`completion.json`、终端里的 `[pipeline] node_end`。不要把「生成了文件」当成功。

## 不要记

- API key、`.env`、网关密钥
- 附件 xlsx 内容
- 与做题无关的 git 脏面（`docs/current`）

## 工作日志

`docs/log/YYYY-MM-DD-….md` 只 **Add-Content** 一行指针到本夹即可，不在日志里复制长文。
