# 契约 · 登记代码插座（_entry 与 inject）

> **给谁**：研究者/接洽会话。**何时**：研究收束后、启动图之前（定稿 [00](../../全流程定稿/00-正式闭环.md) ⑨；顺序见 [14-plan与登记](../../全流程定稿/14-plan与登记.md)）。
> **本文把"怎么写"压成一张纸**：命令与坑仍以定稿 00 / 经验夹为准；骨架抄 [模板-reference_入口.py](模板-reference_入口.py) 与 [模板-sensitivity.py](模板-sensitivity.py)。
> 脚手架：`scripts/scaffold_entry.py` · `scripts/scaffold_sensitivity.py`（不自动搬研究业务逻辑）。
> 实况对照：`problems/cumcm23-c/source/reference/_entry.py` 与 `source/inject/sensitivity.py`。

---

## 1. 两张插座，边界别混

| 文件 | 职责 | 谁执行 | 产出去哪 |
|---|---|---|---|
| `source/reference/_entry.py` | **主求解**：实现模型卡，出各问关键结果 | 图外 `reference run`（冒烟）；图内 coder（冻结 wrapper，哈希校验） | Q 行 + `RESULT:` → 论文主数字 |
| `source/inject/sensitivity.py` | **敏感性扫参**：按研究网格重跑 | 仅图内敏感性节点（exec 注入 `data_dir`） | `RESULT: parameter=…` → 论文敏感性节 |

- `_entry` 只被主求解链执行，敏感性节点**不会**执行它；扫参必须独立成 inject 文件。
- 两文件都在登记后落进题根 `source/`；`reference` 带哈希登记，inject 不带（缺/失败=正式路径停机交棒）。

## 2. 通用铁律（两者都守）

1. **不手抄数字**：数值从 `研究/data` 重读（`_entry`）或**重算**（inject）。对照 `研究/_数据账.md`。把研究结果原样 print 交差 = 伪造证据。
2. **不知道自己在哪跑**：exec 包装只注入 `data_dir`（绝对 `source/` 路径）、不传 `__file__`、cwd 是 `runs/<id>`。定位顺序：注入的 `data_dir` → `__file__` 推题根 → 环境变量 → 放弃。**不要**把 `data_dir=…` 拼进源码开头。
3. **血缘与读表分开**：读 `研究/data` 摘要可以；**必须另**真实 `open` `problem.json` 声明的附件（读前 64 字节即可）。只读研究表、不碰附件 → `code_verify 无主证据`。
4. **fail loud**：缺表、缺附件、断言失败 → 抛错退出。宁可停机交棒，不许静默出空数/旧数。
5. **健全断言**：无 NaN/Inf、量级关系、结构计数。脚本先自撞墙，坏数不进图。
6. **时间预算**：600s 内跑完；吃不下就缩小数据面。

## 3. `_entry.py` 输出契约

- **Q 行**（人/表/评审读）：`Q<id>: k=v k=v …`。字段名用 ASCII 标识符；值=数字或 `[a,b,c]`；`note=` 放定性说明。每问至少一行。
- **主方案证据行**：`RESULT: baseline=ours <指标>=<数值> …`，**至少 3 个指标**。
- **对照行**（finalizer 质量门计数）：每套对照**独立一行** `RESULT: baseline=<名> <共同指标>=<数值> …`，与 ours 有共同指标且数值不完全相同。**只写在 Q 行里的对照不算**。
- **血缘**：真实 `open` `problem.json` 声明的附件（读前 64 字节即可——机器查"碰过没"）；执行 cwd 里落 **PNG**（runner 收为证据图）。只读 `研究/data` 摘要、不碰附件、不出图 → `code_verify 无主证据`。
- 图外冒烟与图内执行同源同码，数字应一致（对账锚）。

## 4. `inject/sensitivity.py` 输出契约

- 每个网格一行：`RESULT: parameter=<参数名> values=[…] results=[…]`，两个列表**等长**。
- **参数名必须与 `plan.json` 的 `sensitivity_relevant` 钉死的名字一致**（中文名带英文别名括号，如 `成本冲击 (cost_shock)`）——LLM 出的扫参计划靠它对齐。
- 中心点与主方案对齐（如 `q2_week_profit`），否则解读/评审会说"对不上主结果"。
- 网格来自研究（加成带、成本冲击、损耗缩放……）；研究表只是参数参考，数字以图内重跑为准。

## 5. 验收自查（写完 → 过闸）

```text
1. reference add --force → reference run → verify（三查过）   ← 图外冒烟
2. run --plan 全图：
   - model_code_consistency ≥8（无"无主证据"=血缘过了）
   - 敏感性节点不停（参数名对上了）
   - finalizer：对照 ≥2（RESULT: baseline= 行）；剩下黄牌应是页数/Overfull 类
3. 交卷前：review-check --strict 数字对账 + 人看完整初稿
```
