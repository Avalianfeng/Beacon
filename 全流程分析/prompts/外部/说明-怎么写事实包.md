# 说明 · 怎么写事实包（新题临时生成）

不要把死题面塞进可复用模板。新题在 `problems/<题>/source/方向生产-提示词包.md`（或等价填充件）写给人读的摘要。

**上游依赖**：02 EDA 画像的 `data_profile.md` + `eda/图说.md`。读图任务**只从图说压缩**，禁止另编一套，禁止「每附件一图」套话。

## 建议章节结构

### 〇、怎么发（本题一句话）

指向 `prompts/外部/操作-怎么发给第二家.md`；写明上传哪 1–2 张拼图（文件名）。

### 一、附件清单

- 文件名、角色、行数/规模  
- 外部现在能看见什么 / **故意不给什么**  
- 列名原文；**表里没有的字段**（缺口必须写进清单，例如无预期销售量列）  
- 哈希与路径以 `source/manifest.json` 为准  

### 二、读图任务（从图说压缩）

按 `说明-怎么写读图任务.md`：

- 上传策略  
- 读图表（特征 / 请回答 / 不要读成）  
- 图说了什么（无图像底线）  

拼图路径写绝对或相对题根均可，但须真实存在。

### 三、主动索取

链到 `协议-索取.md`；本题若已闭环注明轮次。

### 四、事实包（数字）

1. **题面全文**（或与 `problem.md` 一致的摘录）  
2. **已读取的聚合数字**（与概览图配套，不是替代图）：规模、构成、对齐、基线种植摘要、经济参数量级  
3. **粗算锚点**（不是答案）：决策窗口、约束数字、量级提示  
4. **待裁决草稿**（人未拍板）：口径候选，标「待拍板」  

## 质量线

- [ ] 读图表每一行能在 `eda/图说.md` §1 找到对应文件  
- [ ] 「不要读成」覆盖空模板 / 缺口列 / 图说点名的易错读  
- [ ] 聚合数字可追溯到 `data_profile` 或 `_profile_stats.json`  
- [ ] 未要求第二家检索本题题解  

旧题（如 cumcm23-c）填充件可保持历史形态；**新题与重跑**一律按本节。
