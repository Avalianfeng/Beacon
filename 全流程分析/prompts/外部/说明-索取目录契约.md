# 说明 · 索取目录契约（共享切片 ≠ 视角档案混放）

> 对应定稿 [04-索取与回填](../../全流程定稿/04-索取与回填.md) · 多视角 [说明-多视角版本.md](说明-多视角版本.md)。  
> **反面教材**：cumcm23-c 把轮1+轮2 的 csv/png、两份 `_compute*.py` 全堆在同一个 `外部/索取/`——编号连续看起来整齐，实则**视角/轮次/脚本/可复用**搅在一起，后人无法回答「这是谁要的、哪一轮发的、能不能给 V2 复用」。

## 1. 一句话

| 东西 | 放哪 |
|---|---|
| **可复用**：稳定口径切片、通用算子脚本、全局索引 | `外部/_共享/` |
| **完整索取档案**：该视角要了什么、哪一轮、对照表、本轮打包用文件集、视角专用脚本 | `外部/V*/索取/` |

「切片是共享的」= 同一份数字事实可以被多个 V 引用。  
「完整内容在各自 V」= **索取叙事与发送现场**不进大锅；每个 V 自洽可回放。

## 2. 目录契约（新题默认）

```text
problems/<题>/认知地图集/外部/
  README.md
  _共享/
    README.md                 ← 共享层说明
    scripts/                  ← 可复用算子（无 V 私货）
      README.md               ← 每个脚本：输入/输出/何时用
    切片/                     ← 可复用产物（csv/png/…）
      _索引.md                ← 必有：切片ID · 文件 · 口径一句话 · 首次产出V/轮 · 复用记录
  V1/
    索取/                     ← 【该视角完整索取空间】
      README.md               ← 本 V 索取总账（轮次、条目数、状态）
      轮1/
        清单.md               ← 【索取】原文条目 ↔ 文件路径（本目录或 `_共享/切片/`）
        …                     ← 本轮发送所需文件（见 §3）
      轮2/
        清单.md
        …
      scripts/                ← 可选：本 V 编排脚本（thin；调用 `_共享/scripts`）
    轮次/  外发归档/  地图/
  V2/ … 同构
```

旧题 cumcm23-c 扁平 `外部/索取/` = **历史混放形态**，不复制到新题。

## 3. 打包怎么做（避免再混）

对外发送**只打包当前视角当前轮**目录：

```text
python scripts/pack_external_upload.py ^
  --dir problems/<题>/认知地图集/外部/V1/索取/轮1 ^
  --stem 给第二家-V1-轮1 --resolve-shared
```

打完的 `给第二家-*.md/.png` → 默认进 **`V1/外发归档/`**（`--resolve-shared` 时；不要丢进 `_共享/`）。

`轮N/` 对「这一次上传」自洽的两种做法：

- **推荐（脚本）**：清单写切片 ID 或 `_共享/切片/<文件>`，再：
  ```text
  python scripts/pack_external_upload.py --dir …/V1/索取/轮1 --stem 给第二家-V1-轮1 --resolve-shared
  ```
  脚本读索引、临时 stage、成品进 `外发归档/`；**不必**手拷共享文件进轮目录。需要轮内留档时加 `--materialize`（复制，Windows 不用硬链）。
- **禁止**：把 `_共享/切片` 整库或别的 V 的 `索取/` 当 `--dir` 打包——会再次「全混在一起」。

新题目录脚手架（默认仅 V1）：

```text
python scripts/scaffold_external_maps.py --problem problems/<题>
python scripts/scaffold_external_maps.py --problem problems/<题> --versions V2
```

## 4. `_共享/` 放什么 / 不放什么

| 放 | 不放 |
|---|---|
| 多 V 可能引用的口径表/图 | 某一 V 的【索取】对话原文 |
| 通用 `_compute_*.py` 算子 | 「给第二家-打包」成品（属 `V*/外发归档`） |
| `_索引.md` 复用账 | 地图、轮次判断、主持结论 |
| 脚本 README（接口说明） | 未标注口径的临时试算 |

新切片首次算出：先写入 `_共享/切片/` 并登记 `_索引.md`，再在本 V `轮N/清单.md` 挂上 ID，然后 `--resolve-shared` pack。

V2 若索取「同口径」：先查 `_索引.md`；命中则**复用 ID**，只在 V2 `索取/轮N/清单.md` 记账，勿复制第二套口径不同的同名表（除非口径变了，新开 ID）。

## 5. `V*/索取/` 完整内容清单（自查）

每个已开索取的 V，下列应齐：

- [ ] `索取/README.md`：本 V 要过几轮、现在第几轮、条目总数  
- [ ] 每轮 `轮N/清单.md`：条目 ↔ 文件 ↔ 共享 ID（若有）↔ 用途  
- [ ] 每轮发送：用 `--resolve-shared` pack，或轮目录已自洽可独立 pack  
- [ ] 视角专用编排脚本（若有）在 `索取/scripts/`，并注明调用了哪些 `_共享/scripts`  
- [ ] 外发成品在 `V*/外发归档/`，不在索取根更不在 `_共享/`

## 6. 谁可读

| 角色 | `_共享/切片`+`scripts` | `V*/索取/`（清单与轮目录） | 其他 V 的索取 |
|---|---|---|---|
| 主持算数 / 打包 | ✅ | ✅ 当前 V | ❌ 勿打进包 |
| 外部 Vn 对话 | ✅（经回填包） | 只通过本 V 回填包看见 | ❌ |
| 本地探索 | ✅（事实切片） | ❌ 默认不读（避免吃到该 V 的索取叙事） | ❌ |
| Diff | 一般不需要；要溯源数字可查 `_索引.md` | 可选溯源 | 同左 |

## 7. 与 cumcm23 混放的对照

| cumcm23 `外部/索取/` | 新契约 |
|---|---|
| `01`–`08` 与 `11`–`15` 同层 | 分到 `V*/索取/轮1`、`轮2` |
| `_compute.py` + `_compute_r2.py` 同层 | 通用进 `_共享/scripts`；轮次编排进 `V*/索取/scripts` |
| 无「谁复用」账 | `_共享/切片/_索引.md` |
| 打包对着整夹索取 | 打包对着 `V*/索取/轮N` |
