## 2. 各步：意义 · 是否可靠 · 要不要改

### S4 dry-run

- **意义**：挡「brief/附件/路径没齐就开写论文」。本题 blockers 空，只 WARN 缺 sklearn（入口不用）。
- **可靠**：高。机械、可复跑。
- **优化**：本题不必。WARN 噪音可日后按题过滤，不挡。

### 薄 `_entry` 读 `研究/data`（不重扫附件）

- **意义**：把「研究会话已经算完」接到 Beacon 证据链，避免 S5 再发明一套求解。与定稿 10-s5（算）/ 13-s5（登记）分工一致。
- **可靠**：数字链可靠——MAE/周方案/28 行都从同一批 json/csv 读出，assert 钉住 `q3_n==28` 且 BLEND < WD90 < YOY。  
  **不可靠的是「独立复核」语义**：`recertify --verdict pass` 是登记，不是第二人重读 CSV。人闸本次是口头视为通过。
- **优化（值得）**：操作面契约仍写「S5=子 agent 写代码」。本题实际是**适配器**。定稿已区分 10 vs 13；契约文案应改，避免下一题又从零 codegen。  
  **不必**把 `_entry` 做成重算器。

### `__file__` / `data_dir` 路径

- **意义**：不修则 S5 整链作废。根因在 `reference run` 的 wrapper：`exec(..., {"data_dir": data_dir})`，不像 `frozen_asset` 那样带 `__file__`。
- **可靠**：修入口后稳定（绝对 `data_dir` + 父目录=题根）。
- **优化（小、该做）**：CLI wrapper 补 `"__file__": str(entry_path)`，与冻结包装齐。题级 `_entry` 继续兼容 `data_dir`。不要每题靠猜 cwd。

### 为 tables 改 Q 行、再 recertify

- **意义**：`tables.json` 的 `field` 必须是列表；标量装不上。三张表把回测 MAE、周补货/收益、28 方案钉进论文交付表，这是 S6「数字来自执行」的最小可见面。
- **可靠**：这三张表与 evidence 同源，可靠。  
  **不覆盖**研究里的品类×日明细、28 行 SKU 表——那些仍在 `研究/data/`，paper 骨架没装配进去（清单型表本就约定不走 tables.json）。
- **优化**：装配器允许「无 lead 的单行标量」或 `field` 接受标量，可少一次「为了出表改 Q 行再全链 recertify」。  
  **不要**把 28 行 SKU 硬塞进 `tables.json`（T-12 已取消）。

### `reference paper` 骨架

- **意义**：零编造：结果数字只能来自 evidence。分析槽【待展开】留给 expand 或人。S6 完成判据只要 `paper.md` 能被 stage 解析到——**骨架即过关**，不是终稿。
- **可靠**：数字溯源方向对。  
  摘要把 `mae_list` 与分项 MAE **打两遍**，可读性差，但不造数。  
  `check_paper_numbers` 对骨架 WARN（题面日期、sha256 切片、tables.json 行号）——**预期噪音**，exit 0；`--strict` 会误杀骨架，S7 用人判。
- **优化（中）**：摘要模板按题写 `paper_abstract.md`，只填 RESULT 主锚（BLEND MAE、周收益、n=28），不要自动倾倒全部 Q 键。  
  假设段无①②③时用 topic——**已修 CLI**，应保留。

### `reference expand`（T-11）

- **意义**：设计正确：分析槽可以写散文，**不能**引入白名单外新数字。防止「展开」变成第二套造数。
- **可靠（本题）**：**低。** 两次烧 LLM，两次因派生数失败。补白名单会诱发下一轮派生（28−29≈2.41、负号另算 token）。无限追 Q 行 = 把研究笔记搬进 evidence，失去红线意义。
- **优化（该停手，改策略）**  
  1. **本题默认**：骨架交差；分析用题根 `解题说明.md` 人工贴或写作 agent 填槽，**不要**再为 expand 扩白名单。  
  2. 若仍跑 expand：白名单应含 brief 已声明的对照数；或「新 token 若是白名单数的四则运算」放行（有实现成本，另决策）。负号不应单开 token。  
  3. 探索性真跑：T-11 标成 **可选**，与定稿 14「本轮可停」对齐，避免 stage 已 S6 却误以为论文写完。

## 3. 总评（一句话）

登记链（S4→verify→recertify→tables→paper 骨架）**值得做、数字可靠、该保留**；expand **对本题不可靠，不必为过关而优化到绿**；S7 机械闸 **能跑、非 --strict 为绿，不能当人审**。最大流程债仍是：操作面「S5」像写代码，定稿「13-s5」像登记——下一题按登记器走，少烧一轮假求解。

## 4. 不要从这次推出的结论

- 不要因为 expand 红线就关掉「禁止新数字」（那是唯一防造数闸）。  
- 不要把 `recertify pass` 当成第二人已核对 28 行 CSV。  
- 不要为了 S6 把 `研究/data` 手改进 paper。  
- 不要把 `review-check` exit 0 当成论文可交；骨架无图无分析，claims 16 条 WARN。  
- 不要代跑 `accept --approve`。
