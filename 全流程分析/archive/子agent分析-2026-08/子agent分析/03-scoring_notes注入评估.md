# scoring_notes 注入机制评估（worker · 2026-08-28）

## 核心问题（4 条，按严重性排序）

1. **评分点信息在管线中段起完全断供**：scoring_notes 只在 analyst/blueprint_critic 被消费，modeler→writer→paper_critic 全部拿不到。评分点能否生效完全押注于「蓝图一次性完整翻译」单点；任何翻译遗漏静默穿透后续所有环节，且全程无环节能发现。「逐格填齐、格式一致、数字+统计量+推导」这类硬性产出无机制保障落到论文。

2. **把关位全部失效，且无兜底**：paper_critic 零 brief 注入（连题面要求都对照不了）；evaluation 虽有「逐条核对得分点」固定分支但从未收到清单——整条管线不存在任何「对照评分标准核验产物」的环节。两个最后防线空转，产物缺失/错误在走通流程时不被拦截，给出「看似走通」的假信号。

3. **evaluation 的 SYSTEM 承诺与实际行为不一致**：宣称「若提供评分细则则逐条核对」，但调用方从未传参，分支是永久死路径。依赖评价结果的人会误以为输出经过得分点核对，实际只是交付物齐备性检查——机制层面的自欺。

4. **与公理的张力在裁剪依据上**：公理禁止的是「官方答案」，scoring_notes 是自拟的（本不属于被禁内容）；但注入裁剪呈现「前两环全量、后全无」的断层，且 evaluation 预留接口却从不接线。裁剪看起来是机械字段白名单所致，而非依据内容性质决策——防注入公理与自拟评分点可用性之间没有清晰边界规则。
