# 第 2 站：操作面 S4 预检 + S5 求解验证

## S4 预检：烧 token 之前，让机器先自检一遍

- **为什么需要**：开求解 = 开始烧真金白银（LLM 调用）。spec 有问题、blockers 未清、附件缺失、库没装 → 启动即失败。S4 是**成本保护闸**：机械检查 spec/brief/可达性/附件/缺库，不调用任何解题 LLM。
- **命令**：`run --dry-run --problem <spec> --brief <brief> --out <run>`。
- **行为**：`feasibility.blockers` 非空 → **拒绝启动**（S0 人填 blockers 的兑现点）；缺 sklearn 等 → 只 WARN 不阻断（A3：求解脚本必须避开这些库）。
- **产物**：`preflight.json`（ok/warns/blockers/brief_path）写入 `runs/<run>/` 与 `problem.json` 同级——**stage 认 S4 的依据**。
- **失败**：预检不过，不得进入 S5/S9。修 spec/brief/附件后重跑同一命令。
- mcm51-c 对照：`preflight.json` 存在（缺库 WARN，P2 dry-run）。

## S5 求解验证：科学度的生产环节——数字必须自己跑出来

- **为什么需要**：整条证据链的起点。论文每个数字必须来自**可复跑代码的真实输出**（铁律：「生成了文件」≠「成功了」）。防两类失败：算错（脚本 bug）与编造（数字无来源）。
- **信任链三层**（全体系最精巧部分）：
  1. `reference verify`（机械三项）：只查形式——run_success / no_nan_inf / has_result。**故意不查口径**（口径是开放智力问题，机器判不了）。
  2. `reference recertify`（独立复核登记）：第二执行者（人/另一 agent）复核后登记 `independent-review.json` 的 `verdict=="pass"`；可选 `--rerun` 对照第二份 `result` 数值。**缺 pass 不能进 S6**。
  3. **人检锚点**：关键交付表被独立锚点逐格对上（C 题教训：**整模型 RMSE 好看仍可能表 1.1 全错**——S1 记的「同步跳变 idx≈1325/4672」就是用来对格的）。
- **完成判据**：`evidence-package.json` 存在 **且** recertify `verdict=="pass"`（stage 认 S5）。
- **L4 纪律**（D-006，C 题教训回流）：敏感性分析必须写明主口径取舍；Δy/累加重建必须声明 y0 与公式；异常检测前必须有本题操作定义——机械检查 `check_l4_gates.py`（G1–G4）。
- **失败交棒（关键纪律）**：脚本错 → 停在 S5 修；**不许用流水线 coder 生成包装绕过**（docs/19：生成包装=停机源——LLM 生成的包装不可控、掩盖原脚本真实错误、S7 溯源必穿帮）。换执行者 = 交出脚本 + evidence-package + recertify，**不交出「自报分数」**。
- **产物形态**：脚本 stdout 打 `RESULT:` 行（主指标 7 个）+ `Q:` 行（逐问交付结果，表格装配只消费 Q 行）→ `reference run` 解析成 `evidence.json`。mcm51-c 对照：`source/reference/` 7 文件（q1–q5 + _entry.py）、`evidence-package.json`、`independent-review.json`。
