# 第 2 站：操作面 S0–S8（主体，分轮走）

> 核心：每阶段讲透「为什么需要 → 解决什么 → 产物 → 命令 → agent 协作 → 失败交棒」，对照 mcm51-c 真实产物。

## S0 导入：题目进入体系，从此不可变

- **为什么**：题目须可追溯（原始资产冻结）、可机器读取（机械校验前提）、可判完成（下一棒知道过没过）。
- **产物**：`source/`（题面+附件，全部 sha256 登记 manifest.json + problem.json.source_files）+ `problem.md`（事实层，只读）+ `problem.json`（解释层：title/background/questions/feasibility，人可改）。
- **关键设计**：事实层/解释层分离——题意理解是开放问题，人可反复改 questions（mcm51-c 把 5 问压缩成结构化版本）；原始题面一字不碰。`feasibility.blockers` 人填（学-07：人对决策性内容可摄取不受限信息与推演），S4 非空即拒绝启动。
- **命令**：`problem import/show/stage`。import 不做 AI 起草。
- **失败**：题号冲突 → --force；source/ 必改 → 重新 import --force 重算哈希，从 S0 再走预检。
- 细节：哈希锁文件名——同一附件中英文名两个哈希，source/ 必须整体冻结（不改名不动格式）。

## S1 数据探查：选方法前把数据变成可对撞的证据

- **为什么**：没探查的对撞是「方法名 PK」（docs/18 §11.1）。
- **产物**：`data_profile.md`（约定路径，无命令）+ 每附件 ≥1 张概览图（D-007 强制，eda/附件N.png）。
- **内容**：总体速览（列/缺失/量纲/异常/锚点/时序）、诚实声明（数字来自真实读取，未推断清洗）、关键锚点（如附件1 A−B 漂移、同步跳变 idx≈1325/4672/8205/8790）、S1 情报喂 S2（如实验集表面位移 100% 缺失 → 影响「怎么验证预测精度」的方向决策）。
- **为什么概览图是判据**：图让「看不见」变「看得见」，对撞有共享视觉证据。
- **不注入 brief/流水线**：人侧证据包，防 LLM 单点解读污染方向。
- **失败**：探查不足进 S2 → 方法名 PK；错 → 重写 md，不必重 import。

## S2 探索：先扩大认知空间，再收敛

- **为什么**：空白问共同特征=建模视角没进认知空间（H04）；方向质量靠结构保证，不靠模型天赋。
- **协议**（brief-playbook，无 CLI）：开放探索 → 探索消化 → 多视角对撞（2-3 家不同家族模型扮演出题人/评阅人/怀疑者，人主持 diff）→ 逐问清点 → 方向收敛。
- **口径防线 v3**（mcm51-b 教训）：假设分级（①原文/②推断/③经验）；弱依据禁令（禁「题面没有此机制」式禁止）；逆命题检查；题面信号清单；备选口径+数量级差必记。
- **产物**：exploration.md（认知地图）+ 逐问清点.md + 领域知识.md（D-007 强制：术语/典型模式/陷阱，联网核查）+ 对撞记录（口径风险-第二读者.md）。
- **完成判据**：人主持过 diff；互不兼容项标出；「最容易整体漏掉的东西」有一节；领域知识卡存在；没把官方答案写进文件（防泄漏）。
- **警觉信号**：对撞开始深入具体算法细节（参数/包）→ 过早收敛，停，重跑探索。

## S3 方向收敛（brief）：把拍板方向压成可注入约束

- **为什么**：exploration 长文不能直接注入；brief 是唯一方向注入物。
- **真实形态**（mcm51-c 51 条）：per_question_direction（统一状态观：观测=慢变趋势+阶段状态+外部扰动+传感器噪声，水文链/工程链两通道）、formula_notes（速度统一 mm/h，禁混用）、red_lines（爆破空值=非爆破时刻分级①禁插补；实验集表面位移=预测目标非缺失）、required_discussions（数据语义三裁决必进假设）、figure_plan/scoring_notes/data_notes/reference_direction。
- **注入面**：六处 prompt（analyst/blueprint_critic 全量、modeler 方向+公式、model_critic/coder 公式+红线、writer 讨论点分组）。
- **红线价值**：方向可机检、可追责（S5/S7 时「有没有插补」可检查；分级让评审逐条核「是否题面原文」）。
- **命令**：`brief init`（空八字段）→ `brief check`（[OK]）。agent 起草，人拍板，改完必 check。`brief dialogue` TTY 专用，外部 agent 不走。
- **失败**：check 失败 → 修 json；方向被证伪 → 回 S3 改 brief，从 S4/S5 重来（原则 8，不在下游投票）。

## 附：5.2 字段映射表白话解释（2026-08-28，用户要求非表格形式）

**先给一个总抓手**：brief.json 就是给流水线（以及 S5/S6/S7 的校验）的「任务说明书」——它回答一个新手 agent 开工前会问的十个问题。探索阶段（exploration.md）是散落的认知原材料，brief 是压缩后的成品，5.2 表就是「哪堆原材料进哪个桶」的搬运规则。下面每个字段按「装什么 → 为什么需要这个桶 → 从探索的哪一段搬来」讲。

1. **per_question_direction（逐问方向）**——装每一问的「主方向 + 禁止方向」。比如 mcm51-c：Q1–Q5 统一状态观（观测=慢变趋势+阶段状态+外部扰动+噪声）。为什么需要：流水线每个节点拿到它才知道这题「该往哪想」，也知道哪些方向明令不许碰。从哪来：对撞收敛后的方向结论表。每条有个稳定 id（q1-direction 这种），后续门禁/溯源拿它当钥匙。

2. **formula_notes（公式口径）**——装单位、换算、关键公式的约定。比如「速度统一 mm/h：10min 采样步长=1/6h，单步速度=6×Δ位移；禁止 mm/10min 与 mm/h 混用」。为什么需要：单位混比是真实翻车事故（brief-v1 的 3.2 单位口径），公式口径必须写死。从哪来：探索中敲定的关键公式和参数；数值锚点只能从题面+附件+常识重建（防泄漏——不允许引用官方答案）。

3. **required_discussions（必答讨论点）**——装「论文里必须讨论什么」。比如 mcm51-c 的「数据语义三裁决必须进模型假设」（爆破空值=非爆破事件、实验集空值=预测目标、时间基准冲突声明）。为什么需要：出题人想看的东西漏了就丢分（H02 的四问空白），必答项是防漏的清单。从哪来：出题人视角分析+对撞中的分歧裁决。注意 sections 用白名单（abstract/assumptions/model_section/…），保证讨论落到论文的指定章节。

4. **red_lines（红线）**——装「绝对禁止做什么」。比如「爆破空值禁止插补成连续值」「实验集表面位移空值禁止当缺失进补齐」。为什么需要：有些错一旦犯了整问归零（mcm51-b 的教训），红线是机器可检的禁令——S5/S7 能查「你插补了没有」。从哪来：对撞中识别的口径/风险红线；理想态每条带假设分级（①原文/②推断/③经验）和备选口径，弱依据禁禁令必须写备选（比如 mcm51-b 假设 9 的正确写法）。

5. **figure_plan（图计划）**——装「每问必须配什么图」。比如 Q1 校正前后对比图+残差图。为什么需要：评分标准类题目普遍按图给分，图漏了就丢分；每图带 question_id 保证装配时图能找到归宿。从哪来：探索中对题面「必配图表」的识别。

6. **scoring_notes（评分要点）**——装自拟的评分点（注意：不是官方答案，是从题面+探索推断的「评阅人可能看重什么」）。比如「表1.1/3.1/3.2/4.1 必须逐格填齐、格式与题面一致」「每问给数字+检验统计量」。为什么需要：给 writer 和评审一个「这题怎么算答好」的锚。从哪来：自拟 rubric。

7. **data_notes（数据口径）**——装「附件怎么读」。比如列名精确原文、sheet 结构、哪些列要统一前缀。为什么需要：数据读法错了全盘皆错，读法必须在开工前钉死。从哪来：S1 数据探查（data_profile.md）+ 探索中的数据讨论。

8. **reference_direction（参考方向）**——装方法族关键词。比如 mcm51-c 的「结构变点检测（PELT/BinSeg）、小波阈值去噪、MAD/IQR 异常检测、Saito/Voight 预警准则」等 8 条。为什么需要：给 modeler/coder 一个方法空间（该往哪些方法家族里找），不限制具体实现。从哪来：文献/搜索结论。

9. **background_knowledge（领域知识）**——装领域常识+专业背景（术语/典型模式/陷阱），来源分级标注（human/model_draft）。为什么需要：模型不认识「孔隙水压力→有效应力→抗滑力」这条因果链，不注入就容易外行。从哪来：领域知识.md。**注意：契约要求写入但 mcm51-c 实际没有这个字段（实现落差，见 用户建议与体系缺口.md C 条）。**

10. **comparison_baselines（对照方案）**——装对撞中被淘汰的候选方案（为什么淘汰、如果用它预期会差多少）。为什么需要：论文里要有对照方案才诚实有力（B20：有效对照 0 个是硬伤）；M4 冻结期手工补。从哪来：对撞中淘汰的候选。**字段暂不进 schema v2，理想态。**
