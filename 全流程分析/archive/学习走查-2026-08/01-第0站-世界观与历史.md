# 第 0 站：世界观与历史

## 0.1 一段失败史：Beacon 为什么是今天这个样子

Beacon 最初的设计是「知识闭包内自转的求解器」：给一道题，LangGraph 全自动流水线跑到底（analyst → modeler → coder → writer → PDF），无人干预。两记重锤改变了它：

**第一记：mcm51-b 赛后官方参考答案回流**——估分 57–60/100，三等中下沿。四问时长全部偏离官方区间；Q4 购置 2 台 vs 官方口径 7 台。根因**不是算错，是假设 9（禁止同类多机分摊）与官方口径冲突**——方向错，全盘皆错。

**第二记：H02 对照实验**——无 brief 时 35–40 分（四个小问空白 40 分），带高质量 brief 后 74–86 分，直接翻倍。

空白小问的共同特征：**不是算错，而是建模视角根本没进入认知空间**。强模型在开放式建模题上的典型失败 = 自洽、优雅、但偏离出题人问的东西，且自我审查发现不了（H04）。

> **结论**：每道题最贵的智能必须花在「方向生产」上；系统只承担「忠实执行 + 确定性校验 + 廉价早期反证」。这就是 S2 探索、S3 brief 压在流水线之前、且由人主持的原因。

## 0.2 三条公理

1. **参考答案不可得**——brief-v1 的数值命中是意外特例，不得把「数值注入」写进通用路线图。
2. **探索负责避免看不见；验证负责避免做错**——两个阶段职责不同，不可互相替代。探索在流水线之前、由人+强模型+联网完成；验证靠确定性证据（残差/量纲/边界/对照实验）淘汰错误可能性。
3. **方向在源头定，错了回源头改 brief 重跑**——体系内不做无依据的 LLM 投票式方向评审。边界：**多模型对撞 ≠ 投票**。对撞在前置、人主持，目标=暴露遗漏（「A/B/C 之外是否还有看不见的 D」）；多模型一致**不构成**方向正确性证据——多模型负责发现可能性，确定性证据负责淘汰可能性。

## 0.3 三种角色分工（D-021 协作协议）

| 角色 | 干什么 | 为什么归它 |
|---|---|---|
| **agent**（外部编码 agent） | 前置探索、brief 起草、口径裁决；**写代码 + 算数据**（科学度）；评审辅助 | 科学度是开放智力问题，需要模型+人；解题代码必须实跑产出数字 |
| **Beacon** | **产完整论文本体**；机械/确定性职责：哈希冻结、装配、数字红线（check_paper_numbers）、L4/必答项闸门、stage 推演 | 确定性责任不能靠 LLM 自觉——可复现/哈希/装配/闸门全是可机检的，交给代码才可靠 |
| **D 盘工作面** | 只做拆开 + 小改造（Word 化、局部修改）；赛后评估 | 论文精排/Word 交付是另一套工作流，Beacon 不越界 |

**铁律**（CLAUDE.md）：涉及真实运行结论，必须给代码/测试/产物证据，不把「生成了文件」当成功。
