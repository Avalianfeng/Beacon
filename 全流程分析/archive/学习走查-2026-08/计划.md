# cumcm23-c 全流程真跑（再修订）

## 硬约束（本轮）

- **你手动补一家对撞模型**（不同家族、只列约束/歧义/数据驱动淘汰，不解法细节）。
- **brief 只能出现在对撞 + 人主持 diff 之后**。禁止学 mcm51-c 赶工顺序（批次1 先 brief、批次2 才对撞）。
- **禁止联网搜索参考答案 / 优秀论文 / 评分标准 / 本题题解**。领域常识只用题面、附件、模型先验；不打开搜索工具查 2023C。
- **评分反馈你手动做**。主会话只交路径和机械闸门报告。
- **文档交叉用、不单信一份**：契约给命令名，18/C 题记录给翻车点，走查给 brief 字段含义；冲突时以「实操里验证过的交棒」为准。

## 流程自梳（开跑前先认这条，再 import）

单份 playbook 把「探索→清点→对撞→brief」写在一起，C 题真跑又曾把 brief 提前。下面是**对照多源后的交棒**，换题可复用。

```text
赛题目录（只读）
  → S0  冻结 source 哈希；人填解释层（questions / blockers）
  → S1  先探查、先出对撞用图（否则对撞=方法名 PK）
  → S2a 开放探索 + 同会话消化（扩大空间，不写 brief）
  → S2b 把 EDA 包喂给你的第二家 → 你贴回 → 人主持 diff（决策点，不是投票）
  → S2c 逐问清点（口径分级、备选、红线候选）
  → S3  才压缩成 brief.json → brief check
  → S4  dry-run（blockers 必须空）
  → S5  子 agent 写可跑脚本；主会话用独立锚点核交付表（不信汇总 RMSE）
  → S6  登记执行 → 表 → 骨架 → expand（论文本体在 Beacon）
  → S7  只跑机械 review-check；论文好不好你评
  → S8  你口头批准后才 accept
  → 外  D 盘 Word/赛后 本轮不做
  → S9  不跑
```

实操里验证过、文档里容易写飘的点：

- S1 必须在对撞前；对撞提示词默认「先淘汰、后选主」，并带上 EDA 证据包（[docs/18](docs/18-全流程实操范例与经验沉淀-2026-08-21.md) §11 数据驱动对撞）。
- 探索第一轮是思考流，必须同会话消化成地图，不能直接填 brief。
- 改 brief = 从 S4/S5 重来，不要在下游投票圆口径（原则 8；假设 9 的教训）。
- 子 agent 自报「模型很好」不够：交付表逐格对附件锚点（C 题 Q1）。
- 最小论文就能做功能验证：摘要+交付表+数字+诚实声明；精写可后置，但 `check_paper_numbers` 不能省。
- `background_knowledge` 契约有、C 题没注入：本轮不立项注入（ACT-08）；领域知识.md 可写，不靠搜题解。

## 人步骤（按真实使用收紧，执行时在对话里点名）

每步主会话会说明：为何必须人做、你需要交什么、交完才能进哪一站。不把 playbook 表格整页塞给你。

1. **S0 blockers / questions**：决策性内容归你。默认 blockers 空（本机可跑）；你改一句即可。
2. **S1 图是否够对撞**：图在之后主会话出初稿，你说「还缺哪类图」或「够了」。不够就补一轮再对撞（缺口 B，两次对齐）。
3. **S2b 第二家对撞（本轮关键人步）**：主会话给你一份可粘贴提示词 + `data_profile`/概览图路径。你在另一家模型跑完，把原文贴回。主会话不做第二家、不搜答案。
4. **S2b diff 拍板**：主会话列出互不兼容项与「最容易漏的东西」；你标保留/备选/扔掉。不投票取平均。
5. **S3 红线与备选口径**：brief 草稿由主会话从清点压缩；你只审 ①原文/②推断/③经验 分级和「弱依据禁令」是否写成禁令。点头后才 `brief check`。
6. **S5 最小可交范围**：四问各交什么数字，你确认或收窄后再派子 agent。
7. **评分（你）**：机械闸门之后。主会话不写估分、不代拟评阅意见。
8. **S8**：你说批准/不批准。
