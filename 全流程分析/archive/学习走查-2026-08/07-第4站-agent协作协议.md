# 第 4 站：Agent 协作协议（D-021）——agent 与 Beacon 怎么配合

> 定位：任何「要不要改 Beacon」的判断，先查本协议。D-020（Beacon 产完整论文职责）+ D-021（协作梳理）的落地。
> 原则：**先梳理协作，再决定改不改机制**——不「觉得需要就改」。

## 4.1 职责边界（谁做什么）

| 方 | 职责 |
|---|---|
| **agent**（外部编码 agent） | 前置工作（探索、brief 起草、口径裁决）；**写代码 + 算数据（科学度）**；按方向把明确内容注入体系；问题回查（体系问题 vs 方向/计算问题）；评审辅助（读必答项清单、人审） |
| **Beacon** | **产完整论文本体**；机械/确定性职责：资产登记+哈希冻结、装配、数字红线、L4/必答项闸门、口径核查脚本、stage 推演；可复现性（同一登记→同一执行） |
| **D 盘** | 只做拆开 + 小改造（Word 化、局部修改）；赛后评估 |

**对照口径（D-020）**：数据与科学度用 agent 跑的版本；论文本体以 Beacon 产出的作改动依据；遇到问题先判定是哪一方的问题，再决定改谁。

## 4.2 协作接口清单（11 个，按方向）

**agent → Beacon（注入）**：
| 接口 | 作用 |
|---|---|
| `brief.json` + `brief check` | 方向性内容注入；口径防线校验 |
| `problem.json source_files` | 冻结资产登记（T-19） |
| `evidence-package` + `check_paper_numbers --evidence` | 任意证据文件（含 agent 临时脚本产出）提取数字白名单——红线覆盖 |

**agent → Beacon（求解登记）**：
| 接口 | 作用 |
|---|---|
| `reference add` | 求解代码登记 + sha256 冻结（A-13 哈希校验） |

**Beacon → 产出（agent 消费）**：
| 接口 | 作用 |
|---|---|
| `reference run/tables/paper` | 求解执行 / 交付表装配 / 骨架装配（数字唯一事实源=evidence） |
| `reference expand` | 骨架 → 完整论文 prose 展开（A-01，增量数字闸门） |
| `stage --json`（next_command/d007_missing） | 推演已完成前缀 + 提示下一步 |
| `review-check` | L4/必答项/数字/gap 机械校验包装 |
| playbook §〇 选型 checklist | 前置智慧选型（双人双读等） |

## 4.3 缺口判定准则（新需求先问三问）

1. **是机械/确定性职责吗？**（可复现、哈希、装配、闸门）——是 → Beacon 做（且只做机械件）
2. **是红线相关吗？**（数字溯源/证据一致/口径核查）——是 → Beacon 提供机械校验件（check 脚本）
3. **agent 临时脚本 + 现有接口能否覆盖？**——能 → **不建新机制，写约定**（落盘格式/登记位置/白名单入口）

**判定例（2026-08-27 首例）——清单型表（原 A-08）**：①「装配什么」取决于 agent 输出格式，不可预知 → 非纯机械；②清单数字进论文须红线覆盖 → 红线相关；③`check_paper_numbers --evidence` 已支持任意证据文件 → 可覆盖。**结论：取消 A-08 机制，改约定**（我们第 2 站已实际走过：表 3.2 = agent 落盘 CSV + 白名单）。

## 4.5 agent 临时脚本参考约定（清单/图/表类产出）

1. **落盘**：`problems/<题号>/source/` 或 runs 本题目录（命名 `*_list.*` / `*_table.*`，md/txt/json 均可）
2. **登记**：纳入 evidence-package（reference add 时一并登记，哈希冻结）——*注：实际 evidence-package 结构无文件列表字段，登记未落地（见 brief真实调用检查.md 追加记录）*
3. **红线**：论文引用清单数字时，清单文件作为 `--evidence` 传入 check_paper_numbers
4. **附录**：正文节选前 N 行 + 全量清单放附录——由 agent 或 D 盘拼接，Beacon 不加工
