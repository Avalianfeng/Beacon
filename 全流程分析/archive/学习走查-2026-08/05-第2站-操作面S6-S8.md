# 第 2 站：操作面 S6 登记装配（纯代码、无 LLM）

## S6 登记装配：Beacon 的机械职责核心区

- **为什么需要**：把 S5 已验证的脚本登记为「题参考实现」并冻结（sha256），抽出 evidence，装配交付表，出论文骨架。**整个阶段纯代码、无 LLM**——这是 Beacon「确定性生产」的看家本领：同一登记 → 同一执行（可复现性公理）。
- **门禁**：`reference paper/tables` **拒绝**无 ok package 或复核未通过的装配（无 skip-gate）——S5 证据是 S6 装配的唯一素材，证据链不允许缺口。
- **命令链**：

| 命令 | 产物 | 干什么 |
|---|---|---|
| `reference add` | `source/reference/` + `reference.json` + 更新 problem.json 哈希 | 登记求解脚本（入口相对路径），sha256 冻结 |
| `reference run` | `evidence.json`（默认 `runs/<题号>-reference/`） | 跑冻结入口 → 解析 RESULT/Q 行 → evidence |
| `reference tables` | 交付表 md/csv（依 `tables.json`） | Q 行 → 题面指定表格逐格装配 |
| `reference paper` | `paper.md` 骨架（分析 prose =【待展开】占位） | evidence + brief → 骨架，**零编造** |
| `reference expand` | `paper-prose.md` 终稿（T-11/D-020） | 原地展开分析槽；**增量数字闸门**：相对骨架新增未溯源 → 失败；缺料占位不编造 |

- **完成判据**：`reference run` 数字与 S5 锚点一致；`tables` 逐格能对题面指定表；`paper` 可用 `check_paper_numbers` 溯源。
- **题级卫生（T-21，P4）**：`tables.json` / `paper_abstract.md` 按题分派——**非 mcm51-c 不套用 C 题默认表**（C 题的表结构只属于 C 题；其他题按小问+evidence 键生成摘要，无表则空表，求解结果按 questions 长度不写死 Q1–Q5）。
- **失败**：换脚本 → `add --force` 后重跑 run/tables/paper；**不要手改 evidence.json 里的数字**（evidence 是机器产物，手改=编造，红线）。
- **agent 协作**：人/agent 只提供已验证脚本与证据；装配全部由 Beacon 机械完成——这是 D-021 职责边界里 Beacon 的领地。
- mcm51-c 对照：`reference.json`、`tables.json`、`runs/mcm51-c-p2/` 的 tables/paper（附录 A 溯源 20/0）。

## S7 评审：放行前最后防线（查真不真，不是查美不美）

- **为什么需要**：口径、数字、假设在放行前过闸；**写作漂亮不是本阶段目标**（那是 D 盘精排的职责）。
- **命令面**：`review-check --paper <md> --evidence <文件>… [--strict]` 统一入口，包装四个脚本：

| 脚本 | 守什么 |
|---|---|
| `check_paper_numbers.py` | 数字溯源红线：正文每个数字在 evidence 白名单（`--evidence` 可传任意文件，含 agent 临时脚本产出） |
| `check_assumption_claims.py` | 假设自相矛盾：「题面明确要求」须有原文依据；同一假设内「明确要求」与「未要求」并存=矛盾 |
| `check_gap_trigger.py` | 大 gap >15% 必须机制性解释（当前只扫调度题键名，T-16 跨题型待实现） |
| `check_l4_gates.py` | L4 纪律（D-006 回流）：G1 敏感性主口径取舍 / G2 Δy 重建声明 y0 / G3 异常检测先有操作定义 / G4 解释失败仅 WARN |

- **C 类五问必答项**（无命令、人/评审 agent 书面回答，进 review-report）：Q1 假设依据可验证性 → Q2 大差距根因（**gap 写成「诚实加分」不算过关**）→ Q3 数字溯源与敏感性口径 → Q4 得分点覆盖 → Q5 解释失败（正文描述过的现象不得无说明改口）。
- **两层防线**（docs/18 §11.5）：表述误导但数字对 → 改论文不必重算；数字错/无溯源 → 回 S5 修脚本或补证据。判据=数字真伪。
- **失败交棒**：不放行 → 回 S5（脚本）/回 S3（口径）/回 S6（重出骨架）；方向级错误绝不在这里投票。
- **产物**：`review-report.json` + 评审结论 md。`report_calibration_diff.py` 仅赛后有官方答案用，不进正常路径。
- mcm51-c 对照：三闸门 + 四必答项；check_assumption_claims 0 矛盾。

## 可靠性依据（用户追问：为什么简单协议+纯机械装配能稳定应付复杂结构）

1. **确定性来自无 LLM、无随机**：同一登记→同一执行→同一输出；纯 Python 可 pytest（810+ 基线）。
2. **复杂度转移而非消灭**：复杂在声明（tables.json），装配逻辑一条 60 行不变式规则；协议面最小（RESULT:/Q: 两行协议）。
3. **错误显式暴露（fail-loud）**：长度对不上 ValueError 硬失败；agent 脚本「尽力而为」会把错误藏成来源不明。
4. **溯源闭合**：evidence 唯一事实源，数字可沿 paper→evidence→stdout→代码 追到底；agent 自算数字=断链=编造路径。
5. **结构分类+边界明确**：矩形表=静态列/数据列/合计列三类元素一条规则；非矩形清单走 D-021 约定通道（agent 临时脚本+`--evidence` 白名单+落盘约定），仍逃不过红线。
6. **实证**：mcm51-c 表1.1/3.1/4.1 逐格命中（268.700/1251.850 精度保留）、附录 A 溯源 20/0、锚点 7 指标命中。

## S8 人审与提交：最后一道人闸

- **为什么需要**：S7 是机器+评审 agent 的闸，S8 是人的闸——方向级判断只有人做得了（学-07）。放行后 paper.md 即交付物。
- **命令**：`accept --problem <spec> --paper <paper.md> --approve|--no-approve [--actor] [--notes]` → 写 `acceptance.json`（approved/paper sha256/actor/notes）；`--no-approve` 退出码 1，stage 不认 S8（进程式拒绝可追溯）。
- **三个关键设计**：
  1. **哈希锁稿**：acceptance.json 存 paper sha256——防「审 A 稿交 B 稿」，锁住人审通过的那一版。
  2. **双登记分离**（D-004）：分阶段 accept 只写 acceptance.json 不写 checkpoint；流水线 resume 写 checkpoint human_decision——两套终态登记互不串流，命令不混用。
  3. **人审是提交闸不是方向闸**：拒绝 → 回 S7 修订清单；方向错 → 回 S3 改 brief；现场改方向会破坏证据链与回溯性。
- **完成判据**：approved===true → stage 认 S8 → **第 2 站（操作面 S0–S8）走完**。之后：PDF 仅编译预览（原则 7）→ 交接 D 盘 → 赛后诊断 → 教训回流（第 1 站总图右半边）。
