# 用户建议与体系缺口（待处置）

## A. S0 缺强制流程性（用户建议）

- **现状**：`problem import` 不做 AI 起草，`problem.json` 的 questions/feasibility「人必须补」——但补什么、怎么补**没有引导模板**，全靠人自觉。
- **用户建议 1（短期）**：agent 依据清晰的路线指导与人交互，指导人完成填写与思考（包括后面视角打开的过程）；**已有提问模板（brief dialogue 逐字段问答、playbook §0 选型 checklist、§3.3 口径防线）应收敛进流程**。
- **用户建议 2（长期）**：从流程入手重新写前端（流程化表单），**标注为更远的计划**。
- **agent 回应**：认同。建议 1 与 T-03（brief extract / init 按小问预填骨架）同族——「S0 填空引导模板」本质是把 T-03 的交互式版本前移到 S0。建议 2 与前端简化计划（10）相关，属远期。

## B. S1 概览图缺控制点（用户建议）

- **现状**：D-007 强制每附件 ≥1 张概览图，但生成**一次即成**，无「与对撞需求对齐」的环节；agent 自做缺控制，数据类型多。
- **用户建议**：概览图定位=建议/对撞依据；对撞需要什么图由对撞「要求」——要么进模板提示词，要么 agent 提醒人主动做；**至少与人交流两次、尝试多次再确定**，且都变成清晰内容。
- **agent 回应**：认同。本质是「S1 完成判据 = 图存在」vs「图满足对撞需求」的差距——把「图是否满足对撞需求」纳入人检。

## C. S2 产物注入问题（用户提问，已实锤）

- **现状**：`exploration.md`、`逐问清点.md` 不注入（人侧工作产物）——对。
- **实锤**：契约/playbook v3.1 说领域知识写入 `brief.json.background_knowledge`，但 **mcm51-c 实际 brief.json 无该字段**（也无 redline_rules）。领域知识.md 目前**实际未系统化注入** brief；部分内容被压进 reference_direction（如 Saito/Voight 准则）。
- **用户建议**：有价值的领域知识应考虑后续注入需要的地方（对 agent 来说有这部分就可以）。
- **agent 回应**：契约-实现落差成立。注入点候选：brief.background_knowledge（schema 有定义）→ 对应 prompt 注入位。

## D. S3 exploration→brief 衔接（用户建议）
- **现状**：exploration.md → brief.json 靠人/强模型手工总结；探索完全依赖人工与强模型交互。
- **用户建议**：① 结合题目从 **brief 八字段反推作为 exploration.md 的写作参考**（八字段为纲写探索）；② 一整块 brief 明显值得一次强模型注入讨论。
- **agent 回应**：① 是新的组织思路——探索从「自由发散后压缩」变为「以八字段为纲探索」，产出天然对齐 brief；② 正是【待实现】T-03「brief extract」的设计意图（playbook §5.1：认知地图+逐问清点 → 一次 LLM 调用按 5.2 映射生成 brief.json 初稿，人工确认落盘）——用户独立复现了该设计。

## F. 多冲突方案处理（用户决策，2026-08-28，学-10）

- **默认流程**：多冲突方案时选一个进入流程，论文后面诚实交代（不隐藏备选方案）。
- **正赛模式（可补充为新东西，待细化）**：不计成本的大量实验 → 用数据和结论重新思考 → 最终得到唯一解，并说明清楚「尝试了但发现不适用」的方法。
- 关联：B20（有效对照 0 个）、M4（对照方案冻结期）、中段不筛方案赛后才算账的哲学。

## G. coder 节点重估与重试哲学（用户决策，2026-08-28，学-11）

- **coder 节点必要性重估**：**D-024 + D-025 已落地**。**ACT-05/D-026 已落地**（consistency 接续硬信号）。余下 ACT-03 覆盖矩阵。
