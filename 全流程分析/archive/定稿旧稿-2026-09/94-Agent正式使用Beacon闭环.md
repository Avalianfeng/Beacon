# 94 · Agent 正式使用 Beacon 的闭环

> 定稿 · 2026-09-05 · **正式用法真相**（D-030）  
> 取代「本地算完就结束 / 登记=交差 / 写作永远会话层」等错误理解。  
> 旧文 [学习走查第 4 站](../archive/学习走查-2026-08/07-第4站-agent协作协议.md) **信息不够**，只留接口清单；以本文 + [`docs/agent协作协议.md`](../../docs/agent协作协议.md) 为准。

---

## 1. 一句话

本地 agent 负责发挥（探索、写改代码、算数、起草 brief）；**算完不是结束**——用 brief **启动并驾驭** Beacon（LangGraph）；登记代码是为了**在体系里继续改代码**，不是把旧稿塞进去交差；critic 反馈驱动手改，直到图跑通**自然出论文**。

---

## 2. 正式闭环（必须按这个想）

```text
┌─ 本地 agent（能力空间）─────────────────────────────────────┐
│  探索 / Diff / 研究编码 / 算数 / 起草 brief（暂定方向）         │
│  ※ 此时可以「自己跑完全部」——但那只是准备，不是交付结束        │
└───────────────────────────┬─────────────────────────────────┘
                            ▼  启动 Beacon
┌─ Beacon 核心（LangGraph + 机械闸）───────────────────────────┐
│  brief 注入（方向手柄）                                        │
│  reference / inject 登记代码（工作区入口，可反复 --force）       │
│  coder LLM 默认关 → 执行冻结脚本 / 一致性门禁                    │
│  … → writer / paper_critic / table / evaluation / 人审 …       │
└───────────────────────────┬─────────────────────────────────┘
                            ▼  critic / 门禁失败？
┌─ 交回 agent ────────────────────────────────────────────────┐
│  读 issues / stdout / 红线 → 判断：改代码？改 brief？           │
│  手改后重新登记 → 再跑（仍以 Beacon 为编排核心）                 │
└───────────────────────────┬─────────────────────────────────┘
                            ▼  跑通
                     体系产出论文 → 人少量改 → accept
```

### 意外时的判断（agent 自己做）

| 现象 | 优先怀疑 | 动作 |
|---|---|---|
| 执行/一致性总不过 | 代码或口径实现 | 手改脚本，再登记 |
| critic 批方向/假设 | brief 不全面或过时 | 补 brief，从注入段重跑 |
| 体系侧模型/写作明显更合理 | brief 不如体系产出 | 吸收进 brief 或显式采纳体系方向并记账 |
| 数字造不出 / 红线炸 | 证据链或白名单 | 修 `_entry`/evidence，不关闸门 |

---

## 3. 代码登记到底是什么意思

**不是**：把之前 agent 写好的求解「用上」当终局交付。  

**是**：

1. 给本地 agent 一个**插入 Beacon 的插座**（`reference add` / `source/inject/`）。  
2. 让 agent **继续改代码**（响应 critic），不必求 coder 节点 LLM 生成。  
3. Beacon 负责**跑、审、写论文、留 checkpoint**——核心仍在体系。

因此：登记可以、也应该多次发生（`--force` / 换 inject）；每次登记服务的是**下一轮体系跑**，不是归档纪念品。

---

## 4. brief 怎么「管理体系内方向」

已有能力：brief 切片注入多个节点（D-022 块表）。正式用法下：

- brief = **暂定方向手柄**，驾驭「单独操作」某一段图（例如只跑执行+写作，或只复跑 critic）。  
- 本地方向与体系节点对话时，以 brief 为共同语言；冲突用 §2 表格判断。  
- **不要**指望无 brief 空跑图还能「自己找到正确方向」。

## 5. 哪些节点还有价值（在本用法下）

| 节点 / 族 | 还有价值吗 | 怎么用 |
|---|---|---|
| **coder_generate（LLM）** | 默认**无** | 关（D-024）；本地写 |
| **coder_execute / model_code_consistency** | **有** | 跑登记代码；硬信号停机 |
| **paper_critic / model_critic / blueprint_critic** | **有** | 失败 → 交棒 agent 手改 |
| **writer / writer_section** | **有** | 体系产论文（接桥后主路径） |
| **table_assembler / evaluation / human_review / latex / finalizer** | **有** | 收尾与人审 |
| **analyst / modeler** | **视 brief 强度** | brief 已强时可跳过或作对照挑战；不删代码 |
| **sensitivity LLM codegen** | 默认无 | inject 脚本优先 |
| **操作面 reference / review-check / accept** | **有** | 机械装配与闸门；与图内 critic 互补不互替 |

## 6. 和前面做错的方向对照

| 曾经怎么走 | 问题 | 现正式口径 |

| 本地研究完 → 只出骨架 / 会话 prose → 停 | 没启动体系核心 | 算完后必须启动 Beacon 跑图 |

## 7. 工程落地顺序（不在本文实现）
