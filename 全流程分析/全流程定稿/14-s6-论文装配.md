## 正式路径

```text
uv run math-agent run ^
  --problem problems/<题>/problem.json ^
  --brief problems/<题>/brief.json ^
  --plan problems/<题>/plan.json ^
  --out runs/<题>-graph
```

`--plan` 必须带 `--brief`；不能同时 `--from writer` / `--dry-run` / `--allow-coder-llm`。  
无人值守可加 `--no-interrupt`。改过 plan/brief 必须换 `--out`，不能 restart。

内部（图结构不动）：

播种 `as_node=analyst`（`plan_injected`）→ `blueprint_critic` / `model_critic` 真跑 → `modeler` 有 final 卡则短路 → coder 执行冻结 `_entry` → 一致性 → 敏感性（须 `source/inject/sensitivity.py`）→ figure → writer × N → paper_critic → table / evaluation / 人审 / latex。

论文数字只来自图内 `coder_execute` stdout 与 inject 的 RESULT。`reference run` 的 evidence 给人闸和 `review-check --strict`。

门禁停机后读 `critic-handoff.md`：改代码则 `reference add --force` + `restart --from coder`；改 plan 则新开 run。首跑常见坑见 00 第 8 节。

`--from writer` 仍可用作**应急接桥**（吃 evidence，常在 paper_critic 因缺两张证明停机，按 [15](15-s7-评审.md) 人接管）。不要当正式题第一枪。

论文从 writer 链出。`reference paper` 骨架、`expand`、会话手写 prose，都不是正式终态。
