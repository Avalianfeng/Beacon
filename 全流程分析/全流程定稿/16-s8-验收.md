# 16 · 验收

> **收口。** 总图：[00-正式闭环](00-正式闭环.md)。

## 谁 / 产物 / 人闸

| | |
|---|---|
| 谁 | **人**批准；主会话只登记 `acceptance.json` |
| 产物 | 验收记录；工作面可再做 Word/少量改 |
| 人闸 | 看过 **writer 完整初稿** 并有人评结论后才 `--approve` |

先 `review-check`（可 `--strict`），再 `accept`。  
`--strict` exit 1 先按 [00 第 7 节](00-正式闭环.md) 拆开看：关键 RESULT 在正文 ≠ 五把闸全绿；tokenizer / L4 原词 / brief caption 逐字是另账。不要把机械红当成「不能 accept 的唯一理由」——人仍要看完整初稿，也仍要处理 `degraded` 质量门。  
禁止对骨架 `paper.md` 批准。  
应急 prose 若仍在磁盘上，不当正式验收对象。  
`degraded` ≠ 评审没过，也不等于可以交：质量门警告（页数/对照/Overfull）交卷前按清单补。

探索性停用 `--no-approve`。未批准不得装成已验收。  
`--no-interrupt` 的 run 会跳过 `human_review`；那只是跑完图，**不是**人已经验收。
