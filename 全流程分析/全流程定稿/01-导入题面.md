# 01 · 导入题面（事实底座进机器世界）

> **第一幕。** 总图：[00](00-正式闭环.md) ① → 下一站 [02-EDA画像](02-EDA画像.md)。  
> 理解面：[讲解 §1](../讲解-一篇读懂Beacon闭环.md)（机器世界的产物即契约）。

## 这一段在防什么

整条流水线后续所有站都要引用题目事实（附件、题面、数据声明）。如果底座进机器世界时不可复核（原件被改、声明与实物不符），后面每一站的判断都会建立在漂移的事实上——错在最底下，越往上越贵。所以导入只做一件事：**把题面与附件以只读、可校验的方式请进题目录**，并生成后续契约的起点 `problem.json`。

另一个方向性防错：导入后**不要**顺手 `brief init`。brief 必须后置到研究之后（第三幕），先写死方向等于让探索为预设结论找证据。

## 输入 / 怎么做

输入：题面（pdf/docx/文本）+ 附件（xlsx/csv…），人提供。

```text
math-agent problem import …   # 附件进 source/（只读、登记哈希），生成 problem.md/problem.json
math-agent problem show …     # 人看解释层（questions/data_files/data_dir/source_files）
math-agent problem stage …    # 看当前走到哪一站
```

- 附件原件不许改；`source/` 里的副本是唯一可引用版本（图内血缘闸按它核对）。
- 解释层（题目各问、数据文件声明）由主会话起草、**人认 blockers/questions**——声明错了后面全错。

## 边界

- 禁：改动原件；跳过人认直接进探索。
- 人闸：blockers/questions 人认过才进下一站。
- 曾错走法：import 后立刻 `brief init`（旧 CLI 文案误导过）——brief 后置，见 00 ①。

## 站终态树：这一站结束时题根长出什么

```text
problems/<题>/
  problem.md        ← 人读题面（含解释层）
  problem.json      ← 机器契约起点：questions / data_files / data_dir / source_files(哈希)
  source/           ← 附件只读副本 + manifest（哈希）；后续 reference/、inject/ 也落这里
```

| 资产 | 谁写 | 谁读 | 何时 |
|---|---|---|---|
| `problem.json` | CLI + 人认解释层 | 所有下游站与图（数据声明、血缘核对） | 本站产出；后续 `reference add` 会追加登记哈希 |
