# 16 · 停机交棒（critic 的否定 = 交棒点，不是失败）

## 这一段在防什么

图停机时最常见的误读是把交棒当失败、或原地反复 restart。真相：**门禁设计成"首次不过即停"**——自动重试 = 同一输入同一错误重复烧钱且不收敛；停机 = 保留现场（checkpoint）+ 把问题打包交回最擅长改的一方。你要做的不是哄它，是读包、判断、改对地方、选对推进方式。

## 交棒包

`run`/`restart` 真停机后**自动**写 `runs/<id>/critic-handoff.json`（+ `.md`）；也可手动 `math-agent critic-handoff --out runs/<id>`。内含：`gate_reason`、完整 critic/consistency issues、`handoff_action`、可复制 `next_commands`。

## 停机 → 动作（一张表）

| handoff_action | 典型场景 | 动作 | 能否 restart |
|---|---|---|---|
| `edit_code` | 执行失败 / 一致性无主证据 / 分数不够 | 改 `source/reference` 或 `source/inject/sensitivity.py` → `reference add --force` → `restart --from coder` | 能（同一 `--out`；**不带 `--problem`**） |
| `edit_plan` | blueprint / model_critic 打回 | 改 `plan.json`（必要时 brief）→ **新开** `run --plan` | **不能**（输入戳会拒） |
| `edit_brief` | 无 `--plan` 的旧全图 brief 被打回 | 改 brief → 新开 run | 不能 |
| `edit_paper` | paper_critic 批论文 | `restart --from writer`（按意见**定向重写被批节**） | 能 |

**核心规则：restart 只重放现场，绝不吸收外部改动。** 它校验 problem/brief/plan 的输入戳（哈希），对不上就拒绝——改 plan/brief 只能新开 `--out`；改代码必须重登记（`add --force`）才会被下一轮执行吃到。

## 过闸 ≠ 零意见（真跑教训）

paper_critic 门槛是否决制（编造/不一致/完全不引图/上游未过才拒），**9 分通过仍列 issues 是常态**。不要为清 issues 无限 restart——每次重写只换一批 nit。issues 当建议：人判，或进 `_研究日志`。

- 评委建议"未实现的方法"（分位数回归等）→ **不编造**：写进局限，或真补跑（edit_code）后再写。
- `finalizer degraded`（黄牌）是**独立质量门**（页数/对照/Overfull），与"评审没过"是两回事——见 17。

## 边界

- restart `--from coder|writer` 都要求：checkpoint 处于对应门禁停机态、输入戳与 manifest 一致。
- 同一 `--out` 并行 restart 会撞（等当前 worker 结束）。
- 详细坑表：00 [第 8 节](00-正式闭环.md) + `图内真跑/操作坑.md`（血缘/inject/引图/参数名泄漏）。
