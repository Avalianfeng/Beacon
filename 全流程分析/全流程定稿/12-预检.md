# 12 · 预检（启动前的零成本体检）

> **第四幕开头。** 总图：[00](00-正式闭环.md) ⑧ → 上一站 [11-brief定稿](11-brief定稿.md) → 下一站 [13-交接文档](13-交接文档.md)。  
> 理解面：[讲解 §3.1](../讲解-一篇读懂Beacon闭环.md)（机器世界的入场检查）。

## 这一段在防什么

启动图是烧 token 的长跑。若题面声明、附件、brief、路径在开跑前就有问题，跑到一半才炸 = 白烧一轮。预检用**零求解、零 LLM**的机械检查把这类问题挡在门外（blockers 必须空）。

它与 `plan check` 的分工：预检管**题面侧**（数据声明/附件/路径/brief 齐不齐）；`plan check` 管**plan 卡侧**（critic 会打回的字段缺口），在下一站 14 做。

## 输入 / 怎么做

输入：`problem.json` + `brief.json` + 题根路径。

```text
uv run math-agent run --dry-run --problem problems/<题>/problem.json --brief problems/<题>/brief.json
```

- 产物：`runs/<题>-preflight/preflight.json`（ok / blockers）。
- `--dry-run` 不能和 `--plan` 同用；plan 的零 token 预检是 14 的 `plan check`。

人闸：blockers 必须空（或人逐条认掉并说明）。

第一幕的多 V / `_共享` **与预检无关**——预检只看题面侧声明与 brief；探索目录齐不齐不进 blockers。

## 边界

- 预检绿 ≠ 图会过：critic 的语义分（blueprint 7 分打回）预检挡不住，那是 14/16 的事。
- 预检缺 ML 库之类只算 WARN，不算 blocker。

## 站终态树

