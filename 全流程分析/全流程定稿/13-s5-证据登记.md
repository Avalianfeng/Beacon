## 第 0 步 · 交接文档（先写这个，再碰 CLI）

研究者收束 ≠ 下一个会话自然知道一切。登记之前，主会话（或研究者本人）按 [13附 模板](13附-交接文档模板.md) 在题根写 `problems/<题>/交接-beacon.md`：

一句话状态 / 磁盘真相 / 关键数（可复算对齐）/ 人闸记录 / 定稿站位 / 命令序 / 已知缺口 / 禁止 / **可粘贴开工白**。

- **为什么需要**：操作 Beacon 的会话可以是原研究会话续跑，也可以新开会话读盘——交接文档让两条路等价；它也是「禁止只把关键结论留在对话框」的落地文件。
- **实况**：cumcm23-c 的 S5 证据链就是续会话凭 `docs/log/2026-09-04-cumcm23-c-交接-Beacon后续.md`（开工白）跑通的——本模板即那次实践的形式化。

## 登记是什么（只记这一句）

给本地 agent 一个插入 Beacon 的插座。体系去跑这份代码；critic 不过就手改，再 `--force` 登记。  
**不是**把旧求解交进去交差，也不是替代 LangGraph。替代的是 coder 节点 LLM。

**快照范围（事实）**：`reference add` 归档的是 `problems/<题>/source/reference/` 下的 `*.py` + 每题两份哈希登记（`problem.json` 的 `source.source_files` 与 `reference.json`），**不含数据文件**——`_entry.py` 通过运行时注入的 `data_dir` 读题根数据。

图内当主方案执行时，血缘闸还要求：进程**真实 open** `problem.json` 声明的附件（xlsx/csv 等），并且工作目录落下 **PNG**。只读 `研究/data` 摘要、不碰附件、不产出图 → `code_verify 无主证据`。改完必须 `--force` 再登记。

## 怎么做（命令序与语义）

```text
plan build --brief brief.json --out plan.json   合成 v0（coverage 带锚；手补变量/验证区间）
plan check --plan plan.json --brief brief.json  零 token 预检 critic 缺口
reference add --force    图外快照 + sha256 登记（改过代码后必须 --force 再登记）
reference run            确定性执行 _entry（600s 上限、零 LLM）→ 冒烟 evidence.json
reference verify         机械三查
reference recertify      人闸落账
```

每次登记的产物服务**下一轮图内执行**；可以、也应该多次发生。

**敏感数字**：研究表（加成带 / 成本冲击等）只是参数参考。论文敏感性节的数由 agent 按这些参数写 `source/inject/sensitivity.py`、**图内重跑**产生；不要期望与研究 CSV 逐位相同，也不要把 `evidence.json` 的 `markup_*` 写进论文。

## ⚠ 两套 run 不是一回事（先钉死，防串味）

| 命令 | 在哪跑 | 干什么 |
|---|---|---|
| `reference run` | **图外** CLI | 冒烟 + 人闸抽查 + `review-check --strict` 对照锚 |
| `math-agent run --plan` | **图内** LangGraph | 执行冻结脚本；**论文数字 = execute stdout** |

推论：

- 改**代码**后：`add --force` → `restart --from coder`（正式 `--plan` 路径）。图外可再 `reference run` 方便对账。
- 改 **brief / plan** 后：**新开** `run --plan`（restart 输入戳会拒）。
- `--from writer` 只应急；改证据后必须新开接桥 run。
- `restart` 只重放 checkpoint，不带入新 plan / 新 brief。
