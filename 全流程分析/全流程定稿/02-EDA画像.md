# 02 · EDA 画像（让人先看见数据）

> **第一幕。** 总图：[00](00-正式闭环.md) ② → 下一站 [03-外部开放探索](03-外部开放探索.md)。  
> 理解面：[讲解 §1](../讲解-一篇读懂Beacon闭环.md)（事实底座；印象不算证据）。  
> 出图提示词：[../prompts/eda/](../prompts/eda/)。

## 这一段在防什么

探索阶段的两个角色（外部第二家、本地探索 Agent）都要基于数据说话。若没人先看过数据的形态——量级、结构、列对齐、明显异常——探索就会盲猜口径，地图画得再漂亮也是空中楼阁。

但 EDA 的产物要**克制**：它是「事实画像」（这张表长什么样），不是分析结论（这张表说明什么）。结论属于探索与研究的认知世界；画像只负责让人和外部模型**看见**。把印象当证据写进画像，是这一站最典型的越权。

另一类失败：**按附件张数机械出图**（「每附件一柱状图就收工」）。图的类型必须以「要让人看见的数据特征」为核心；张数可以多于或少于附件数。没有「为何这样画」的图说，后人无法判断图是证据还是装饰。

## 输入 / 怎么做

输入：上一站的 `problem.md/json` + `source/` 附件。

### 自主出图循环（主会话或派 `prompts/eda` 子任务）

高自主性：出图过程**包含**对题面约束与附件气质的分析，并按**已画出的图的视觉特征**继续改策略——不是「扫完表 → 固定模板画完」。

```text
1. 读题面 + 扫附件结构
      ↓ 列出「必须被看见的特征」候选（量级/构成/时间或季次/对齐/缺口…）
2. 为每条特征选图型（柱/条/散点/热力/结构示意/对照…）；一张图可服务多特征，一个附件可多张图
      ↓
3. 写脚本出图 → 主会话（或出图者）真看 PNG
      ↓ 视觉上读得出假设特征吗？误导吗？缺哪一块？
4. 改选图型 / 拆图 / 补图 / 删装饰图 → 回到 3，直到「看图能建立正确直觉」
      ↓
5. 落盘 data_profile.md + eda/*.png + eda/图说.md（为何这样画 / 呈现何特征 / 已知不足）
```

- **图说是一等产物**：每张（或每组）图写清：假设要呈现的特征 → 为何选这图型 → 看图应读出什么 → 不负责什么 → 已知不足。
- **「每附件一图」不是硬约束**：只是早期打包习惯。特征需要就拆多张；空模板可以只画结构示意；没有分布就不要硬画分布。
- 外发拼图（可选）：
  `python scripts/pack_external_upload.py --dir problems/<题>/eda --glob-png "*.png" --stem 概览拼图 --md-skip`  
  （或按需 `--glob-png "附件*.png"`；拼图文件名不必叫「四合一」。）
- 大附件没有官方抽样 CLI 时，用题侧脚本（`eda/_make_overview.py` 一类）——通用命令未建，需要时再议。

人闸：人说「对撞够用这些图」，或点名补哪张——**图给人看，数字事实留给探索自己算**。图说里的「开放点」可以喂给 03/06，但画像正文仍不断言解法。

## 边界

| 做 | 不做 |
|---|---|
| 结构、量级、对齐、异常、**缺口**（某列不存在也要可见） | 相关性/因果/「该用什么模型」定案 |
| 按特征选图型；看图后迭代 | 固定「附件 N → 一种默认图」交差 |
| 空表画提交几何 | 把空模板画成假分布 |
| 图说记录决策痕迹 | 只留 PNG、不问为什么 |

## 站终态树

```text
problems/<题>/
  data_profile.md              ← 人读画像（量级/结构/异常/缺口）
  eda/
    *.png                      ← 特征导向；张数不限
    图说.md                    ← 为何这样画（必有）
    _make_overview.py          ← 题侧出图脚本（可迭代）
    _profile_stats.json        ← 可选：机读统计缓存
    概览*.png                  ← 可选：外发拼图
```

| 资产 | 谁写 | 谁读 | 何时 |
|---|---|---|---|
| `data_profile.md` + `eda/*.png` + `eda/图说.md` | 主会话（可派 eda 子任务） | 人、外部第二家、本地探索 | 本站产出；可按人闸增补重绘 |

## 自查

- [ ] `data_profile.md` 存在；关键数字可追溯到脚本/JSON
- [ ] `eda/图说.md` 存在：每图有「特征 → 图型 → 应读出 → 不足」
- [ ] 图型服务于特征，不是服务于附件编号
- [ ] 至少做过一轮「看自己的图再改」；装饰图已删或降级
- [ ] 画像/图说里没有越权写「这题应该怎么做」
- [ ] 人不觉得缺关键图（或已点名补图清单）
