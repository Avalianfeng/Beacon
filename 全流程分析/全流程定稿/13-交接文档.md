# 13 · 交接文档（让下一个会话能无痛接手）

> **第四幕 · 登记之前。** 总图：[00](00-正式闭环.md) ⑨ 第一句 → 上一站 [12-预检](12-预检.md) → 下一站 [14-plan与登记](14-plan与登记.md)。

> 理解面：[讲解 §4.2](../讲解-一篇读懂Beacon闭环.md)（三层文档：心智 / 本题状态 / 命令）。

## 这一段在防什么

研究者收束 ≠ 下一个会话自然知道一切。操作 Beacon 的会话可以是原研究会话**续跑**，也可以是**新开会话读盘**——两条路要等价，靠的是物化记录，不是聊天记忆（"禁止只把关键结论留在对话框"的落地）。交接文档就是那道物化：把"本题现在走到哪、凭什么信、下一步做什么、别踩什么"写成一份给接洽会话的开工文件。

它必须写在**登记之前**：14 的每一个登记/复算动作都是在兑现这份文档里的状态与计划——没有交接文档就登记，等于没有说明书先开机。

## 输入 / 怎么做

输入：题根全部研究资产 + brief/plan 状态 + 人闸记录（人抽查结论）。

1. 主会话（或研究者本人）按 [13附 模板](13附-交接文档模板.md)，在题根写 `problems/<题>/交接-beacon.md`，九节：
   一句话状态 / 磁盘真相 / **关键数（可复算对齐）** / 人闸记录 / 定稿站位 / 命令序 / 已知缺口 / 禁止 / **可粘贴开工白**。
2. 人闸记录只写事实：没真做过的人闸写"未过"，不许替写通过（recertify 的 actor/notes 要与它对齐）。
3. 写好后，接洽会话（续跑或新开）凭它开工：读本文 → brief.json → 研究日志 → 按命令序执行。

## 边界

- 禁：只把关键结论留在对话框；替写人闸通过；把研究结论的"自信"写进事实栏。
- 文档是快照不是圣经：登记动作中发现状态不对，回写文档再继续。
