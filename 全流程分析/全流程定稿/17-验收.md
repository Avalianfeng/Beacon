# 17 · 验收（绿牌/黄牌/只有人能给的通行证）

> **收口。** 总图：[00](00-正式闭环.md) ⑫ → 上一站 [16-停机交棒](16-停机交棒.md)。  
> 理解面：[讲解 §3.9](../讲解-一篇读懂Beacon闭环.md)（黄牌/绿牌；只有人能 accept）。

## 这一段在防什么

图跑通 ≠ 可以交。体系能证明"流程跑完、证明齐了"，能给绿牌（completed）或黄牌（degraded），但**给不了"可以参赛"**——那是人看过完整初稿之后的决定。这一站防两件事：把机器的绿/黄牌当验收结论；把 `--no-interrupt`（跳过人审）当人已看过。

## 怎么做

1. **人看 writer 完整初稿**（`runs/<题>-graph/paper.md`，不是骨架）。`--no-interrupt` 的 run 只表示图跑完，不表示人验收过。
2. `math-agent review-check`（可 `--strict`）——机械对账：
   - `--strict` 只核**关键 RESULT** 是否出现在正文（主结果 + `RESULT: baseline|…` 行）；
   - 年份/题面数字/图题逐字/口头禅类 → WARN，不是红；
   - 它**不重跑求解器**：冒烟复算在启动图之前（14）就已做，对账拿已有 evidence 扫论文数字。
3. 处理黄牌：`completion.json=degraded` 的警告（正文页数 / 有效对照方案数 / Overfull）是**独立质量门**——交卷前补篇幅/对照/排版；degraded ≠ 评审没过，也不等于可以交。
4. **人**评结论 + `math-agent accept`（`--approve`）。Word/精排放工作面（可从初稿起，不从骨架重写）。

探索性停用 `--no-approve`；未批准不得装成已验收。

## 边界

- 禁止对骨架 `paper.md` 批准；应急 prose 若还在磁盘上，不当正式验收对象。
- `evaluation` 的机器综评只是提示，验收看人（16 站教训：7.x 不挡 finalizer，也不替你下结论）。

## 自查

- [ ] 人看过 writer 完整初稿并有结论
- [ ] `review-check`（或 `--strict`）的红/WARN 逐条看懂（不是看见红就慌）
- [ ] degraded 警告清单已处理或明确挂起原因
- [ ] `acceptance.json` 由人批准后登记
