# 15 · critic 交回手改

> **第五幕。** 总图：[00-正式闭环](00-正式闭环.md)。

## 谁 / 产物 / 人闸

| | |
|---|---|
| 谁 | 图内 critic 停机；主会话把交棒包交回研究者；机械闸 `review-check` |
| 产物 | `runs/<id>/critic-handoff.json`（+ `.md`）；改过的代码 / plan / brief |
| 人闸 | 机械绿 ≠ 可交；评分由人 |

## 正式口径

critic / 门禁失败 = **交棒**，不是结束。

`run` / `restart` 真停机（`snap.next` 为空且未终态完成）后**自动**写出交棒包；也可手动：

```text
math-agent critic-handoff --out runs/<id>
```

包内含：`gate_reason`、完整 critic/consistency issues、`handoff_action`、可复制 `next_commands`。

## 停机 → 动作（单一正式流）

正式入口是 `run --plan`。`--from writer` 应急接桥仍可能因缺模型/一致性报告在 paper_critic 停机，那时用人接管，不要当成正式路径的常态。

| handoff_action | 动作 |
|---|---|
| `edit_code` | 改 `source/reference` 或 `source/inject/sensitivity.py` → `reference add --force` → `restart --from coder` |
| `edit_plan` | 改 `plan.json`（及必要时 brief）→ **新开** `run --plan`（禁止 restart） |
| `edit_brief` | 无 `--plan` 的旧全图：改 brief → 新开 run |
| `edit_paper` | `restart --from writer`：按 critic 定向重写被批节 |

`restart --from coder|writer` 要求：对应门禁停机态；problem / brief / **plan** 哈希与 run_manifest 一致。改 plan/brief 只能新开 `--out`。

首跑常见坑（blueprint 空字段、`_entry` 不读附件/无 PNG、缺 inject）见 [00 第 8 节](00-正式闭环.md)。

`review-check --strict` **不会重跑** `_entry`。产品口径：证据里的关键 RESULT 必须出现在完整初稿；年份/题面/文献、brief 图题逐字、敏感性「主口径取舍」只 WARN。仍挡闸的是缺关键数、假设自相矛盾、红线。证据在 `runs/<题>-reference/evidence.json`（冒烟锚，不是论文数字源）。细则见 [00 第 7 节](00-正式闭环.md)。

对照是否够数是 finalizer 质量门，不是 `--strict`：同 stdout 的对照要写成独立 `RESULT: baseline=<名>` 行（与主方案有共同指标且数值不同）。只写在 Q 行里不算。

paper_critic **通过后仍可能带 issues**（本题 9 分过闸时假设口径/Q1 方法仍在列表里）：人决定要不要 `edit_paper`，不要把「有 issues」自动当成没过闸。  
8 分打转、引图、inject 参数名泄漏、`degraded` 质量门：见 [图内真跑](../图内真跑/README.md) 与 [00 §7–8](00-正式闭环.md) / [16](16-s8-验收.md)，不要当成「用法又改了」。
