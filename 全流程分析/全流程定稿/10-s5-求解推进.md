# 10 · 研究会话（把题算明白）

> **第二幕。** 总图：[00-正式闭环](00-正式闭环.md)。  
> 同一研究者会话把题算明白；不要硬切成另一个「求解 Agent」。  
> 提示词：`prompts/研究/` · 派发：`problems/<题>/_派发/研究.md`  
> **算完不是结束** —— 算完之后启动 Beacon。

## 谁 / 产物 / 人闸

| | |
|---|---|
| 谁 | **同一研究者会话**：优先在 Diff 对话上**续跑**；或人新开对话粘贴研究会话派发 |
| 产物（副产品） | 题根 `_研究日志`；`解题说明`；`经验与坑`；**`exploration.md`（人读收束）**；`brief草稿`；**`plan.json`（机读卡，收束时 `plan build`）**；自管脚本/表/图 |
| 人闸 | 不按文件清单卡死；看是否已形成「够稳、有证据」的解题认识 |

## 一句话

**把题研究明白**——方向经真实数据与计算检验；日志/说明/brief 是研究外显，不是驱动器。

## 核心目标（唯一）

> 把这道题研究到：你能够基于真实数据和实际计算，对主要解题方向、关键口径、模型选择与结果有足够可靠的认识，并留下足够证据，使后续 Beacon 能忠实完成论文生产。

brief 草稿是研究成熟后的**压缩**，不是研究开始时的任务单。

## 身份与阶段

```text
第三方研究者（同一会话）
  │
  ├─ 已完成：预构想 → 双图 → Diff（认知状态，不是终局）
  │
  └─ 继续：读数据 / 实验 / 局部建模 / 否证 / 修正 / 跑到结果
         → 「我做明白了」→ 收束成日志 + 说明 + brief 草稿
```

「Diff」不是职业；只是研究过程中的一个状态。

## 工作区

题目录本身即实验室：`problems/<题>/`  
不另建 `求解/` 沙箱（已废止）。派发集中在 `_派发/`；脚本/表/图可在题根或自选子目录自管。

## 当前工作假设（非锁）

拍板表 = **当前方向**，可被实验推翻。  
推翻时必须在 `_研究日志.md` 写清：原判断 → 证据 → 结果 → 新方向。

## 子 Agent

允许按需调用（独立验证 / 分叉探索 / 机械脏活）；**不**规定每问一 Agent，不强制批评链。

## 停止

不是「文件写完了」，而是：

> 已有经数据与计算检验的稳定解题认识；继续探索边际收益明显低于成本。

然后再压缩交付物 → [11-s3-brief定稿.md](11-s3-brief定稿.md)
