# 00 · Agent 使用 Beacon：从头到尾

> **本页是唯一总图。** 01–16 是各段怎么做；和本页冲突时信本页。  
> 不要用 S0–S9 当「两套主路径」。那些编号只是 CLI 帮助里的旧标签。

读法：先扫第 0–1 节认角色和时间序；启动图前精读第 4–6 节（命令、图内节点、停机交棒）；数字口径看第 7 节。

---

## 0. 先认角色（后面会换人）

| 角色 | 是谁 | 干什么 | 不干什么 |
|---|---|---|---|
| **人** | 你 | 开第二家、开新对话、拍板、评论文、accept | 不把对话框当唯一真相 |
| **主会话** | 本机主持 agent | CLI、拼包、记盘、抽查、收口 brief / plan / 登记 | 不代写 Diff、不代评、不替人拍板 |
| **外部第二家** | 另一家模型 | 知识/方法探索，产出外部认知地图 | 不读本机未公开材料；不给最终竞赛解 |
| **本地探索 Agent** | 干净上下文的子 agent | 一次长探索，留下证据卡 + 本地认知地图 | 不看外部地图；不在这一步写正式论文 |
| **研究者会话** | 人新开（常从 Diff 续跑） | 把题**算明白**：编码、实验、否证、出数 | 算完不等于交卷 |
| **Beacon** | LangGraph + 机械闸 | 按 brief+plan 跑登记代码、critic、**写论文** | 默认不让 coder 节点 LLM 写代码 |

科学对不对，以研究者实算为准。  
论文长什么样，以 Beacon 跑通后的稿为准。  
本地自己跑完全部，只是准备，不是结束。

两份机读输入（第四幕才齐）：

| 文件 | 管什么 | 谁写 |
|---|---|---|
| `brief.json` | 方向手柄：各问走法、红线、写作要点；切片进各节点 | 研究收束后压缩 |
| `plan.json` | 图内蓝图 + final 模型卡；`run --plan` 播种到 critic 前 | `plan build` 出 v0，再手补变量/验证/路线 |

brief 驾驭「写什么、禁什么」。plan 提供「模型长什么样」，让 `blueprint_critic` / `model_critic` **真跑**，而不是跳过。

## 1. 时间顺序（换角色跟着走）

### 第一幕 · 把方向找出来（Beacon 图还没启动）

**① 导入题面** — 主会话 CLI，人认 blockers。  
附件只读进 `source/`。不要一导入就 `brief init`。  
→ 细节：[01](01-S0-导入题面.md)

**② 看数据** — 主会话出 EDA 图和 `data_profile.md`。  
人看图；数字事实留给后面探索自己算。  
→ [02](02-S1-EDA画像.md)

**③ 两边独立探索**（可交错，不要互相偷看）

1. **人**把题面/EDA 发给**外部第二家** → 外部地图。缺证据就索取：主会话在本机算切片，打包再发，直到地图可对撞。  
   → [03](03-S2-外部开放探索.md) · [04](04-S2-索取与回填.md) · [05](05-S2-外部地图闭环.md)
2. **主会话**派**本地探索 Agent**（干净上下文，禁止读外部地图）→ `_证据卡.md` + `认知地图-本地.md`。  
   → [06](06-S2-本地认知地图.md)

**④ Diff** — **人新开对话**（不是主会话代写）：先锁预构想，再读双图，综合成可拍板的方向。  
主会话只准备派发、事后抽查。  
→ [07](07-S2-Diff综合.md)

**⑤ 人拍板，主会话登记** — 拍板表 + 主线。然后逐问清点（可薄，但问要齐）。  
→ [08](08-S2-拍板登记.md) · [09](09-S2c-逐问清点.md)

这一幕结束时：有方向，**还没有**竞赛解，**还没有**启动图。

---

### 第二幕 · 把题算明白（仍在本地）

**⑥ 研究者会话** — 优先在 Diff 对话上续跑，不要硬切成另一个「求解 Agent」。

在题目录里写代码、跑数、否证、改方向。拍板是工作假设，实验可以推翻（推翻必须写进 `_研究日志.md`）。

留下：脚本 / 表 / 图 / `_研究日志` / `解题说明` / `经验与坑` / 人读的 `exploration.md` / **brief 草稿**。  
敏感性表（加成带、成本冲击等）只作**参数参考**，正式论文里的敏感数字要在图内重跑。

提示词：[prompts/研究](../prompts/研究/说明-从Diff续跑.md) · 本题派发：`problems/<题>/_派发/研究.md`  
→ [10](10-s5-求解推进.md)

> **停在这里的错觉**：研究者已经能交出数字和说明。  
> **正式口径**：这叫准备完毕，**不是交付结束**。

---

### 第三幕 · 压成方向手柄

**⑦ brief 定稿** — 把已经算过、站得住的方向压成 `brief.json`，`brief check` 过。

brief 是**暂定**的、拿来**驾驭 Beacon** 的手柄：告诉图要走哪条路、红线是什么、各问写什么。  
它不是研究任务单，也不是圣经。图跑起来以后如果方向被证伪：改 brief，或承认体系侧更好并记账。

→ [11](11-s3-brief定稿.md)

这一幕**还没有** `plan.json`。机读卡在下一幕和登记一起做。

---

### 第四幕 · 启动 Beacon（核心从这里开始）

**⑧ 预检** — `run --dry-run`，人看 blockers。不烧求解、不调 LLM。  
→ [12](12-s4-预检.md)

**⑨ 交接、plan、登记代码** — 研究者收束后，先按 [13附](13附-交接文档模板.md) 在题根写 `交接-beacon.md`，再按下面顺序（可反复）：

1. **`plan build` → 手补 → `plan check`**  
   v0 会带 brief 条目到小问/方程 id 的锚。必须手补：`decision_variables`、`validation_plan.pass_criteria`、`recommended_route`、`data_requirements`（附件标 given）、题面约束（`source=given`）。coverage 的 `reason` 要写清「这条 brief 怎么落地」，不能只写骨架编号。  
   敏感数字**不要**写进 plan 当论文事实；plan 里只钉扫参**参数名**（如 `成本冲击 (cost_shock)`），数由图内 inject 重跑。
2. **写 `source/reference/_entry.py`**（或从研究适配脚本登记进来）  
   打印 `Q1`…`Qn` 与一行 `RESULT: baseline=ours …`。  
   图内当主方案跑时还要满足血缘闸：运行时**真实 open** `problem.json` 声明的附件（至少一份 xlsx/csv），并且工作目录要有 **PNG**（可从研究 figures 拷进 cwd，或当场画）。只读 `研究/data` 摘要、不碰附件、不落盘图 → 一致性会报「无主证据」。
3. **`reference add --force`** → **`reference run` / `verify` / `recertify`**  
   图外冒烟 + 人闸。evidence **不是**论文数字源。
4. **写 `source/inject/sensitivity.py`**  
   按研究网格重跑（成本冲击、加成带、损耗缩放等），打印  
   `RESULT: parameter=<名> values=[…] results=[…]`。  
   参数名最好带英文别名括号，便于和 LLM 出的敏感性计划对上。缺文件或执行失败：`--plan` 路径**停机交棒**，不会静默滑走。

登记**不是**把研究者旧代码交进去交差。  
登记是给本地 agent 插上 Beacon 的**改代码插座**：体系去跑这份代码；跑不过就拿 critic 意见回来改，再 `--force` 登记，再跑。  
替代的是 **coder 节点 LLM**，不是替代 Beacon。

→ [13](13-s5-证据登记.md)

**⑩ 图开始跑**（正式入口只有 `run --plan`；coder LLM 默认关）

```text
uv run math-agent run ^
  --problem problems/<题>/problem.json ^
  --brief problems/<题>/brief.json ^
  --plan problems/<题>/plan.json ^
  --out runs/<题>-graph
```

无人值守可加 `--no-interrupt`（跳过 `human_review`，等价自动批准）。需要人看稿时不要加。

`--plan` **互斥**：不能同时 `--from writer`、`--dry-run`、`--allow-coder-llm`；必须带 `--brief`。

图内顺序（结构不改，靠 `plan_injected` 短路生成）：

```text
播种 as_node=analyst（蓝图 + final 模型卡）
  → blueprint_critic 真跑
  → modeler（有 final 卡则 0ms 跳过 LLM/推导链）
  → model_critic 真跑
  → coder：执行冻结 _entry（不 LLM 写代码）
  → model_code_consistency
  → 敏感性：LLM 出计划 → 执行 inject/sensitivity.py → LLM 解读
  → figure 审图
  → writer × N 节
  → paper_critic
  → table / evaluation / 人审 / latex / finalizer
```

论文数字 **只**来自图内 `coder_execute` stdout（以及敏感性 RESULT）。  
`reference run` 给人闸和 `review-check --strict` 对账。

`--from writer` 只作**应急接桥**（吃 evidence，常因缺模型评审/一致性报告在 paper_critic 停）。cumcm 这类正式题不要用它当第一枪。

→ [14](14-s6-论文装配.md)

### 第五幕 · 失败就交回手改，直到出论文

**⑪ critic / 门禁停机** — 这是闭环的一部分，不是「流程失败」。  
停机后 `runs/<id>/critic-handoff.md` 会写明 `handoff_action` 和可复制命令。

| 现象 | handoff | 动作 | 能否 restart |
|---|---|---|---|
| 执行失败 / 一致性无主证据 / 分数不够 | `edit_code` | 改 `_entry` 或 `inject/sensitivity.py` → `reference add --force` → `restart --from coder` | 能（同一 `--out`） |
| blueprint / model_critic 打回 | `edit_plan` | 改 `plan.json`（必要时 brief）→ **新开** `run --plan --out <新目录>` | **不能** restart（输入戳会拒） |
| 敏感性缺 inject / 扫参失败 | `edit_code` | 补 `source/inject/sensitivity.py`，再登记再跑 | 视停机点；无 inject 时多在敏感性节点 |
| 无 `--plan` 的旧全图、brief 被打回 | `edit_brief` | 改 brief，新开 run | 不能用旧 run 偷换 brief |
| paper_critic 批论文 | `edit_paper` | `restart --from writer` 定向重写被批节 | 能 |
| 数字对不上 / 红线炸 | `edit_code` | 修 `_entry`；图外 `reference run` 只对人闸与 `--strict` | 能 |
| 体系侧模型/写法明显更好 | （人判） | 吸收进 brief/plan，或显式采纳并记账 | 改 plan 则新开 run |

`restart` **不**带入新的 plan / brief / problem 哈希。改这三样只能新开 `--out`。

→ [15](15-s7-评审.md)

**⑫ 跑通** — 体系产出完整初稿。人评、少量改、`review-check`（可 `--strict`）、`accept`。Word/精排放工作面，不从骨架重写。  
→ [16](16-s8-验收.md)

## 2. 一张图

```text
人 + 主会话          导入 / EDA
        │
        ├─→ 外部第二家     探索 → 地图（可索取多轮）
        └─→ 本地探索 Agent 独立探索 → 本地地图
        │
人 新开对话           Diff：预构想 → 双图 → 拍板
主会话                登记拍板 / 清点
        │
人 在同一对话续跑      研究者：编码 · 实验 · 出数 · brief草稿
                      ※ 自己跑完 ≠ 结束
        │
主会话                brief.json（方向）+ plan.json（机读卡）
        │
        ▼  启动 Beacon
登记 _entry + inject/sensitivity.py
        → run --plan → critic 真跑 → 冻结执行 → 敏感性 → writer → …
        │
        ├─ edit_code：改脚本 → add --force → restart --from coder
        ├─ edit_plan：改 plan/brief → 新开 run --plan
        └─ 过：完整初稿 → 人评 → accept
```

## 3. 图里哪些节点还要

| 节点 | `--plan` 正式流 | 无 `--plan` 的旧全图 |
|---|---|---|
| analyst / modeler **生成** | 不跑；plan 已播种产出位 | 从 analyst 起，会调 LLM |
| blueprint_critic / model_critic | **真跑**（接入正当性） | 真跑 |
| coder_generate（LLM 写代码） | 默认关；冻结脚本直执行 | 无冻结且无 `--allow-coder-llm` 则停 |
| coder_execute / consistency | 要用 | 要用 |
| 敏感性 plan（LLM）+ 执行 inject | 缺 inject **停机** | 缺 inject 可 `phase=done` 滑走（兼容旧测） |
| figure / writer / paper_critic | 要用 | 要用 |
| table / evaluation / 人审 / latex | 要用 | 要用 |

不要实现 `plan.sensitivity_runs` 短路：敏感性子图仍由 LLM 出计划，数字只认 inject 重跑。

## 4. 不要再走的路

| 旧走法 | 错在哪 |
|---|---|
| 本地算完 → 骨架 / 会话 prose → 停 | 没启动 Beacon |
| `reference add` = 交差 | 登记是改代码入口 |
| 首枪 `run --from writer` | 应急接桥；正式入口是 `--plan` |
| 「S9 可选所以图不用了」 | 不用的是无人值守从零 codegen |
| expand / 手写 prose = 写作终态 | 应急可以，正式写作在 writer |
| 先写死 brief 再研究 | brief 后置，由研究倒推 |
| 把研究 CSV / evidence `markup_*` 写进论文 | 敏感数字以图内 inject 为准 |
| 改 plan 后 `restart` | 哈希闸会拒；必须新开 `--out` |
| 用 D-028/029/030 互相解释 | 流程以本页为准，不再叠 ADR |

## 5. 工程入口（产品化）

复制时把 `<题>` 换成题目录名。网关要在听（本机常见 `127.0.0.1:20128`）。

```text
# 预检（不跑图）
uv run math-agent run --dry-run --problem problems/<题>/problem.json --brief problems/<题>/brief.json

# plan
uv run math-agent plan build --brief problems/<题>/brief.json --out problems/<题>/plan.json
uv run math-agent plan check --plan problems/<题>/plan.json --brief problems/<题>/brief.json

# 图外登记与冒烟（改代码后必须 --force）
uv run math-agent reference add --problem problems/<题>/problem.json --solver problems/<题>/source/reference --entry _entry.py --force
uv run math-agent reference run --problem problems/<题>/problem.json --out runs/<题>-reference
uv run math-agent reference verify --problem problems/<题>/problem.json --evidence runs/<题>-reference/evidence.json
uv run math-agent reference recertify --problem problems/<题>/problem.json --evidence runs/<题>-reference/evidence.json --actor "<谁>" --notes "<人闸>" --verdict pass

# 正式全图
uv run math-agent run --problem problems/<题>/problem.json --brief problems/<题>/brief.json --plan problems/<题>/plan.json --out runs/<题>-graph

# 停机交棒（run 结束也会自动写）
uv run math-agent critic-handoff --out runs/<题>-graph
uv run math-agent watch --out runs/<题>-graph

# 改代码后续跑（同一 out；plan/brief 不能变）
uv run math-agent reference add --problem problems/<题>/problem.json --solver problems/<题>/source/reference --entry _entry.py --force
uv run math-agent restart --out runs/<题>-graph --from coder --reason "…"

# 写后对账 / 验收
uv run math-agent review-check --out runs/<题>-graph --strict
uv run math-agent accept --out runs/<题>-graph --approve
```

应急（不要当本题第一枪）：

```text
uv run math-agent run --from writer --evidence runs/<题>-reference/evidence.json …
uv run math-agent restart --from writer --reason "…"
```

## 6. 题目录（做题时认这个）

```text
problems/<题>/
  problem.md|json   data_profile.md
  exploration.md                        ← 研究收束后人读，不是对撞地图
  交接-beacon.md                        ← 收束后按 13附 出
  _派发/{本地,diff,研究}.md
  eda/   source/                        ← 附件本机保留、不入库
  source/reference/_entry.py            ← 冻结主求解（插座）
  source/inject/sensitivity.py          ← 图内扫参（无则 --plan 停）
  认知地图集/外部|本地|diff|清点
  研究/{scripts,data,figures}/          ← 实算；不是论文数字源
  _研究日志.md  解题说明.md  经验与坑.md
  brief.json   plan.json
```

`runs/` 是某次执行产物，不要当题目档案改。改 plan 再跑请换 `--out`（如 `runs/<题>-graph-r2`）。

硬禁止：先 brief 后对撞；搜本题题解当依据；产本地地图时读外部地图；只把关键结论留在对话框。

锁三件事（探索/研究通用）：出口类型明确；信息边界按站禁读；成本有预算。不锁「思考轮数」。

## 7. 数字口径（防串味）

| 数从哪来 | 用在哪 |
|---|---|
| 研究脚本 / `研究/data` | 人做方向、写 `_entry`、定 inject **网格** |
| 图外 `reference run` → `evidence.json` | 冒烟、人闸、`review-check --strict` 对照锚 |
| 图内 `coder_execute` stdout（Q 行 + RESULT） | **论文主数字** |
| 图内 `inject/sensitivity.py` 的 RESULT | **论文敏感性节** |
| `plan.json` 里的示例数 | 只帮助 critic 理解量级，不是发表数字 |

不要期望图内重跑与研究 CSV 逐位相同；口径一致、中心点对齐主方案即可。

## 8. 首跑常见坑（机械，不是「流程失败」）

这些是注入式全图接上真 LLM 之后会碰到的闸，按交棒改，不要改图结构。

| 停在 | 常见原因 | 改什么 |
|---|---|---|
| `blueprint_critic` 未过 | `data_requirements` 空；`recommended_route` 空；coverage `reason` 空泛；Q1 `task_type` 不像分析；Q4 目标写成 maximize；缺题面约束；验证标准无对照 | `plan.json`，**新开** run |
| `code_verify` 无主证据 | `_entry` 没 open 声明附件；或没产出 PNG | `_entry` → `add --force` → `restart --from coder` |
| 敏感性 `stop` | 没有 `source/inject/sensitivity.py`，或 RESULT 参数名对不上计划 | 写/改 inject；必要时让 plan 的 `sensitivity_relevant` 钉死参数名 |
| `model_critic` 打回 | 模型卡缺方程/覆盖/映射 | 补 plan，新开 run |
| paper_critic 缺两张证明 | 误走了 `--from writer` | 改走 `--plan`，让 critic 真跑 |

`plan check` 能挡住一半 blueprint 打回，但不能代替 critic。
