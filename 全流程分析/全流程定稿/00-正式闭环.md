# 00 · Agent 使用 Beacon：从头到尾

> **本页是唯一总图。** 后面 01–16 是各段怎么做；和本页冲突时信本页。  
> 不要用 S0–S9 当「两套主路径」。那些编号只是操作面命令的旧标签。

---

## 0. 先认角色（后面会换人）

| 角色 | 是谁 | 干什么 | 不干什么 |
|---|---|---|---|
| **人** | 你 | 开第二家、开新对话、拍板、评论文、accept | 不把对话框当唯一真相 |
| **主会话** | 本机主持 agent | CLI、拼包、记盘、抽查、收口 brief / 登记 | 不代写 Diff、不代评、不替人拍板 |
| **外部第二家** | 另一家模型 | 知识/方法探索，产出外部认知地图 | 不读本机未公开材料；不给最终竞赛解 |
| **本地探索 Agent** | 干净上下文的子 agent | 一次长探索，留下证据卡 + 本地认知地图 | 不看外部地图；不在这一步写正式论文 |
| **研究者会话** | 人新开（常从 Diff 续跑） | 把题**算明白**：编码、实验、否证、出数 | 算完不等于交卷 |
| **Beacon** | LangGraph + 机械闸 | 按 brief 跑登记代码、critic、**写论文** | 默认不让 coder 节点 LLM 写代码 |

科学对不对，以研究者实算为准。  
论文长什么样，以 Beacon 跑通后的稿为准。  
本地自己跑完全部，只是准备，不是结束。

---

## 1. 时间顺序（换角色跟着走）

### 第一幕 · 把方向找出来（Beacon 图还没启动）

**① 导入题面** — 主会话 CLI，人认 blockers。  
附件只读进 `source/`。不要一导入就 `brief init`。  
→ 细节：[01](01-S0-导入题面.md)

**② 看数据** — 主会话出 EDA 图和 `data_profile.md`。  
人看图；数字事实留给后面探索自己算。  
→ [02](02-S1-EDA画像.md)

**③ 两边独立探索**（可交错，不要互相偷看）

1. **人**把题面/EDA 发给**外部第二家** → 外部地图。缺证据就索取：主会话在本机算切片，打包再发，直到地图可对撞。  
   → [03](03-S2-外部开放探索.md) · [04](04-S2-索取与回填.md) · [05](05-S2-外部地图闭环.md)
2. **主会话**派**本地探索 Agent**（干净上下文，禁止读外部地图）→ `_证据卡.md` + `认知地图-本地.md`。  
   → [06](06-S2-本地认知地图.md)

**④ Diff** — **人新开对话**（不是主会话代写）：先锁预构想，再读双图，综合成可拍板的方向。  
主会话只准备派发、事后抽查。  
→ [07](07-S2-Diff综合.md)

**⑤ 人拍板，主会话登记** — 拍板表 + 主线。然后逐问清点（可薄，但问要齐）。  
→ [08](08-S2-拍板登记.md) · [09](09-S2c-逐问清点.md)

这一幕结束时：有方向，**还没有**竞赛解，**还没有**启动图。

---

### 第二幕 · 把题算明白（仍在本地）

**⑥ 研究者会话** — 优先在 Diff 对话上续跑，不要硬切成另一个「求解 Agent」。

在题目录里写代码、跑数、否证、改方向。拍板是工作假设，实验可以推翻（推翻必须写进 `_研究日志.md`）。

留下：脚本 / 表 / 图 / `_研究日志` / `解题说明` / `经验与坑` / 人读的 `exploration.md` / **brief 草稿**。

提示词：[prompts/研究](../prompts/研究/说明-从Diff续跑.md) · 本题派发：`problems/<题>/_派发/研究.md`  
→ [10](10-s5-求解推进.md)

> **停在这里的错觉**：研究者已经能交出数字和说明。  
> **正式口径**：这叫准备完毕，**不是交付结束**。

---

### 第三幕 · 压成方向手柄

**⑦ brief 定稿** — 把已经算过、站得住的方向压成 `brief.json`，`brief check` 过。

brief 是**暂定**的、拿来**驾驭 Beacon** 的手柄：告诉图要走哪条路、红线是什么、各问写什么。  
它不是研究任务单，也不是圣经。图跑起来以后如果方向被证伪：改 brief，或承认体系侧更好并记账。

→ [11](11-s3-brief定稿.md)

---

### 第四幕 · 启动 Beacon（核心从这里开始）

**⑧ 预检** — `run --dry-run`，人看 blockers。  
→ [12](12-s4-预检.md)

**⑨ 交接与登记代码** — 研究者收束后，先按 [13附](13附-交接文档模板.md) 在题根写 `交接-beacon.md`（操作 Beacon 的会话续跑或新开都能凭它开工），再 `reference add` / `source/inject/`。

登记**不是**把研究者旧代码交进去交差。  
登记是给本地 agent 插上 Beacon 的**改代码插座**：体系去跑这份代码；跑不过就拿 critic 意见回来改，再 `--force` 登记，再跑。  
替代的是 **coder 节点 LLM**，不是替代 Beacon。

→ [13](13-s5-证据登记.md)

**⑩ 图开始跑**（正式入口 `run --plan`；coder LLM 默认关）

```text
plan.json 播种蓝图+模型卡 → blueprint_critic / model_critic 真跑
     → 冻结脚本执行 → 一致性门禁
     → 敏感性（须 source/inject/sensitivity.py；缺则停机交棒）
     → figure → writer × N → paper_critic
     → table / evaluation / 人审 / latex
```

`--from writer` 只作应急接桥。论文数字以图内 execute stdout 为准。

→ [14](14-s6-论文装配.md)

---

### 第五幕 · 失败就交回手改，直到出论文

**⑪ critic / 门禁停机** — 这是闭环的一部分，不是「流程失败」。

| 现象 | 谁判断 | 动作 |
|---|---|---|
| 执行/一致性不过 | 研究者 | 改脚本，`reference add --force`，`restart --from coder` |
| critic 批蓝图/模型卡 | 研究者 | 补 `plan.json`（及必要时 brief），**新开** `run --plan` |
| 敏感性缺 inject / 扫参失败 | 研究者 | 写 `source/inject/sensitivity.py`（参数可参考研究表），再登记再跑 |
| 体系侧模型/写法明显更好 | 研究者 | 吸收进 brief/plan，或显式采纳并记账 |
| 数字对不上 / 红线炸 | 研究者 | 修 `_entry`；图外 `reference run` 只对人闸与 `--strict` 对账 |

→ [15](15-s7-评审.md)

**⑫ 跑通** — 体系产出完整初稿。人评、少量改、`accept`。Word/精排放工作面，不从骨架重写。  
→ [16](16-s8-验收.md)

## 2. 一张图

```text
人 + 主会话          导入 / EDA
        │
        ├─→ 外部第二家     探索 → 地图（可索取多轮）
        └─→ 本地探索 Agent 独立探索 → 本地地图
        │
人 新开对话           Diff：预构想 → 双图 → 拍板
主会话                登记拍板 / 清点
        │
人 在同一对话续跑      研究者：编码 · 实验 · 出数 · brief草稿
                      ※ 自己跑完 ≠ 结束
        │
主会话                brief.json（方向手柄）+ plan.json（机读卡）
        │
        ▼  启动 Beacon
登记代码（插座，可反复）→ run --plan → critic 真跑 → 执行 → writer → …
        │
        ├─ 不过：交棒手改代码（重登记）或改 plan（新开 run）
        └─ 过：完整初稿 → 人评 → accept
```

## 3. 图里哪些节点还要

| 节点 | 还用吗 |
|---|---|
| coder_generate（LLM 写代码） | 默认关。代码由研究者写 |
| coder_execute / consistency | 要用。跑登记代码 |
| 各类 critic | 要用。失败 = 交棒手改 |
| writer / writer_section | 要用。论文从这里出 |
| table / evaluation / 人审 / latex | 要用 |
| analyst / modeler 生成 | `--plan` 时不跑；播种产出位后 critic 真跑 |
| analyst / modeler | 无 `--plan` 的旧全图仍从 analyst 起 |

---

## 4. 不要再走的路

| 旧走法 | 错在哪 |
|---|---|
| 本地算完 → 骨架 / 会话 prose → 停 | 没启动 Beacon |
| `reference add` = 交差 | 登记是改代码入口 |
| 「S9 可选所以图不用了」 | 不用的是无人值守从零 codegen |
| expand / 手写 prose = 写作终态 | 应急可以，正式写作在 writer |
| 先写死 brief 再研究 | brief 后置，由研究倒推 |
| 用 D-028/029/030 互相解释 | 流程以本页为准，不再叠 ADR |

---

## 5. 工程入口（产品化）

```text
math-agent run --from writer --evidence runs/<题>-reference/evidence.json …
math-agent restart --from writer --reason "…"
math-agent critic-handoff --out runs/<id>
```

写后数字严格闸仍走 `review-check`（可加 `--strict`）。缺的不再是哲学，是题目侧模型卡是否要 `--model-card` 覆盖。

---

## 6. 题目录（做题时认这个）

```text
problems/<题>/
  problem.md|json   data_profile.md     ← CLI
  exploration.md                        ← 研究收束后人读，不是对撞地图
  交接-beacon.md                        ← 收束后按 13附 出；Beacon 操作会话开工入口
  _派发/{本地,diff,研究}.md
  eda/   source/
  认知地图集/外部|本地|diff|清点
  _研究日志.md  解题说明.md  经验与坑.md
  brief.json
```

硬禁止：先 brief 后对撞；搜本题题解当依据；产本地地图时读外部地图；只把关键结论留在对话框。

锁三件事（探索/研究通用）：出口类型明确；信息边界按站禁读；成本有预算。不锁「思考轮数」。
