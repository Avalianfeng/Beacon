# 一篇读懂 Beacon 闭环

> **这不是规则源。** 命令、参数、坑以 [全流程定稿/00-正式闭环.md](全流程定稿/00-正式闭环.md) 为准；本文讲的是**为什么体系长成这样**，以及每个环节**在做什么、停下来意味着什么**。
> 读完你应得到：全部设计的心智模型 + 上手推进的操作直觉 + 引导用户（而不是被用户引导）的信心。

---

## 0. 怎么读这篇文章

假设你是一个什么都不知道的会话，刚被用户打开，用户把一道建模竞赛题放在桌上，说："按咱们的 Beacon 流程做。"

你不需要先背任何命令。本文带你从零走一遍：**从开始使用，到往后推进**。每走一步，先遇到一个真实的问题，再看体系为这个问题做了什么机制。机制往往又带来新问题，于是有下一个机制——整篇文章就是一条问题链。链走完，你就"重新发明"了一遍这个体系，那时：

- 你会理解为什么有这么多文件和名词——每一个都对应一个你刚亲身遇到的问题；
- 你会知道每个停点、每张黄牌意味着什么，因为你知道它背后的机制；
- 你会有底气对用户说"这是设计内的交棒点，不是失败"，而不是等用户告诉你怎么办。

规则细节不在这里。文中凡是出现命令、字段、坑，都只点一句并给出链接——需要时去对应文档查。

## 1. 第一个问题：交付物是什么，凭什么被信任

竞赛的最终交付物是一篇论文，论文的命门是**可信**：每个数字要能追到计算，每个说法要能追到模型与数据。评委和用户都会问："这个数哪来的？"

现在想：一个 AI 会话从头做到尾，能不能交付这样的论文？

不能，有三个原因，每个都直接决定体系的一个大设计：

1. **会话的记忆会腐烂**。上下文越长越不可靠，跨天续跑会漂移。→ 所以**结论必须物化成文件**，"只把关键结论留在对话框"是硬禁止。
2. **会话会护短**。自己算出来的结论，自己再审一遍，很难推翻自己。→ 所以需要**独立的视角**（另一家模型、另一个干净会话）和**无立场的机械闸**。
3. **会话的产出不可复核**。聊出来的结论没有执行痕迹，别人无法验证。→ 所以需要**可复算的产物**：同一份代码、同一个环境、再跑一遍、得到同样的数。

反方向想：一台全自动机器从题面干到论文，行不行？也不行——真实的无人值守真跑（早期版本）证明：它会跑偏、会编造、会在 critic 循环里空转不收敛，而且没人把关方向。机器擅长的是**机械、闸门、复核、按契约执行**；不擅长的是**想明白一道题**。

于是体系的第一性结构出现了：**两个世界**。

- **认知世界**：会话、研究、讨论。私有、叙事、可以被推翻。负责"想明白"。
- **机器世界**：图（LangGraph 流水线）、文件契约、闸门。公有、可复核、可追溯。负责"执行与证明"。

中间有一道国境线。全文所有机制，都是在回答同一个问题：**认知怎么安全过境，变成可复核的论文？**

## 2. 认知世界的前半段：方向怎么长出来（快进）

（这一段不是本文重点，但链条要从头接上，否则后面的"接洽"没有来处。每个环节仍然遵循"问题→机制"。完整细节见定稿 [01](全流程定稿/01-导入题面.md)–[10](全流程定稿/10-研究会话.md)。）

**问题：一个头脑想一道题，够吗？**
不够。一个模型一个思路，会锚定在第一个想法上。→ 机制：**两条独立探索线，且外部线刻意多视角**——外部第二家（可多家 / 多 `外部/V*`，互不喂地图；不懂题也能贡献知识/方法，且不许读你本机材料）和本地探索 Agent（干净上下文，`本地/V*`，不许看任何外部 V 地图）。两边各自产出「认知地图」；外部还可再开 V2 放大对撞轴。  
（两道墙是机制的核心：**信息边界**。探索阶段的地图互相禁读，为的是后面 Diff 时能看见「多个独立头脑撞出来的差异」，而不是两团互相污染的想法。多视角契约：定稿 03–05、07 · `prompts/外部/说明-多视角版本.md`。）

**问题：探索产出多份地图，谁来做判断？**
不能让写地图的会话自己裁决——它们各自有立场。也不能让主会话代写（主会话没有参与探索的上下文）。→ 机制：**人新开一个干净对话做 Diff**：先锁「预构想」再读**本地现行 + 全部已闭环外部 V\***（防锚定），综合出冲突与结合点（冲突段带来源），产出可拍板的候选方向。→ **人拍板**（判断责任归人），主会话登记拍板表并逐问清点。

**问题：方向定了，可它只是"想出来的"，经不起真实数据吗？**
拍板是工作假设，不是答案。→ 机制：**研究会话**——通常在 Diff 对话上续跑（方向认知还热着），把方向拿到真实数据上去验证：回测、实验、否证、修正，跑到"我对这道题有了经真实计算检验的稳定认识"为止。留下脚本、表、图和研究日志。

**问题：研究完，算完事了吗？**
这正是最初最容易错的一步。研究者的产物（数字、说明、日志）仍然属于**认知世界**：它们长在会话与私人脚本里，没有机器复核过。你"算明白了"只说明你信任自己——论文要的是别人也能复核。

**正式口径：本地自己跑完全部，只是准备，不是结束。**

收束时研究者留下两件人读的东西：`exploration.md`（给主会话/人压缩方向用）和 `brief草稿`。然后——过境开始了。

## 3. 接洽：认知怎么过境（全文核心）

从现在起，每一步都发生在"研究结论"与"机器图"之间的口岸上。慢读。

### 3.1 机器不信会话，信文件——但文件要写成两份

**问题：你说你算明白了，机器凭什么信？**
它不对话语负责，只对文件负责。→ 机制：研究收束后，主会话把方向压成 `brief.json`——**方向手柄**：每问走哪条路、红线是什么、写作要点、数据口径。它会切片注入图的各节点，约束"写什么、禁什么"。

**问题：有 brief 就够了吗？**
不够。brief 回答"写什么、禁什么"，但图里的评审节点还要审"**模型长什么样**"——变量有哪些、目标函数是什么、约束是什么、验证计划是什么。这是另一套形态。→ 机制：`plan.json`——**图内蓝图 + final 模型卡**：蓝图（小问、决策变量、目标、约束、验证标准）+ 模型卡（方程、变量表、目标/约束映射、逐问覆盖）。

**问题：两份文件会不会打架？**
它们同源（都由同一份研究收束产生），并且用 **coverage 锚**栓在一起：brief 的每一条都要锚到 plan 的某个小问/某条方程，注明"这条 brief 是怎么落地的"。锚是血缘证明。人只在真偏离时改默认值。

- brief = 方向手柄（驾驭图，人读为主）——定稿 [11](全流程定稿/11-brief定稿.md)
- plan = 机器审的模型（critic 的审问对象）——`plan build` 出 v0，人补关键字段

**问题：研究者要手写 plan 的 schema 吗？**
不用。`plan build` 从 brief 合成 v0，人只需补 critic 真会查的几样：决策变量、验证标准的数值合理区间、推荐路线、数据要求、coverage 的理由。`plan check` 零 token 预检"还缺什么会被打回"。（注意：check 挡得住一半缺口，挡不住语义分——见 3.3。）

### 3.2 为什么不让图自己从头想一遍

**问题：图里有 analyst（拆题）和 modeler（建模）节点，让它们自己从头干不行吗？**
可以，但那是给"没有前置研究"的情况用的。我们已经花了大量真实计算得到更好的结论——图内 LLM 从零生成会：偏离已验证的方向、消耗大量 token、且产出质量不如研究结论（这是早期无人值守真跑的教训）。

→ 机制：**注入**。`run --plan` 把 plan 里的蓝图与模型卡**播种到图内对应节点的产出位**——图的节点、边、闸门结构一行不改，只是 analyst/modeler 的"生成"这一步不跑了，因为它们的位置上已经放好了更可信的产物。

### 3.3 为什么不干脆跳过前面、直接让图写论文

**问题：既然前面都注入好了，为什么不跳过所有评审直接进写作段？**
这是这条路上最贵的一次试错，结论值得背下来：

早期版本正是这么做的（`--from writer` 接桥：研究证据直接喂给写作段）。它撞上两堵墙：

1. **结构性停机**：论文评审节点硬性要求"建模评审通过 + 代码一致性报告通过"两张证明才能放行——而这两张证明只有前面的节点真跑过才会存在。跳过前面 = 证明不存在 = 每次都在论文评审门前必然停机，还无法通过 restart 修复（重启不产生新证明）。这不是稿子质量问题，是结构问题。
2. **闸门形同虚设**：如果为绕开它而放行，那 critic、门禁就全部变成了摆设——我们辛苦建的"可复核"体系自己先不守规矩。

→ 机制：**注入 + 真检**。播种之后，让图内自己的评审节点**真跑**：

```text
播种蓝图 → blueprint_critic 真跑（蓝图质量 + brief 覆盖）
→ modeler 短路（0ms，不重生成不跑推导链）
→ model_critic 真跑（假设/严密性/相关性/可计算 + 与蓝图对齐）
→ coder 执行登记代码 → model_code_consistency 真跑
→ ……
```

**这就是"接入的正当性"**：你的研究结论不是被豁免审查地塞进去，而是以图能审的形态进去、过图自己的门。评审打回 = 你的卡有真问题（缺字段、口径冲突、覆盖不齐——cumcm 首枪的 blueprint 打回就是实例），补卡重跑；这不是刁难，是体系在替你查漏。

（`--from writer` 没有删除，降级为应急工具——它仍会撞那两堵墙，所以正式题不要拿它当第一枪。）

### 3.4 代码谁写：研究代码为什么只是"参考"

**问题：模型过了评审，图要算数了。求解代码从哪来？**
曾经设计让图内 coder 节点用 LLM 写代码。真实教训：LLM 生成的竞赛求解代码不可靠、不可控。而研究者明明已经有一堆能跑出数字的代码——**直接把研究代码塞进图行不行？**

不行。这里有一条最容易被忽略的认识：**研究代码和图内代码的目标不同，二者不同构**：

- 研究代码的目标是"研究者自己算明白"：爱怎么组织怎么组织，输出给人看。
- 图内代码的目标是"**实现模型卡**"：必须实现模型卡里声明的变量、目标、约束，必须以约定格式输出（Q 行、RESULT 行），必须让下游评审能核。

把研究脚本原样塞进去，一致性评审会打回——不是它不好，是它不回答评审的问题。

→ 机制：**登记插座 + 人（agent）在环**。

- 研究代码 = **参考素材**（它的数字、网格、口径是方向依据）。
- 图内正式代码 = 由 agent（你）按**模型卡这个契约**来写和改，通过 `reference add` **登记**进图的执行插座。
- 图内 coder 节点不再用 LLM 生成代码，而是**确定性执行登记代码**（哈希校验、零 LLM、限时）。
- 一致性评审（model_code_consistency）审"代码 vs 模型卡"：变量实现了没有、目标实现了没有、约束实现了没有、输出指标对齐没有、**数值数量级在验证标准给的合理区间内没有**。
- 不过 → 停机 → 你按评审意见改代码 → **每次改完必须 `reference add --force` 重新登记**（哈希变了，图才会跑新代码）→ `restart --from coder` 再跑。

所以登记不是"把旧代码交进去交差"，是**给你自己插一个能反复改代码的插座**。改多少次都行，每改一次登记一次。

### 3.5 图内执行凭什么证明数字是真的

**问题：登记代码跑出来的数字，怎么证明不是编的？**
机器无法判断"你读没读数据"，但可以查**执行痕迹**。→ 机制：血缘闸——图内执行时要求代码**真实打开** `problem.json` 声明的附件（xlsx/csv），并且执行工作目录里要落下**证据图（PNG）**。只读二手摘要、不碰附件、不出图 → 一致性评审报"无主证据"。

这不是形式主义：它是"论文数字可溯源"链条的第一环。真跑里第一轮就栽在这——研究脚本只读了 `研究/data` 的摘要，没开附件，被打回。

### 3.6 敏感性：为什么研究跑过的表不能直接引用

**问题：研究者做敏感性分析时已经跑过加成带、成本冲击的表，论文直接引用不行吗？**
不行，同一句话：**论文里的每个数字都要能在图内环境被复核**。研究表跑在私人脚本里，没有统一执行环境，无法溯源。→ 机制：论文敏感性节的数字必须由图内敏感性**子图重跑**产生：图内 LLM 出扫参计划 → 执行 `source/inject/sensitivity.py`（你按研究网格写的扫参脚本）→ 输出约定格式的 RESULT。

研究敏感性表降级为**参数参考**：它不再被引用，它只告诉你"该扫哪些参数、什么网格"。正式路径上，缺扫参脚本或执行失败 = **停机交棒**（不许静默滑过——这是诚实闸：论文宁缺一章，不写跑不出来的数）。

### 3.7 论文为什么只能在 writer 链里出生

**问题：会话直接写论文不行吗？**
历史教训：会话写 prose、骨架展开（expand）产出的稿子，数字"未溯源"、踩红线——因为会话写作时没有机制约束它只能引用执行过的数字。→ 机制：**写作是承诺，承诺必须对着唯一数字源写**。

论文正式稿只从图内 writer 链出来：图内执行 stdout（Q 行 + RESULT）是**论文主数字的唯一来源**，writer 分节写作（每节一个存档点）被提示词约束只能引用这些数字。骨架、expand、会话手写 prose 全部不是正式终态。

约束是「提示词 + 事后 tokenizer」，不是「正文里不能出现任何证据文件没有的数字」。题面年份、约束（如最小陈列量 2.5 kg）、参考文献出版年，writer 几乎一定会写，它们不在 `evidence.json` 里——所以 `--strict` 的 tokenizer 常会黄/红，哪怕关键 RESULT 已经对齐。这是闸的粒度问题，不是「论文数字来源」改了。

真跑还教会体系三件"写作侧"的事（都已变成系统机制，不是文笔要求）：

1. **引图**：评审读的是章节文本，不是排版后的图。写作必须产生"如图N所示"，系统在装配前确定性补引——否则每轮都因"未引用图"被打回。
2. **消毒**：plan/代码里的机读参数名（如 `cost_shock`）一旦溜进假设小节，会被当成工程泄漏。写作视图在源头剥离内部标识。
3. **否决门槛**：评审的否决只留给真问题（编造、前后不一致、完全不引图、上游没过）；"建议换个更优方法"这类意见进 suggestions、不进否决——否则评审永远能找到话说，稿子永远过不了（真跑里连续 8 分打转的教训）。

### 3.8 停机 = 交棒点：为什么设计成"停"而不是"自动重试"

**问题：评审不过，为什么不自动重试？**
自动重试 = 同一批输入、同一个错误，重复烧钱且不收敛。→ 机制：**首次不过即停**（保留现场），把问题**打包**交回给最擅长改它的人/agent。

图停机时自动写一个**交棒包**（critic-handoff）：为什么停、评审的完整意见、建议改什么（`edit_code` / `edit_plan` / `edit_brief` / `edit_paper`）、下一步命令。

**问题：拿到交棒包后，怎么知道"改完怎么再跑"？**
这是最容易混乱的地方，用一条规则讲清楚：**restart 只重放现场，绝不吸收外部改动**。图的内存里只有开跑那一刻的输入。于是：

| 你要改什么 | 怎么再跑 |
|---|---|
| 代码（`_entry` / inject 脚本） | 改 → `reference add --force`（重新登记）→ `restart --from coder`（同一 `--out`） |
| plan / brief（评审说方向/模型卡有问题） | 改 → **新开** `run --plan`（新 `--out`） |
| 论文内容（论文评审提意见） | `restart --from writer`（按意见**定向重写被批的节**，意见会注入写作提示词） |

为什么改 plan/brief 必须新开：每次 run 会给 problem/brief/plan 三个输入记**指纹**（哈希）。restart 校验指纹，对不上就拒绝——保证"你审的和我跑的是同一版本"。所以"改 plan 后 restart"会被拒，这是保护不是故障。

**问题：哪些会停、停了说明什么？**（完整坑表见定稿 00 [第 8 节](全流程定稿/00-正式闭环.md)，此处只给判断框架）

- `blueprint_critic` / `model_critic` 打回 → 你的 plan 卡有缺口或语义问题 → 补卡新开 run。
- 一致性报"无主证据" → 代码没碰附件/没出图 → 改代码重登记。
- 敏感性停机 → 缺扫参脚本或参数对不上 → 写/改 inject。
- 论文评审门前说"缺两张证明" → 你误走了应急入口（`--from writer`）→ 改走 `--plan`。

### 3.9 收口：黄牌、绿牌、和只有人能给的通行证

**问题：全链跑完，机器说"好了"，就完了吗？**
还差三道关：

1. **终态收口（finalizer）**：机器把成品钉账。注意它有两类结果：`completed`（绿牌：无质量警告）和 `degraded`（黄牌：有警告但仍交付）。黄牌警告是**独立于论文评审**的质量门——正文页数不够、有效对照方案不足、LaTeX 溢出。黄牌 ≠ 评审没过，也不等于可以交：交卷前要把警告清单处理掉。正式流程已锁：不再因缺模型评审/一致性证明而 degraded。页数/对照/Overfull 仍可以黄牌，那是交卷体面，不是入口。
2. **数字对账（review-check，可 --strict）**：这**不是**再跑一遍求解器。图外冒烟（`reference run` → `evidence.json`）在启动图**之前**就已经做过；写后对账核证据里的**关键 RESULT**是否出现在论文。年份、题面约束、参考文献年只提示，不挡闸。brief 图题是否原句、敏感性有没有「主口径取舍」口头禅，同样不挡闸。读报告的方法见定稿 [15](全流程定稿/16-停机交棒.md) 与 [00 第 7 节](全流程定稿/00-正式闭环.md)。
3. **人评与 accept**：**只有人能说"可以交"**。机器能给绿牌/黄牌，给不了"参赛"的通行证。注意 `--no-interrupt` 只是无人值守跑完图（人审环节自动放行），**不等于人已经验收**——这是 16 站反复强调的。

到这里，链条就完整了。回头看一遍整条链，你会发现每个机制的出现都拦下了一类真实的失败。这就是全部设计。

## 4. 会话（你）怎么工作：把认识变成行为

### 4.1 角色是怎么来的（不是规定，是分工的必然）

把整条链按"谁适合干什么"切一刀，角色表就自己长出来了：

| 角色 | 为什么存在 | 边界 |
|---|---|---|
| **人** | 判断责任（拍板、评稿、accept）机器不可替代 | 不把对话框当唯一真相 |
| **主会话** | CLI、打包、记盘、抽查、收口 brief/plan/登记——口岸操作员 | 不代写 Diff、不代评、不替人拍板 |
| **外部第二家 / 本地探索 Agent** | 独立视角防锚定 | 互相禁读 |
| **研究者会话** | 深度理解与真实计算 | 算完 ≠ 交付 |
| **Beacon** | 机械执行、评审、写作、闸门、checkpoint | 不默认让 coder LLM 写代码 |
| **接洽会话**（可能就是你） | 口岸之后的图操作者 | 只重放不吸收，输入变了就新开 |

### 4.2 三层文档，各干各的

- **本文**：心智模型。读一次，困惑时回翻。
- **交接文档**（`problems/<题>/交接-beacon.md`，模板在定稿 [13附](全流程定稿/13附-交接文档模板.md)）：本题的状态与命令序。研究收束后、过境之前先写它——它让"续跑研究会话"和"新开会话读盘"两条路等价，是"禁止只把关键结论留在对话框"的落地文件。
- **定稿 00**：命令、参数、坑。卡住时查。正式做题流程已锁在这一页；旧规划稿在 archive，不当现行用法。

### 4.3 上手推进的最小动作序列（认识已就位时的肌肉记忆）

```text
一屏命令（细节照抄定稿 00 第 5 节，这里只给顺序）：
plan check → reference add/run/verify/recertify（冒烟+人闸）
→ run --plan（正式全图）
→ 停了读 critic-handoff：edit_code → add --force → restart --from coder
                        edit_plan → 新开 run --plan
→ 跑通：review-check --strict → 人看初稿 → accept
```

### 4.4 对用户说话的正确姿势（几个例子）

- 图停了 → "这是交棒点：评审说 X，我们需要改 Y，改完再跑。不是失败。"
- 黄牌 → "稿子过了论文评审，但质量门有三条警告（页数/对照/排版），交卷前要处理。"
- 改了 plan 想 restart 被拒 → "这是指纹保护：输入变了必须新开 run，不能重放旧现场。"
- 用户问"你直接写论文不就行了" → "论文数字必须来自图内执行，会话手写无法溯源——这是体系的底线。"

## 5. 常见误解速查（曾经都真实发生过）

| 曾经以为 | 实际 |
|---|---|
| 本地算完 = 结束 | 只是准备；正式稿必须过境 |
| `reference add` = 交差 | = 改代码插座，每次改完要重登记 |
| 首枪用 `--from writer` | 应急工具；会因缺上游证明结构性停机 |
| 改 plan 后 restart | 指纹拒绝；必须新开 `--out` |
| 研究 CSV / evidence 的数可直接进论文 | 论文数字只认图内 stdout 与 inject 重跑 |
| 评审 8 分反复 = 稿子不行 | 可能是结构性原因（没引图/要未实现方法）；先看机制再动稿 |
| degraded = 没过评审 | 黄牌是质量门（页数/对照/排版），与评审独立 |
| `--no-interrupt` 跑完 = 验收 | 只是无人值守跑完；人没看过就不算 |
| `review-check --strict` exit 1 = 关键数没对齐 / 注入流失败 | 先看缺了哪个 RESULT。年份/题面/文献、图题逐字、「主口径取舍」现在只 WARN |
| 写后对账会再跑一遍 `_entry` | 不会。冒烟在启动图之前；`--strict` 核已有 evidence 的关键 RESULT |
| 论文里写了 YOY/另一套件数，对照门却是 0 | 对照必须是独立 `RESULT: baseline=<名>` 行，且与主方案指标可比、数值不同；Q 行里的对照不算 |
