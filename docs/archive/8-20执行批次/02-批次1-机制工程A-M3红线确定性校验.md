## 一、brief schema 扩展设计（本批次核心设计，与 M4 共用）

现状：`ModelingBrief` 的 39 条为文本条目（brief.json），无机器可读禁止项。
设计（向后兼容，v2 扩展字段，缺省不影响旧 brief）：

```jsonc
{
  "redline_rules": [
    {
      "id": "rl-001",                       // 关联 39 条 id（如 2.2-fbond-red）
      "target": "code|stdout|paper",        // 校验对象
      "rule_type": "literal_ban|expr_ban|symbol_ban|result_rule",
      "pattern": "600.71",                  // 字面量 / 正则表达式 / 符号名 / 数值表达式
      "severity": "hard",                   // hard=违反即 stop；warn=记入诊断不阻断
      "note": "禁止硬编码官方参考值"
    }
  ]
}
```

- rule_type 语义（v1 保守实现）：
  - `literal_ban`：code 文本含数值字面量（含格式化变体如 `600.710`、`6.0071e2`）→ 违规；
  - `unit_mix_ban`：量纲/单位一致性（**D3 决策，2026-08-20：M5 校验层并入本机制，不单独造轮子**）——如「力用 kN、应力 MPa、力矩 kN·m，同式混用即违规」，扫描 code 文本单位标注模式，先 warn 级观察误报；
  - `expr_ban`：code 文本匹配正则（如 `0\.8\s*\*\s*T_max`）→ 违规；
  - `symbol_ban`：code 文本出现符号名（如 `K_avg`）→ **v1 只做出现检测（宁严勿松）**，用途语义判断标记为已知局限，真跑观察误报率；
  - `result_rule`：stdout 数值等式/区间（如 `T_opt == 0.8 * T_max`）→ 违规（依赖 result 解析，可为 warn 级）。
- 兼容：无 brief / 无 `redline_rules` → 恒通过（向后兼容，同 brief_coverage 语义）；`brief check` 校验规则 schema 合法性。
- 本次真跑（brief-v2）至少应包含：600.71（literal_ban，code）、`0.8*T_max`（expr_ban，code）、K_avg（symbol_ban，code）。
