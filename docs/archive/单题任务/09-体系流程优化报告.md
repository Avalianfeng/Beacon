# Beacon 体系流程优化报告：外部知识注入与多视角推演

- 建立日期：2026-08-18
- 关联：MCM-51 锚杆题 r1–r11 全程实证
- 定位：体系级（非单题）优化探讨。回答三个问题：① 现有体系能否继续优化？② 未来多角度推演能否灌输外部信息，而非完全依赖题面？③ 哪些视角是体系自身无法拓展的？

---

## 一、现状盘点：体系的知识来源（代码事实）

当前 Beacon 流水线的知识输入通道，按 `src/math_agent` 代码逐一核实：

| 通道 | 位置 | 状态 | 容量 |
|---|---|---|---|
| 题面文本（problem/background/questions） | `run` 初始状态 → analyst/modeler 全链 | ✅ 主通道 | 全文 |
| 附件数据摘要（data_hint：列名/行样例/稀疏键提示） | `prompts/coder.py` 等 | ✅ 主通道 | 结构化摘要 |
| LLM 预训练知识 | 所有 `complete()` 调用 | ✅ 隐含 | 模型权重内 |
| 反馈循环（评审→重试→定向修复） | critic/consistency/low-score 通道 | ✅ 运行时 | 见 P01–P20 |
| **RAG 外部语料检索** | `rag/retrieve.py`；analyst/modeler/writer 注入点 | ⚠️ **默认关闭**（`RAG_ENABLED` 默认 `"0"`）；51mcm 从未启用 | TOPK=4，analyst/modeler 各 1500 字符、writer 800 字符 |
| 学术文献检索 | `tools/scholar.py` + `references.py` 静态库回退 | ⚠️ 仅 writer references 分组 | ≤10 条 |
| 历史教训沉淀（P 系列、docs） | `docs/` | ❌ **人读，不注入体系** | — |
| 官方评分标准 / 参考思路 / 获奖论文 | 无通道 | ❌ **完全缺失** | — |

**结论（事实）**：体系的"知识闭包" = 题面 + 附件摘要 + 模型预训练 + 反馈循环。RAG 通道**机制上已存在**（`math-agent ingest` 可把任意语料目录嵌入 `runs/rag.sqlite`），但默认关闭、容量有限、且只注入"检索上下文"而非结构化约束。**评分标准这类"比赛元知识"没有任何注入通道。**

## 二、实证缺口：r1–r11 证明的"视角盲区"

以本题官方评分标准为对照，列出体系 11 轮运行中**从未自发产生**、但外部资料中明确写明的视角：

| 视角 | 外部资料中的答案 | 体系表现（r1–r11） | 性质 |
|---|---|---|---|
| 问题1.2 应做**变点检测/分段回归**（非 min 力学模型） | 官方评分标准明确"突变点识别模型"，岩石 T_c∈[100,150]、煤体∈[150,200] | r11 仍用工况A参数直接算 600.71，方向性错误 | **方向盲区**：题面只说"给出临界预紧力矩"，未提示方法 |
| F_bond 用**钻孔直径** D_hole（非锚杆直径） | 附录2 公式 F_bond=π·D_hole·L_bond·τ；工况A=334.27kN、B=169.65kN | r11 用锚杆直径，数值错 245~565 倍 | **细节盲区**：题面公式存在但未强调参数选择 |
| 问题3.1 **调心垫圈定量分析**（10 分） | 评分标准：e=0 参考线、e_cr≈3.66mm、e=5mm 提升 233%、150 N·m 规范线 | r11 完全未提及调心垫圈 | **概念盲区**：题面附录1 符号表有"调心垫圈"，但问题3 正文未提 |
| K 按直径使用（工况A→K₂₀、B→K₂₂） | 评分标准参考结果三组 K | r11 全用整体 K=0.176681 | **粒度盲区** |
| 问题4 应建 **min 四约束统一模型** + 围岩分级 | 评分标准：T_opt(f)=min{T₁..T₄}，软/中/硬三级 | r11 用拍脑袋 T_opt=0.8·T_max | **结构盲区** |
| f→E 必须**参数化假设 + 敏感性**（不能拍脑袋） | 评分标准开放性说明；官方思路强调"不要伪装成唯一确定" | r11 用 E=f×1e9 被 sensitivity 校验拦截 | **严谨性盲区** |
| 压陷公式 δ=P(1-ν²)h₀/(E·b²)，h₀=900mm 载荷影响深度 | 附录2 明示 | r11 用 k·A_b 近似，h₀ 参数未用 | **公式盲区** |

> **核心事实**：这 7 项没有一项需要"更聪明的模型"——全部是**外部资料中已写明、但体系无法获取的信息**。r1–r11 的反馈循环只能在"题面+预训练"闭包内试错，闭包外的视角（调心垫圈、变点检测）无论跑多少轮都不会自发出现。这直接回答了"依赖于体系本身完全无法拓展"的担忧——**属实，且已实证**。

## 三、为什么体系无法自行拓展这些视角

1. **输入即边界**：analyst 的 blueprint 只由题面+背景+问题生成（`prompts/analyst.py`），没有"评分标准/参考解法"输入项。模型只能从题面和预训练知识猜测出题人意图。
2. **反馈循环是闭包内的**：评审（model_critic/paper_critic）也是同一个模型家族，其判断基准同样是"题面+预训练"——它不知道评分标准要求变点检测，就不会因为"你没做变点检测"而拒绝。r11 一致性评审自认"未实现分段拟合"仍给 9 分（P17），正是闭包内评审的体现。
3. **RAG 通道存在但从未启用**：51mcm 全程 `RAG_ENABLED=0`。即便启用，也需先有人把评分标准/参考论文/领域文献 ingest 进库——**"谁来准备语料"本身就是人工环节**。
4. **多视角机制不存在**：全链单 analyst、单 blueprint、单 modeler 路线。没有"数据驱动视角 vs 力学视角 vs 工程视角"的并行推演或反方论证。

## 四、优化方向（设计建议，本轮未实现）

按"投入产出比"排序：

### A. 建模预备阶段（Modeling Brief）：标准化资料 + 人机协同认知注入（最高优先）

**为什么要分两层（实证）**：r1–r11 的 7 项视角盲区中，标准化注入（评分标准文本）只能解决约 4 项"数值/结构类"（变点检测区间、F_bond 用钻孔直径、K 按直径、压陷公式）；其余 3 类**即使把标准答案给模型，论文也写不出"为什么"**：

| 盲区 | 标准化注入能给的 | 只有人讨论才能产生的 |
|---|---|---|
| 3.1 调心垫圈 | 公式 T_max(e)、e_cr=3.66、233% | 工程意义叙事：e=0 参考线为什么代表垫圈效果、垫圈在什么现场条件下是"必要条件"、233% 如何解读为"释放坚硬围岩承载潜力" |
| 1.2 变点检测 | T_c 区间 [100,150]/[150,200] | 为什么"前期非线性/后期稳定"本质是变点检测问题、为什么取区间+推荐值而非单点、均值化消除单次实验误差的理由 |
| 4 的 f→E | 参数化映射 E₀(f/f₀)^m | "题目未给唯一关系，必须声明为参数化假设并做敏感性"的严谨性立场——这是竞赛论文防扣分的表述艺术 |

评分标准给的是"评分点"，论文要的是"思考过程"。**标准化输入是低熵答案，人参与的建模预备是高熵认知**——后者正是用户强调的"极强的自定义"，也是"杜绝重大方向性错误"的前置保障。

#### A1. 标准化资料包注入（机器可读，改动最小）
- 题目 spec（`run --problem` 的 JSON）增加可选字段 `reference_material`（评分标准/参考思路/领域知识/获奖论文摘要的文本或文件路径）。
- analyst 与 blueprint_critic 的 prompt 注入该资料包，硬性指令："参考资料中的方法要求优先于默认建模直觉；若与题面冲突，在 blueprint 中标注来源"。
- 同时注入 modeler/coder 关键节点，作为建模路线约束。

#### A2. 人机协同建模预备（Human Modeling Brief，核心设计）

**目标**：任务开始前，由人注入"具体思路 + 注意事项 + 必须体现的讨论点"，通过前期的卓越认知工作杜绝重大方向性错误——不是给模型抄答案，而是给模型"思考起点"。

**流程**（在 `run` 之前新增一个前置阶段，不进入 LangGraph 主图）：

```
题目导入 → [建模预备对话] → 产出 brief.json → run --brief brief.json → 流水线
```

**brief.json 结构**（8 个部分，人工填写，可沉淀为题目级资产复用）：

| 字段 | 内容 | 本题示例（来自 iteration-plan） |
|---|---|---|
| `per_question_direction` | 逐题建模类型指引 + 明确禁止的方向 | 1.2 必须是变点检测/分段回归，**禁止**用工况A参数直接算临界值；2.2 P_max=min(P_yield,F_bond)，压陷只作钢带判据 |
| `formula_notes` | 关键公式原文、参数选择注意事项 | F_bond=π·D_hole·L_bond·τ（钻孔直径！）；δ=P(1-ν²)h₀/(E·b²)，h₀=900mm；K 按直径使用 |
| `required_discussions` | 论文必须体现的讨论点（工程意义/假设声明） | 调心垫圈 e=0 参考线意义、233% 解读；f→E 必须声明"参数化假设非唯一"+敏感性；T_c 取区间+推荐值不声称唯一 |
| `red_lines` | 方向性错误红线（禁止清单） | 不得硬编码 600.71/0.8·T_max；不得用 E=f×1e9 拍脑袋映射；不得把压陷放进 P_max 的 min |
| `figure_plan` | 必做图清单 + 标注要求 | 图3 临界点标注、图6 三条线+e_cr、图8 主控分区（共 8+1 张） |
| `scoring_notes` | 评分标准要点（如有） | 满分分布、±5% 容差、参考数值区间 |
| `data_notes` | 数据注意事项 | 表2/3 五测点均值化、T 范围 25~375、稀疏分组键 ffill |
| `reference_direction` | 参考文献方向 | 巷道支护、Winkler 地基、螺纹力学 |

**注入点与覆盖验证**：
- analyst：prompt 注入 brief 为"建模方向约束"，blueprint 必须**逐条显式回应**（新增 `brief_coverage` 字段：每条状态 = 遵守 / 偏离+理由）——复制 question_coverage 机制，防止模型忽略人工输入；
- blueprint_critic / model_critic：把 brief 作为评审基准之一，"blueprint 未覆盖 brief 第 X 条"记 issue；
- modeler：路线选择约束（公式/参数注意事项）；
- coder：实现红线（red_lines 直接进代码提示）；
- writer：required_discussions 注入各 section 模板，确保讨论点出现在论文中；
- 门禁：`brief_coverage` 全遵守或显式偏离才可 advance（确定性校验，不依赖 LLM 判断）。

**与现有流程兼容**：
- `run --brief path/to/brief.json` 为可选参数；不提供则走现有流程（向后兼容）；
- 主图结构不变（前置对话是 CLI/Web 层的一次交互，不新增图节点）；
- brief 沉淀为 `docs/problems/<题号>/brief.json`，同题复用、跨题参考（衔接 E 通道）。

**成本评估**：
- 实现：CLI 模板生成 + analyst/modeler/coder/writer 四处 prompt 注入 + brief_coverage 校验——**约 1–2 天工作量（小改版）**；
- 收益：本题 11 轮中有 5+ 轮死于方向性错误（1.2 方向、F_bond 参数、0.8 系数、f 映射、压陷公式），每轮 30–45 分钟 / 15–25 万 tokens。**一次建模预备（人工 30–60 分钟）可消除全部方向性错误轮次**，投入产出比极高；
- 用户判断依据：本次实验已验证"闭包内试错不可达外部视角"（第二节实证），且"论文要思考过程、标准答案给不了"（本节分层论证）——**大改值得**。

### B. RAG 常态化（机制已有，补齐启用与语料）
- `MATH_AGENT_RAG_ENABLED=1` + `math-agent ingest` 把 `docs/`、官方资料、参考论文嵌入 `runs/rag.sqlite`。
- 现状限制：TOPK=4、每节点 ≤1500 字符——对"评分标准全文"这种高密度约束可能截断，需按题型分层（评分标准走结构化注入 A，领域知识走 RAG）。
- 检索 header 已有"仅供启发，不可照抄"声明，符合竞赛诚信。

### C. 评分标准 → 机器可读门禁（衔接 O06）
- 把评分标准中的"参考结果范围"（如 T_c∈[100,150]、F_bond,A=334.27kN±5%）解析为 blueprint 的 `validation_mapping` 数值区间，进 coder 提示 + 一致性门禁（确定性校验）。
- 这正是 O06"pass_criteria 机器可读提取"的落地路径，且能直接修掉 P17（评审放行"自认缺失"）。

### D. 多视角并行推演（中期，工作量中等）
- analyst 阶段并行产出 2–3 份 blueprint（如：数据驱动视角 / 力学解析视角 / 工程实用视角），blueprint_critic 综合择优或融合。
- 或增加"反方推演"节点：对已通过 blueprint 主动提出"出题人可能期待的另一种解法"。
- 注意成本：每视角一次 LLM 调用，需与收益权衡。

### E. 知识沉淀回灌（长期，成本最低）
- 每题的教训（如本题 9 条转向清单）写入 `docs/`，并通过 A/B 通道注入后续题目。
- 沉淀文件本身可 ingest 进 RAG 库，形成跨题经验库。

## 五、风险与边界

| 风险 | 说明 | 对策 |
|---|---|---|
| 外部资料误导 | 非官方推演（如 GPT 思路）可能错误；评分标准也可能有不同解读 | 资料包来源分级：官方文件 > 人工整理 > 模型推演；analyst 需标注引用来源 |
| 照抄违规 | 参考论文/思路直接进论文 | RAG header 声明 + table_assembler 禁用词清洗 + writer 数值溯源硬约束（已有） |
| 信息过载 | 大段资料挤占模型上下文，稀释题面注意力 | 容量上限（1500 字符级）+ 仅关键节点注入 + 结构化为要点而非全文 |
| 依赖人工准备语料 | 资料包/RAG 语料需人工整理 | 每题一次准备成本，多题复用（E 通道） |
| 人工输入质量不均 | brief 由人填写，质量取决于人的建模认知；错误指引会直接带偏方向 | brief 模板结构化 + 来源分级标注；model_critic 仍按题面独立核验（人工指引不能覆盖题面硬约束）；迭代中可修订 brief 重跑 |
| 人参与增加前置时间 | 每题建模预备 30–60 分钟 | 相比每轮 30–45 分钟/15–25 万 tokens 的方向性错误循环，一次前置投入消除 5+ 轮试错，净收益显著；且 brief 可复用/沉淀 |
| 人工指引与题面冲突 | brief 可能与题目要求矛盾 | 冲突时以题面为准（analyst prompt 明确优先级：题面 > brief > 预训练直觉），blueprint_critic 交叉核对 |

## 六、结论

1. **体系可以继续优化**，且突破口不在"更严格的评审/更多重试"（P01–P20 已证明这条路在收敛），而在**打破知识闭包 + 提升人的参与度**——让外部信息（评分标准、参考解法、领域知识、历史教训）与人的建模认知进入建模决策。
2. **"灌输外来信息"在机制上可行且必要**：RAG 通道已存在（默认关闭），学术检索已有雏形；但标准化资料只能解决"数值/结构类"盲区，**"为什么这样建模、论文怎么论述"的思考过程必须由人注入**（分层论证见第四节）——这正是用户强调的"极强的自定义"，也是建模竞赛论文区别于答案堆砌的本质。
3. **体系自身无法拓展的视角已被 r1–r11 实证**：7 项盲区全部是"外部资料写明、体系闭包内不可达"的信息。**这不是模型能力问题，是输入设计问题**——输入即边界。
4. **落地优先级（本次实验验证后调整）**：
   - **第一优先：A2 人机协同建模预备（Modeling Brief）**——前置对话注入逐题方向/公式注意/讨论点/红线/图表规划，`brief_coverage` 门禁防忽略。约 1–2 天工作量（小改版），可消除本题 5+ 轮方向性错误（每轮 30–45 分钟/15–25 万 tokens），投入产出比最高；
   - 第二：A1 标准化资料包（评分标准文本注入，改动最小，与 A2 共用注入通道）；
   - 第三：C 评分标准门禁化（衔接 O06）；
   - 第四：E 知识沉淀回灌（brief/教训跨题复用）；
   - 第五：D 多视角并行推演（视成本评估）。
5. **预期效果**：建模预备阶段落地后，"方向性错误"类问题（本次 40 分空白项中的大部分）可在任务开始前被杜绝，论文内容不再出现明显的评分标准违背；后续迭代即可专注于**建模论文本身的优化**（表述、论证深度、图表质量），而非方向纠偏。
