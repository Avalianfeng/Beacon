# 前端与新题入库——简化计划（独立计划，不阻塞主线）

- 建立日期：2026-08-21
- 定位：**独立计划（另案）**。前端壳允许整体重设计（D6 已批准，原则 3 豁免）；本计划只覆盖
  「前端极简重设计 + Web 新题入库」两件事：**直接进入现有接口、最简单模式**，不做复杂逻辑与设计；
  **允许用户做较复杂的手工操作，复杂度外置给人**。
- 状态：**暂缓**——主线（brief-playbook → 导入 → M3/M2 → pilot → mcm51-b 真跑）完成后再启动；
  [08-前端重设计与交互方向](08-前端重设计与交互方向.md) 冻结为方向记录，执行以本文件为准。
- 用户约束（2026-08-21）：真实的导入过程需要对源代码做重构；前端 + 新入库另起计划；
  不需要太复杂的逻辑和设计，直接进入现有接口、最简单模式即可。

---

## 一、范围（只做两件事）

1. **前端极简重设计**：每个产出流程一个看板看状态（现有 `watch` / `progress.jsonl` /
   `insights/` 数据的透出），无对话式建模 UI、无多路径推演、无能力边界自动识别
   （08 的完整形态不进本计划）。
2. **Web 新题入库**：复用现有接口——
   - 解析链路：`math_agent.problem_ingest`（`parse_problem_file` / `apply_vision_transcription`）
     经由现有 `scripts/extract_file_meta.py` / `scripts/vision_transcribe_problem.py`（`server.mjs`
     现有 spawn 方式不变）；
   - 资产落盘：与 CLI `problem import`（00 设计）共享同一套目录约定
     （`problems/<题号>/source/` + `problem.md` + `problem.json`）；
   - 最小接线：解析产物落到 `problems/<题号>/source/` 的收尾步骤；或直接让用户在 CLI 完成
     import、Web 只负责 PDF/图片转写（复杂度外置）。

## 二、与现有代码的接口（不改内部逻辑）

- `server.mjs` 现有 spawn python 脚本路径与 `run/supervise --problem --brief` 透传均保持不变；
- 新增 CLI 命令（00 设计 O1–O4）是 Web 与本地共用的唯一事实源，Web 不做第二套逻辑；
- `frontend/` 旧资产清理清单见 [00 第九节](00-新题上线流程设计.md)，删除动作执行前需用户确认
  （工作区安全规则）。

## 三、执行顺序（暂缓期内不排期，解冻后按此顺序）

1. 前端旧资产清理（git rm / 归档，用户确认后执行）；
2. 看板前端（最简：一个看板看状态）；
3. Web 入库接线（复用现有脚本，落盘到统一目录）。

## 四、明确不做

- 对话式建模 UI；多路径推演/回溯前端；能力边界自动识别；数据管理高级形态（08 第三/四节完整形态）；
- 任何新后端服务、新库、新 API 设计——复用现有接口即可；
- 前端任何「智能」逻辑——判断与决策全部外置给人（与主线 brief-playbook/pilot 分工一致）。
