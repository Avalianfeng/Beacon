## 一、根因（已代码定位，三层叠加）

1. `src/math_agent/nodes/coder.py:90-94` `_missing_baseline_items`：`if not _has_green_logistics_attachments(state): return []` —— **非物流题根本不生成 baseline 任务**（MCM-51 力学题无订单/距离矩阵附件 → 直接返回空）。
2. `src/math_agent/prompts/coder_baseline.py:10-33` `BASELINE_SPECS` 三个预设（no_schedule 无调度 / simple_pred 简单平均预测 / greedy 贪婪）指令全是**物流语义**（调度、预测模型、MILP/随机规划），力学题不可用。
3. `src/math_agent/nodes/model_code_consistency.py:79` `required_baselines = {"no_schedule", "simple_pred", "greedy"}` 特化集合；`finalizer.py:396` 门禁「有效对照方案 ≥2」本身是**通用的**，问题在上游喂不出东西。

## 二、设计

### 方案（推荐）：brief 指定对照 + 通用基线库回退

1. **brief 结构化对照字段**（并入批次 1 的 schema v2 扩展，一次设计）：
   ```jsonc
   "comparison_baselines": [
     {"id": "cb-001", "name": "均值参数简化", "method_hint": "用整体平均 K 替代分段回归（物理可行但精度低）", "evidence_role": "baseline"}
   ]
   ```
   专家在前置定方向时顺带指定 1–2 个「与主方案不同方法」的对照（这是前置信息，不是参考答案数值——与原则 1 不冲突）。
2. **通用基线库**（`prompts/coder_baseline.py` 重构）：
   - 保留物流三预设（题目有物流附件时仍用，向后兼容）；
   - 新增**题型无关预设**：`const_mean`（常数/全局均值替代拟合）、`linear_extrap`（线性外推替代分段/回归）、`simple_greedy`（贪心/按序构造替代优化）——指令模板参数化（数据加载与评估口径必须与主方案一致，RESULT: 行格式不变）。
   - `_baseline_items`/`_missing_baseline_items` 改为：brief 指定 > 题型通用库（按数据特征可选）> 物流三预设（仅物流附件题）。
3. **required_baselines 特化拆除**：`model_code_consistency.py:79` 不再硬编码集合——改为「存在 ≥2 个 effective baseline 类别」即可（对齐 finalizer 门禁语义），或读 brief 的 comparison_baselines。
4. 模型一致性检查（`_verified_green_contract_report`）中基线指标名对齐逻辑保持通用化。

### 最小可行切分

- 阶段 2a（本批次）：通用基线库 + 闸门拆除（无 brief 的非物流题也能出 2 个通用对照）——先让门禁真实可达；
- 阶段 2b：brief comparison_baselines 字段接线（随 schema v2 一起落地）——让专家可指定高质量对照。

## 三、测试

- 单测：
  - 非物流题（无物流附件）无 brief → 队列生成 ≥2 个通用基线任务；
  - 物流题 → 仍生成 no_schedule/simple_pred/greedy（向后兼容断言）；
  - 有 brief comparison_baselines → 按 brief 生成（id/类别正确、evidence_role=baseline）；
  - finalizer 门禁：2 个有效类别通过、1 个不通过（既有测试语义保持）。
- 证据角色隔离：baseline 产物不得覆盖 primary（CLAUDE.md 规则），复用既有角色断言。

## 四、验证与实验需求

- 真跑验证（批次 5 brief-v2）：`final_state.json` 出现 ≥2 个 `evidence_role=baseline` 且 `RESULT: baseline=*` 可解析；论文「各方案结果对比表」非空（12 §7 残留硬伤「基线对照纯文字」闭环判据）。
- **需要实验**：通用基线质量评估——对照是否「真可比、真不同方法」（防止生成与主方案同构的假对照）；token 增量成本记录（每对照 1 次 LLM + 1 次执行，进成本表）。

## 五、风险

- 通用基线指令若与主方案同构 → 假对照。缓解：method_hint 强制「与主方案采用不同方法/不同假设」，并在提示中禁止复用主方案 RESULT。
- 队列/预算膨胀：每对照约 +1 次调用 + 执行；用成本遥测观察，超预算再压缩预设数。
