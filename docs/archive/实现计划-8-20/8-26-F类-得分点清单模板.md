# F 类（重定位 2026-08-26）：得分点检查的落点说明

> **用户质疑后重估**：F 类原方案（得分点清单模板 + 从官方细则拆解）**在正常流程中不成立**——
> 正常做题时不会有官方评分要点（赛后才有）。按执行原则（贴合真实流程；能在 agent 侧完善的
> 就在 agent 侧完善，体系侧做需明确价值），F 类重新定位如下，**体系侧不新建独立工具/文档**。

## 一、正常流程（无细则）下得分点检查怎么做

**得分点检查 = 题面信号驱动的交付物完整性检查**，作为 **轨 B 写作/评审 agent 提示词的一条**（agent 侧完善），
不建独立体系工具。内容（评审 agent 必答项 Q4 的展开，见 `8-26-C类-评审口径核查必答项.md`）：

1. 题面指定交付物是否齐备：指定表格（表 1–5 类）全部填出、行数与格式对齐题面模板（含"可加行"提示）；
2. 数字自洽：每台设备时长 = 工程量 ÷ 效率（取整规则与题面假设一致）——工程量守恒；
3. 关键 claim 与题面假设一致（如双设备工序完成口径）；
4. 敏感性至少覆盖一类参数且档位出自实跑（`check_paper_numbers.py` 溯源）；
5. 诚实声明（启发式/近似）到位。

这些条目本质是"评委必然检查的交付物"，由 agent 在写作/评审时自我核对，**不需要体系侧清单文档**。

## 二、赛后校准场景（有细则时）

官方参考答案进场后，用 calibration 资产（E1）拆真实得分点、跑口径偏差报告（E2）复盘——
这是 E 类校准流程的一部分，不是正常做题流程。mcm51-b 实例见 `problems/mcm51-b/calibration/官方参考答案要点.md`
（赛后复盘用途，不进入正常做题路径）。

## 三、落点汇总

| 场景 | 得分点检查方式 | 落点 |
|------|----------------|------|
| 正常做题（无细则） | 题面信号驱动的交付物完整性检查（上述 5 条） | 轨 B 写作/评审 agent 提示词（agent 侧） |
| 评审节点（轨 A） | 必答项 Q4（有细则逐条核对；无则交付物齐备性） | evaluation/paper_critic prompt（C3 已注入） |
| 赛后校准（有细则） | calibration 资产 + 口径偏差报告 | E1/E2（已落地） |
| 命题者意图积累 | 赛后得分点命中率 → E3 模式库（≥2 题后） | E3（长期） |
