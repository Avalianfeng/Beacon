# D-028 · S6 完成 = 本地完整初稿；写作引擎 ≠ 仅 expand

- 日期：2026-09-04（用户纠偏）｜ 状态：accepted
- 决策编号：07 决策表 D-028

## 背景

cumcm23-c 操作面走到 S6 骨架后，agent 把「后段没做事」读成设计：D 盘分节改稿、expand 失败即停、S9 非默认所以 writer 不用。这与用户原设想冲突——**本地要产出完整可评初稿，后面只少量修改，不应负担彻底写作。**

走错的机制（文档误导 × 路线错位，不是论文能力被拆）：

1. **D-007 总纲图未跟 D-020**：D-019（prose 归 D 盘）已被 D-020 取代，但总纲仍画「D 盘：分节改稿」，操作面契约仍写「Beacon 管到骨架论文」。agent 读总纲就会把权宜当成终态。
2. **D-005 被过度解读**：D-005 说的是**执行方式**（默认分阶段，不无人值守 `supervise`），不是产出物（不产论文）。writer 链仍在 `graph.py`：`writer → writer_section → paper_critic → table_assembler → evaluation → human_review → latex → finalizer`。8-21 拆除的是绿色物流专属章节，不是通用写作。T-19（D-008）后，有冻结参考实现可跳过 coder 直达下游。
3. **`stage` 机械前缀 ≠ 论文完成**：S6 只要磁盘上有 `paper.md` 就算完；骨架分析槽是【待展开】。agent 把 stage 绿当成「写作职责已尽」。
4. **expand 被当成唯一写作引擎**：T-11/`reference expand` 是给操作面的填槽命令（单槽 + 无语义白名单 + 写后增量数字红线）。cumcm23-c 两次红线失败只说明**这条实现糙**，不说明「机器不能写」。反例：`runs/mcm51-c-skill-v1/paper.md`（轨 B 协议，完整 prose、零编造）。
5. **学-20③ / 定稿 14「本轮可不跑」** 是本题探索性停点，被读成产品把写作外置。

expand 当时要解决什么：D-002 之后操作面是主路径，`reference paper` 无 LLM、只能出骨架。要让操作面不依赖整图 S9 也能出论文本体，才加 expand。它是 **T-11 的试作**，不是 D-020 的完成形态。D-020 写的是「操作面接入 writer 能力」。

## 决策

1. **职责（重申 D-020，纠正总纲残留）**：Beacon 产出**完整论文初稿**（可评、数字可溯源）。D 盘只做拆开、Word 化、出图精排、支撑材料、赛后诊断，以及**少量**修改。不得把「从骨架写终稿」当成外流程主业。
2. **S6 两层完成**：机械层（`tables` + 骨架 `paper.md`）供 `stage` 推演；**写作层**须另出完整初稿（`paper-prose.md` 或等价完整 `paper.md`）。骨架不能交接、不能 `--approve`。
3. **写作通路（按可靠程度，不是按 CLI 默认顺序）**：
   - **轨 B 协议**（已验证）：语义化 evidence（数字→含义→文件+行号）+ 三件套 + 写作时零编造自查 + 分节 + 独立评审抽查。
   - **writer 链**（代码在）：S9 从 writer 接续，或有 T-19 冻结时跳过 coder；不是「拆掉了」。
   - **`reference expand`**：可选填槽；失败后**必须切前两条**，禁止扩白名单把研究笔记搬进 evidence 来「过关」。
4. **D-005 / 「轨 A 出好论文」防复燃**：禁止把无人值守全图宣传为已验证出赛论文。**不禁止**本地受控写作。
5. **D-027 例外**：本决策授权改 `内外全流程总纲` 与 `8-27-操作面契约` 中与上列冲突的句子（D-027 曾规定治理不重写这两份细则）。

## 后果

- **正面**：agent 不再把骨架绿、expand 红、S9 可选读成「后面不用写」；S7/S8 重新有可评对象。
- **负面**：操作面还缺「轨 B 协议产品化」的正式子命令；本轮只纠文档与完成语义，不实现新 CLI。
- **保留**：增量数字红线不关；S9 仍非默认全图；人未看完整初稿不得 `accept --approve`。
