# D-023 · 重试哲学：门禁一次停

- 日期：2026-08-29（学-11 落地；与 D-022 hard 红线协同）｜ 状态：accepted → 已落地
- 决策编号：07 决策表 D-023

## 背景

学-11：阻止性失败一次直接停（人/agent 断点续跑）；自动重试只留给输出性迭代（JSON/think 剥离）与延迟类暂时问题。D-022 已把 `hard_redline_violations` → `stop`。其余 routing 门禁仍是「retry 至 `MAX_*` 再 stop / 带病前进 / `advance_review`」。

## 决策

1. **routing 门禁首次未通过即 `stop`**：`after_blueprint_critic`、`after_model_critic`、`after_paper_critic`、`after_model_code_consistency` 不再看迭代预算。废除 `advance_with_warning` 与 `advance_review`。
2. **接续**：checkpoint + `recover` / `restart --from coder` / `math-agent review`（论文完整时置 `paper_review_takeover` 走人审）。
3. **本轮不改**：`complete()` 的 JSON 修复与传输 failover；coder 单任务 `MAX_CODE_RETRIES`；`retry.py` 仍不接线。
4. **`MAX_*_ITERATIONS`**：保留 env/遥测，不再决定 routing 去向。

## 后果

- 正面：与学-11 / D-022 同一旋钮；不再空转 2～3 轮 critic。
- 负面：basic/improved 不再「cap 仍前进」；论文未过 critic 不会自动进人审（须显式 `review`）。
- 兜底：无 brief 时 coverage 恒通过；human_review 语义不变。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 只改 hard 红线、其它门禁仍 retry | 学-11 未落地，成本最低的推广被浪费 |
| 连 `MAX_CODE_RETRIES` / `complete()` 一并关掉 | 输出修复与传输故障不是阻止性失败 |
| 保留 `advance_review` 自动放行 | 与一次停打架；接管应显式 |
