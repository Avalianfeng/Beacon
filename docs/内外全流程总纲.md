## 二、环节总表（每环节：产物 / 执行者 / 完成判据）

### 内（Beacon 操作面，细则见 8-27-操作面契约）

| 阶段 | 产物 | 默认执行者 | 完成判据 |
|---|---|---|---|
| S0 导入 | `problem.md/json` + `source/`（哈希） | 人 | `problem show` 可读；questions 非空；feasibility 已填 |
| S1 数据探查 | `data_profile.md` + **每附件 ≥1 张概览图**（时序/分布/缺失，路径写入 md） | 人/外部 agent | 对撞可拿它当数据证据包；**概览图齐全（强制，D-007）**；交付表锚点已记 |
| S2 探索 | `exploration.md` + `逐问清点.md` + **`领域知识.md`（强制，D-007）** + 对撞记录 | 人主持+外部强模型 | 人主持过 diff；"最容易整体漏掉的东西"有一节；领域知识卡片存在；未写官方答案 |
| S3 brief | `brief.json`（含口径分级/备选口径） | 人 | `brief check` [OK] |
| S4 预检 | `preflight.json` | 人/agent | `run --dry-run` 全过；blockers 空 |
| S5 求解验证 | 求解脚本 + `evidence-package.json` + `independent-review.json` | 人/解题 agent | stage 认 S5（package + recertify pass）；**L4 闸门**（check_l4_gates） |
| S6 装配 | `reference.json` + `runs/…/paper.md` + tables | 人/agent | reference run 数字与 S5 锚点一致；paper 可 check_paper_numbers 溯源 |
| S7 评审 | `review-report.json` + 评审结论 | 人/评审 agent | `review-check`（五闸门）过；C 类五问有书面回答 |
| S8 人审提交 | `acceptance.json`（approved=true） | 人 | `problem stage` 认 S8 |
| S9 流水线（可选） | runs 产物 | 监督进程 | 不作主路径（D-005） |

`problem stage` 的连续前缀只认机械产物（上表完成判据中的 package/json/paper 等）。**b/c/d（概览图 / 领域知识）为人检**：缺口列在 `--json` 的 `d007_missing`，**不把**已完成的旧题从 S8 打回 S2。

### 交接点（内 → 外）

- **交接物**：`paper.md`（骨架/终稿）+ `evidence-package.json` + `runs/` 产物 + `problems/<题号>/` 档案。
- **数字唯一来源**：D 盘工作面的 `结果/关键数字.md`（= 可复跑代码实跑产物，附 文件:行号）——外流程一切数字以此为准，与 evidence-package 一致。
- **原则**：外流程不在 Beacon `runs/` 里改论文当定稿；Beacon 不写评分细则、不做 Word 精排（体系工作流程 §1）。

### 外（D:\数学建模 工作面，细则见体系工作流程）

| 阶段 | 产物 | 完成判据 |
|---|---|---|
| 搭建 | `工作面/<id>/`（对照/数据/代码/图/结果/关键数字.md/README/来源） | md-sections split/verify 往返一致 |
| 分节改稿 | `章节/` → merge `paper.md` | 无造数/口径错；方法名=代码；诚实声明/假设分级保留 |
| 出图配图 | `图片/` 达标 + `配图放置说明.md` | `check_figures.py` 0 张 ⚠️ |
| 支撑材料 | 四类目录 + zip | `pack_support.py` + 人工对照上一题逐目录核对 |
| Word 交付 | paper.docx + 修改日志 | 交接说明自查清单 |
| 赛后诊断 | `赛后评估/最终评估报告.md` + `参考答案.md`（探针） | 七问答完；A/B 两表分开；错误分类 + 分流（建模赛后诊断 §8 骨架） |

## 三、教训回流机制（正式通道，L4 为第一例）

1. **沉淀**：赛后诊断中"体系性缺陷"写入 `D:\数学建模\docs\建模赛后诊断.md` §6（已沉淀五条）；
2. **回流清单**：诊断报告"待注入 Beacon"节列出候选（机制/闸门/契约改动），**不在 runs/ 里改论文**；
3. **注入**：按批次把候选变成 Beacon 的 T-xx 闸门/契约/check 工具——登记 **D-xx 决策**（如 D-006 = L4 闸门进 review-check）；
4. **验收**：新题真跑时验证闸门生效（C 题教训 → mathorcup16-c/mcm51-c 复查）；
5. **本地可修复项**：只回写本题 `结果/关键数字.md`，不进规则。

已回流示例：C 题五条规则 → `check_l4_gates.py`（敏感性回流 G1 / 状态重建 y0 G2 / 异常操作定义 G3 / 解释失败 WARN G4，D-006）。

## 四、题目档案生命周期（含赛后段）

`problems/<题号>/` 完整生命周期（操作面契约 §0.1 + 以下赛后段）：

| 段 | 文件 | 何时产生 | 维护 |
|---|---|---|---|
| 生产段 | problem/source/brief/exploration/data_profile/逐问清点/领域知识/… | S0–S8 | 操作面契约 |
| **赛后段** | `赛后诊断.md`（D 盘报告摘要+指针）、`教训卡片.md`（本题教训，下题强制）、`calibration/`（官方细则转录：官方参考答案要点.md + official_answers.json）、`关联题.md` 或教训卡片内关联节 | 赛后诊断后回填 | 每题赛后必做 |
| 知识段 | `领域知识.md`（术语/典型模式/常见陷阱，联网核查产物） | S2 强制 | 随题演进 |

- **关联题**：同届（mcm51-b ↔ mcm51-c）、同型（mcm51-c ↔ mathorcup16-c 数据驱动）在 `教训卡片.md` 头部"关联题"节交叉引用——前后题的方法/口径/教训可互查。
- **旧题不补**（用户 2026-08-27）：历史题档案保持现状；仅 mcm51-c 补赛后段作为范本。

## 五、b/c/d 强制产物（从"建议"升级为"判据"）

| 方向 | 强制内容 | 落点 |
|---|---|---|
| b 数据先探 | S1 数据画像先行，且"关键交付表锚点"（如 C 题表 1.1 的 B 同刻读数）必须在 data_profile.md 记录 | S1 完成判据（D-007）；`stage` 人检见 `d007_missing` |
| c 图表辅助 | 每附件 ≥1 张概览图（探索用，非论文图），路径写入 data_profile.md | S1 完成判据（D-007）；缺口 → `data_profile.md#概览图` |
| d 领域知识注入 | S2 必须产出 `领域知识.md`（联网核查术语/典型模式/陷阱），并写入 brief 的 background_knowledge | S2 完成判据（D-007）；缺口 → `领域知识.md` |

## 六、边界（本总纲不覆盖）

- 不做具体功能实现：T-xx 待实现项（brief extract/数据探查命令/骨架→终稿 prose 等）按需慢慢推进；
- 不做 Web 完整形态、RAG（原则 4）、图体系重设计（大模块 1，暂缓）；
- 估分不是赛后诊断主产物（建模赛后诊断 §0）；
- 系统不在 `runs/` 里改论文当定稿、不写评分细则、不做 Word 精排（三处职责）。
