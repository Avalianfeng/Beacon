# 参考实现登记中间件（轨 B → 体系自动装配论文）

> **目标**：把「agent 写好的求解脚本 + sha256」登记为题参考实现，体系据此自动做
> **数字提取 → 表格装配 → 论文骨架**，替代轨 B 当前「主会话手动喂给 writer」的人工环节。
> **节奏**：不赶 MVP，一步步全做；每阶段子 agent 实现 + 主会话独立验证。
> **定位**：与轨 A `run` 流水线**并行**的独立轻量路径（纯代码、无 LLM analyst/modeler/coder）。

## 背景

- 批次 6.3 缺口：轨 B 脚本 → 体系无「登记 + 自动装配」正式路径。
- C 题已人工整合参考实现（`problems/mcm51-c/source/reference/` 7 文件，A1），方向不变；
  本中间件把「登记 + 装配」正式化为命令，之后新题只需 `reference add` 即可复用。

## CLI 面（新增 `math-agent reference` 子命令组）

| 命令 | 作用 |
|---|---|
| `reference add --problem <spec> --solver <dir> --entry <entry>` | 复制 solver .py → `source/reference/` + sha256 + 更新 problem.json + 写 reference.json（entry） |
| `reference run --problem <spec> [--out <dir>]` | 跑入口 → 解析 RESULT/Q 行 → 输出 evidence.json |
| `reference tables --problem <spec> --evidence <json> [--out <dir>]` | Q 行结构化字段 → 交付表（md/csv） |
| `reference paper --problem <spec> --evidence <json> [--out paper.md]` | evidence + brief → paper.md 骨架（摘要/假设/结果/表格/附录A溯源/附录B代码清单） |

## 设计要点

- 复用 `tools/runner.py`：`run_python`（跑入口）、`extract_numeric_results`（RESULT）、`structured_evidence_lines`（Q 行）——均为纯函数。
- evidence.json 是中间产物（数字单一事实源）；表格/论文都从 evidence + brief 生成，不重跑、不编造。
- 表格映射用题级声明（字段名 → 表标题/列），C 题先落地 4 张交付表。
