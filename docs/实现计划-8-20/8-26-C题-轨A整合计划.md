## 一、背景与目标

- 轨 B 已产出 8 个求解脚本（`runs/mcm51-c-skill-v1/solve/`），本质是「参考实现」，但无体系登记路径（见 `docs/8-26 记录.md` 批次 6.3）。
- mcm51-b 已有雏形：`source/reference_solver.py` + brief 的 `formula-solver`/`formula-reference` + `rl-greedy`/`rl-result-format`，让 coder exec 参考实现而非从零生成。
- C 题 coder 从零生成必翻车（venv 无 sklearn/ruptures，变点/鲁棒回归/分阶段预测全要手写 numpy/scipy）。本计划做最小整合，让轨 A 走 exec 降级路径。

## 二、已摸清的 pipeline 机制（本计划依据）

1. **coder 注入面**：`render_coder_brief` 只注入 brief 的 `red_lines` + `formula_notes`（**不注入** `data_notes`）。
2. **data_dir 解析**：`_read_problem_spec` 把相对 `data_dir` 解析为绝对路径 `problems/mcm51-c/source`，coder prompt 的数据提示给绝对路径。
3. **RESULT 门禁**（`validate_numeric_results`）：`RESULT: baseline=ours <ascii指标>=<数值>`，指标名 `\w+`、值纯数值、≥4 指标；禁 `%`/字符串/列表/nan/inf；指标名避开 cost/count/rate 等敏感词（触发非负/比例/整数检查）。
4. **血缘门禁**（`validate_code_data_usage`）：wrapper 的 AST 需有 loader 调用 + 附件名/目录枚举；运行时 audit hook 记录真实打开声明的附件。
5. **exec 共享命名空间**：coder wrapper `exec(reference_solver.py)` 后，reference_solver 可直接用 wrapper 里已定义的 `data_dir` 变量。

```
RESULT: baseline=ours q1_gain=<g> q1_rmse=<r> q2_node1=<n1> q2_node2=<n2> q3_common=<c> q4_rmse=<r4> q5_rmse=<r5>

Q2: node1=<n1> node2=<n2> time1=.. time2=.. speeds=[s1,s2,s3]
Q3: table31_a..e=<..> common=<c> r2=<r> contrib_rain/pore/deep/micro=<..>
Q4: table41=[5值] rmse=<r> level_rmse=<..> final=<..> ci=[lo,hi]
Q5: best=drop_rainfall rmse=<r> rel_err=<..> thresholds_slow/accel/fast=[..]
```

- RESULT 行 7 个数值指标（主证据门禁 ≥4 即可，多给安全）。
- `Q<id>:` 行承载非数值/明细（表值、组合名、阈值），供 paper_critic 引用；**全 stdout 禁出现 nan/inf/error/failed/traceback 字样**。
