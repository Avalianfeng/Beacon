# 多工序协同作业问题：方向性认知地图

这道题表面上是“求最短完工时间”，但从出题和评阅角度看，它实际上叠加了 **工序前后约束 + 多资源容量约束 + 移动设备 + 跨车间运输 + 双资源同步完成 + 重复循环工序 + 多车间协同 + 离散设备购置决策**。

所以，**现在最重要的不是选一种算法，而是先把题目到底允许哪些调度行为、哪些因素真正进入约束系统厘清**。

从现有研究的术语来看，它与经典 **Resource-Constrained Project Scheduling Problem (RCPSP)**、**Resource-Constrained Multi-Project Scheduling (RCMPSP)**、**multi-site RCPSP** 有明显联系；尤其“资源可以在不同地点之间移动并产生运输时间”这一点，与 multi-site RCPSP 非常接近。([科学直通车](https://www.sciencedirect.com/science/article/pii/S0377221722007639?utm_source=chatgpt.com))

但这道题又并非一个可以直接套模板的标准 RCPSP，因为它还有一些题目自定义的特殊结构。

------

# 一、首先把题目真正要求的东西拆开

## 1. 问题1：单车间、单班组

> 班组1独立完成 A 车间全部工序，使完成时间最短。

这里实际上只存在：

- 一个项目：A；
- 一个车间；
- 班组1全部设备；
- A1 → A2 → A3 固定顺序；
- 设备之间存在有限容量；
- 同一设备不能同时执行两个工序；
- 但不同设备可以并行。

### 真正需要决定的不是“工序顺序”

A1、A2、A3 的**工序顺序已经被题目锁死**。

真正的调度决策主要是：

> 当工序需要某类设备时，到底分配哪一台设备，以及这台设备何时开始。

不过 A 只有三道工序，因此问题1更像是整个模型的**基础验证场景**。

尤其值得注意 A1、A2 都需要两类设备：

- A1：灌装机 + 输送臂
- A2：抛光机 + 清洗机

因此这里很早就出现一个重要结构：

# [ \text{一道工序的完成}

\text{多个资源条件同时满足}
]

也就是一种“AND 型资源需求”。

------

# 二、问题2开始真正进入全局调度

> 班组1完成 A–E 五个车间全部任务，使总完工时间最短。

这里与问题1相比，最大的变化**不是工序数量变多**，而是：

> **设备开始成为跨车间流动资源。**

因此调度系统从：

[
\text{单车间资源调度}
]

变成：

[
\text{多车间 + 可移动资源 + 运输时间 + 工序约束}
]

这正是 multi-site RCPSP 类问题的重要特征：资源在不同 site 之间转移，而且转移期间不能用于执行任务。([Springer](https://link.springer.com/article/10.1007/s10479-022-05109-0?utm_source=chatgpt.com))

------

# 三、题目中最值得重视的关键词

我认为这道题真正的“建模信号”主要在下面这些词。

| 关键词                             | 潜在含义                                          |
| ---------------------------------- | ------------------------------------------------- |
| “严格按给定顺序依次执行”           | 项目内部 precedence constraint                    |
| “设备数量固定”                     | renewable resource capacity                       |
| “同一时刻每台设备只能服务一道工序” | individual machine disjunctive constraint         |
| “设备可重复使用”                   | 不是一次性资源                                    |
| “同一车间运输时间忽略”             | 同车间设备切换可视为零 setup time                 |
| “不同车间转移时间不可忽略”         | sequence/location-dependent setup / transfer time |
| “两类设备共同参与”                 | 多资源耦合 / AND resource requirement             |
| “两类设备都完成后才完成”           | 同步完成判据                                      |
| “速度相同”                         | 运输时间只由距离决定                              |
| “精确到秒且向上取整”               | 离散时间 / ceiling rounding                       |
| “重复2遍，共3遍”                   | 循环/重复生产段                                   |
| “预算500000”                       | 离散投资 + 调度联合优化                           |
| “购买设备台数”                     | 整数决策                                          |
| “最短时长”                         | 典型 makespan minimization                        |

尤其是最后三个问题：

> **移动资源、重复工序、设备投资**

三者叠加以后，就已经不是一个特别朴素的“流水线排程题”。

# 四、物理 / 数学结构地图

## 4.1 基本时间结构

每道工序都有一个基础加工时长：

# [ p_{ijr}

\left\lceil
\frac{Q_i}{v_{ir}}
\right\rceil
]

这里：

- (Q_i)：工程量；
- (v_{ir})：设备类型 (r) 对工序 (i) 的效率；
- (p_{ijr})：设备 (r) 完成该工序所需时间。

但这只是**资源层面的加工时间**。

真正的一道“双设备工序”的工序完成时间还要考虑两台设备的完成关系。

例如：

[
A1:
\begin{cases}
\text{灌装机完成}\
\text{输送臂完成}
\end{cases}
]

最终：

# [ C_{A1}

\max(C_{A1}^{fill},C_{A1}^{arm})
]

如果两台设备可以独立提前抵达并独立开始，这一点就非常关键。

------

# 五、一个极容易被误读的问题：双设备工序究竟是什么

题目：

> “不考虑两类设备先后顺序与等待时间，两类设备都完成该工序对应工程量后，该工序才判定为完成。”

这里至少存在三种可能理解。

## 解释A：必须同时开始

类似：

[
S_{i,r_1}=S_{i,r_2}
]

然后：

[
C_i=\max(C_{i,r_1},C_{i,r_2})
]

这是最强同步解释。

------

## 解释B：不要求同时开始，只要都完成即可

即：

[
S_{i,r_1}\neq S_{i,r_2}
]

允许某设备提前到达、提前工作。

只要求：

[
C_i=
\max(C_{i,r_1},C_{i,r_2})
]

而且题目专门写：

> “不考虑两类设备先后顺序与等待时间”

实际上**更接近这种解释**。

因为如果题目要求同时启动，通常会明确写“同时开始”。

------

## 解释C：存在一种“联合工序”，但仍可将两个设备活动分别调度

也就是把一个工序拆成两个资源活动：

[
(i,r_1),\quad(i,r_2)
]

然后添加：

[
C_{i,r_1}\le C_i
]

[
C_{i,r_2}\le C_i
]

以及：

[
C_i\le C_{i,r_1}+M
]

[
C_i\le C_{i,r_2}+M
]

最终：

[
C_i=\max(C_{i,r_1},C_{i,r_2})
]

这个结构可能是最自然的数学表示。

**这一点以后必须在建模假设中明确。**

------

# 六、运输时间实际上比看起来更复杂

设备运输时间：

[
t_{ab}=
\left\lceil
\frac{d_{ab}}{v}
\right\rceil
]

速度统一为：

[
v=2;m/s
]

所以运输时间在数学上看起来非常简单。

但关键不在公式，而在：

> **什么时候会触发运输？**

------

## 6.1 同车间

题目明确：

> 同一车间作业不存在运输时间。

因此：

[
t(A\to A)=0
]

无论：

- A1 → A2
- A1 → A3
- A3 → A1

只要还是 A，不考虑设备搬运时间。

这实际上使“设备所在位置”可以看成一种状态变量。

------

## 6.2 跨车间

例如某台灌装机：

[
A\rightarrow B
]

必须付出：

[
t_{AB}=
\frac{1020}{2}
=510s
]

而：

# [ C\rightarrow D

\frac{520}{2}
=260s
]

所以设备调度不再只有：

[
\text{加工}\rightarrow\text{等待}\rightarrow\text{加工}
]

而是：

[
\text{加工}
\rightarrow
\text{移动}
\rightarrow
\text{加工}
]

这意味着设备存在一种**“占用但不生产”的运输状态**。

------

# 七、运输时间会产生一个非常重要的资源耦合

假设一台灌装机：

[
A1 \rightarrow B2
]

A1 完成后不能立刻执行 B2。

必须：

[
S_{B2}\ge C_{A1}+t_{AB}
]

而且在运输这段时间：

> 这台灌装机不能服务别的工序。

所以运输不是单纯的“工序之间加一个时间”。

而是：

[
\boxed{
\text{运输会消耗设备的可用时间}
}
]

因此，它可能改变**设备之间的竞争关系**。

这类“移动资源 + 运输时间”的问题确实已经被专门作为 RCPSP 的扩展研究。([科学直通车](https://www.sciencedirect.com/science/article/abs/pii/S0360835217303303?utm_source=chatgpt.com))

------

# 八、另一个很重要的问题：设备身份到底重不重要？

例如班组1有：

- 输送臂 4 台
- 清洗机 5 台
- 灌装机 5 台
- 传感机 1 台
- 抛光机 1 台

表面上，同类型设备似乎完全相同。

但一旦出现跨车间运输：

> “同一个设备从哪里来？”

就非常重要。

例如有两个灌装机：

[
F_1,\ F_2
]

可能：

[
F_1:A\rightarrow B
]

而：

[
F_2:A\rightarrow C
]

这两个选择具有不同的后续价值。

因此：

### 同类型设备虽然参数相同，但其“位置状态”不同。

这是这道题非常容易被简单模型忽略的一点。

------

# 九、设备数量约束并不是单纯“每类设备最多几台”

至少有三层资源限制。

## 第一层：数量容量

例如：

[
\sum_i x_{ir}(t)\le N_r
]

------

## 第二层：单设备不可并行

同一台具体设备：

[
M_i\cap M_j=\varnothing
]

也就是说即使某类设备还有容量，也不能让**同一编号设备**同时服务两个工序。

------

## 第三层：设备位置

设备除了：

[
busy/free
]

之外实际上还隐含：

[
location
]

所以一个设备至少有状态：

[
(\text{availability},\text{location})
]

这比传统“固定工厂机器调度”复杂。

------

# 十、车间内部与车间之间其实形成了两个不同的调度尺度

可以理解为：

### 车间内部

主要决定：

[
\text{资源冲突}
]

### 车间之间

主要决定：

[
\text{资源空间迁移}
]

于是一个很自然的层次结构出现：

[
\boxed{
\text{车间内部排程}
+
\text{跨车间资源迁移}
}
]

甚至可以进一步理解为：

> 上层决定“哪个设备去哪个车间”，下层决定“到车间后具体怎么排”。

这未必一定要做成两阶段模型，但这是一个很值得保留的建模视角。

------

# 十一、A–E五个车间不是五个完全独立项目

每个车间都有：

[
A_1\rightarrow A_2\rightarrow A_3
]

之类的内部 precedence。

但是车间之间没有显式工序依赖。

因此：

[
A,B,C,D,E
]

原则上可以**并行开展**。

这非常重要。

如果简单把五个车间串起来：

[
A\rightarrow B\rightarrow C\rightarrow D\rightarrow E
]

会直接丢掉题目的核心价值。

------

# 十二、所以“关键路径”不一定是传统关键路径

如果完全没有资源限制，可以做：

[
CP=\max{\text{各车间工序链长度}}
]

但有资源限制后：

> 最长的工序链不一定决定最终完工时间。

因为可能发生：

[
A\text{ 和 }B
]

同时需要同一种有限设备。

比如传感多功能机每个班组只有：

[
1
]

台。

那么：

- A3
- B4
- C5
- D4
- D5
- E3

都会竞争它。

于是真正的决定因素可能变成：

[
\boxed{
\text{资源瓶颈形成的“资源关键链”
}
}
]

而不是单纯的 precedence critical path。

RCPSP 文献中，这正是资源约束导致完工时间超过纯 precedence critical path 的核心原因。([项目管理协会](https://www.pmi.org/learning/library/resource-based-project-scheduling-concurrent-activities-1978?utm_source=chatgpt.com))

------

虽然此时还不应该正式算最终模型，但从数据结构已经可以看出：

但它出现在：

台。

### 灌装机

出现频率也很高。

它虽然重要，但**容量压力和位置压力可能比数量压力更加重要**。

------

### 清洗机

台。

同样属于相对充足资源。

> 哪个设备工作时间最长？

而应该问：

> 哪个设备同时具有**高工作需求 × 低数量 × 高跨车间迁移价值**？

这才是资源瓶颈识别的正确方向。

# 十四、C车间的“重复2遍”是整道题最值得单独处理的结构之一

题面不是简单：

[
C1\rightarrow C2\rightarrow C3\rightarrow C4\rightarrow C5
]

而是：

[
C1
\rightarrow C2
\rightarrow
(C3\rightarrow C4\rightarrow C5)
\rightarrow
(C3\rightarrow C4\rightarrow C5)
\rightarrow
(C3\rightarrow C4\rightarrow C5)
]

也就是说有效流程可以写成：

[
C1\to C2\to
C3^{(1)}\to C4^{(1)}\to C5^{(1)}
\to
C3^{(2)}\to C4^{(2)}\to C5^{(2)}
\to
C3^{(3)}\to C4^{(3)}\to C5^{(3)}
]

这里非常可能形成一个**循环式/重复工序链**。

------

# 十五、C车间重复过程可能造成“不同类型瓶颈”

假设 C3-C5 重复三次：

### C3

灌装机 + 输送臂

### C4

抛光机 + 清洗机

### C5

传感机

于是一个循环内部实际上不断调用：

[
F \rightarrow A \rightarrow P/C \rightarrow S
]

（灌装、输送、抛光、清洗、传感）

这意味着 C 车间本身可能形成一种“资源周期”。

尤其：

[
C5
]

反复需要唯一的传感机。

所以 C 车间不一定只是“工作量大的车间”，还可能是**稀缺资源的周期性占用源**。

------

# 十六、C重复工序还会带来一个非常重要的问题：是否允许跨循环打乱？

题面说：

> 各车间工序顺序固定，所有工序必须严格按给定顺序依次执行。

因此大概率应理解为：

[
C3^{(1)}
\rightarrow
C4^{(1)}
\rightarrow
C5^{(1)}
\rightarrow
C3^{(2)}
\rightarrow
C4^{(2)}
\rightarrow
C5^{(2)}
]

而不是：

[
C3^{(1)}
\rightarrow C3^{(2)}
\rightarrow C4^{(1)}
]

这样的重排。

但这实际上需要在正式模型里明确表达。

### 这是一个必须保留的解释点。

# 十七、两个班组加入以后，问题发生了“资源池化”

问题3：

> 班组1 + 班组2共同完成。

这里最核心的问题并不是简单把设备数量加倍。

例如：

[
N_{\text{sensor}}=1+1=2
]

但两个设备有不同的**起始空间位置**。

班组1：

- A 400
- B 620
- C 460
- D 710
- E 400

班组2：

- A 500
- B 460
- C 620
- D 680
- E 550

所以：

> 两班组的设备虽然性能相同，却不是完全等价的。

------

# 十八、因此班组本身实际上是一个“初始空间分布”

举个概念例子。

假设：

[
B\text{和}D
]

同时竞争传感机。

班组2：

[
B=460m
]

而班组1：

[
B=620m
]

那么班组2的设备天然更适合优先覆盖 B。

反过来：

[
A
]

班组1只有：

[
400m
]

班组2：

[
500m
]

所以不同车间的“初始归属优势”不同。

------

# 十九、这里甚至存在一个“小型资源定位问题”

每个设备不仅需要决定：

[
\text{什么时候工作}
]

还需要决定：

[
\text{第一次先去哪}
]

也就是说：

[
\text{initial allocation}
]

本身就是调度的一部分。

因此问题3其实可以抽象为：

[
\boxed{
\text{资源分配}
+
\text{时间调度}
+
\text{空间迁移}
}
]

------

# 二十、车间距离网络本身可能需要研究

车间之间给了完整距离：

- A-B
- A-C
- A-D
- A-E
- B-C
- B-D
- B-E
- C-D
- C-E
- D-E

表面看只需要：

[
t_{ij}=d_{ij}/2
]

但这里还存在一个值得核查的工程问题：

### 是否允许设备直接从任意车间到任意车间？

题面看起来是允许的。

因为给的是完整两两距离，而且没有路网约束。

所以一般不应该自行引入：

- 必须经过某个车间；
- 最短路；
- 路径网络；
- 运输车辆容量；

这些都没有题面依据。

------

# 二十一、但是距离矩阵仍然有结构性价值

例如：

[
C-D=520m
]

非常近；

[
B-E=720m
]

也比较近。

而：

[
D-B=1630m
]

很远。

所以很可能出现：

[
C\leftrightarrow D
]

成为一种天然的“设备共享区域”。

而：

[
B\leftrightarrow D
]

的频繁设备切换成本很高。

这可能影响车间组团策略。

------

# 二十二、一个可能被忽略的概念：调度不是唯一优化变量

本题至少有三层决策。

### 第一层：工序执行时间

什么时候做？

[
S_i,C_i
]

### 第二层：资源分配

哪一台设备做？

[
r(i)=k
]

### 第三层：空间迁移

设备从哪里来？

[
l_{k,t}
]

问题4再加第四层：

### 第四层：设备购买

买什么、多少：

[
n_{g,r}^{buy}\in\mathbb Z_{\ge0}
]

所以问题4其实是：

[
\boxed{
投资决策
+
资源配置
+
空间调度
+
时间调度
}
]

------

# 二十三、问题4不是简单的“多买设备就更快”

这是非常重要的一点。

预算是：

[
500000
]

但不同设备价格不同：

| 设备   | 单价  |
| ------ | ----- |
| 输送臂 | 50000 |
| 清洗机 | 40000 |
| 灌装机 | 35000 |
| 传感机 | 80000 |
| 抛光机 | 75000 |

所以存在一个典型：

[
\text{设备投资}
\leftrightarrow
\text{瓶颈释放}
\leftrightarrow
\text{完工时间}
]

关系。

------

# 二十四、问题4实际上存在投资的“边际收益”

例如：

> 多买一台清洗机。

它的意义不是“设备数量 +1”。

而应该问：

# [ \Delta T

T_{\text{old}}-T_{\text{new}}
]

然后比较：

[
\frac{\Delta T}{\text{设备价格}}
]

即：

> 每花 1 元，能减少多少完工时间？

这会自然引出一种很值得保留的分析：

### 设备投资边际收益曲线

例如：

[
\text{第一台传感机}
]

可能带来巨大改善；

第二台可能收益明显下降。

而某个本来就不构成瓶颈的设备，即使再买：

[
\Delta T\approx0
]

------

# 二十五、问题4很可能具有“离散相变”

假设：

[
T(N_s)
]

表示传感机数量为 (N_s) 时的最优完工时间。

那么它通常不是光滑函数，而可能是：

[
T(1)>T(2)\gg T(3)\approx T(4)
]

于是增加第一台设备很有意义，增加第二台意义巨大，之后逐渐失去效果。

这就是一个典型的**瓶颈解除临界点**。

因此问题4值得做：

> **设备数量—完工时间敏感性分析**

哪怕题面没有明确要求，也很适合作为建模论文中的结果讨论。

------

# 二十六、多个约束之间到底谁是“主控”？

这是这道题真正值得做的一层分析。

可以把约束分成四类：

### A. 工序约束

[
i\rightarrow j
]

决定：

> 什么可以先做。

------

### B. 设备容量约束

[
\text{同一设备不能同时做两个任务}
]

决定：

> 什么不能同时做。

------

### C. 空间运输约束

[
t_{ab}
]

决定：

> 设备什么时候才能到。

------

### D. 双设备完成约束

[
C_i=\max(C_{i,r_1},C_{i,r_2})
]

决定：

> 什么时刻才算真正完成。

------

这四者并不处于同一逻辑层级。

可以理解成：

[
\boxed{
\text{工序约束}
\rightarrow
\text{形成候选时间}
}
]

然后：

[
\boxed{
\text{设备资源约束}
\rightarrow
\text{筛掉冲突}
}
]

再：

[
\boxed{
\text{运输约束}
\rightarrow
\text{改变资源可用时间}
}
]

最后：

[
\boxed{
\text{联合完成约束}
\rightarrow
\text{决定工序真正结束}
}
]

当然，在具体优化模型中这些约束是同时成立的，而不是严格按这个顺序求解。

------

# 二十七、一个重要区别：有些变量是“主控变量”，有些只是“派生变量”

例如：

### 设备选择

是核心决策变量。

### 工序起始时间

也是核心决策变量。

而：

### 持续工作时间

很多情况下其实是：

[
\text{由设备种类+工程量直接计算}
]

所以不是自由变量。

------

再比如：

### 运输时间

其实也是：

[
\text{设备路线}
\rightarrow
\text{地点关系}
\rightarrow
\text{运输时间}
]

所以属于派生量。

------

这对最终建模的变量规模非常重要。

如果把所有东西都设成独立变量，模型会非常臃肿。

------

# 二十八、题目要求“表1～5”，反过来透露了模型的数据结构

尤其是：

> 表中要求设备编号、班组、起始时间、结束时间、持续工作时间、工序编号。

这意味着出题人其实已经告诉我们：

> **最终调度必须追踪到具体设备实例。**

因此最终结果不是简单：

| 工序 | 开始 | 结束 |

而是：

| 设备编号 | 班组 | 工序 | 开始 | 结束 |

这实际上暗示：

[
\boxed{
\text{resource identity is part of the solution}
}
]

不是只需要统计各类设备使用量。

------

# 二十九、问题之间的递进关系很明显

整个题目很可能有这样的设计意图：

[
\boxed{
问题1
\rightarrow
问题2
\rightarrow
问题3
\rightarrow
问题4
}
]

------

## 问题1

验证：

> 单项目 + 单资源池 + 固定工序

------

## 问题2

加入：

> 多项目 + 空间迁移

------

## 问题3

加入：

> 第二资源池 + 初始空间差异

------

## 问题4

最终加入：

> 资源扩容投资

------

因此它很可能不是四道彼此独立的问题。

而是：

[
\boxed{
\text{同一个调度模型逐层增加自由度}
}
]

这一点对建模报告结构非常重要。

------

# 三十、这意味着问题1可以成为问题2–4的基线

例如最终可以形成：

| 场景 | 资源           | 项目 | 投资    |
| ---- | -------------- | ---- | ------- |
| P1   | 班组1          | A    | 无      |
| P2   | 班组1          | A–E  | 无      |
| P3   | 班组1+2        | A–E  | 无      |
| P4   | 班组1+2+新设备 | A–E  | ≤500000 |

这样非常容易做出：

[
T_1,\ T_2,\ T_3,\ T_4
]

并分析：

[
\Delta T_{2\to3}
]

[
\Delta T_{3\to4}
]

即：

> 第二班组到底带来了多少收益？

> 500000 元投资到底带来了多少收益？

这很符合数学建模竞赛中“模型解释力”的要求。

------

# 三十一、需要特别考虑“设备等待”与“设备空闲”的区别

例如某双设备工序：

- 灌装机先完成；
- 输送臂后来完成。

那么灌装机可能：

[
C_{fill}<C_i
]

之后处于：

[
idle
]

状态。

这个时候问题是：

> 它能不能立刻去做别的工序？

题面没有禁止。

所以理论上：

[
C_{fill}<C_i
]

并不意味着灌装机必须等待整个联合工序完成后才能离开。

这是一个非常关键的建模判断。

如果允许它离开，那么资源利用率会显著提高。

------

# 三十二、但这里又出现另一个潜在解释问题

如果设备已经完成了该工序对应工程量，是否意味着它真的可以“脱离现场”？

题目从数学建模假设上没有说必须留在工序现场等待另一设备完成。

因此按照字面：

> 应倾向于允许设备在自己任务完成后释放。

但这是**必须写清楚的解释性假设**，否则评阅人可能认为你偷偷改变了题意。

------

# 三十三、“无等待时间”到底意味着什么也需要专业核查

题目说：

> 不考虑两类设备先后顺序与等待时间。

至少有两种理解：

### 解释1

设备之间不存在因另一设备没完成而产生的等待。

### 解释2

双设备工序必须同步协调，只是不额外计协调等待。

二者对结果可能有明显影响。

因此这个地方应该作为**题目语义敏感点**保留，正式建模前最好明确。

------

# 三十四、时间单位本身是个小陷阱

效率：

[
m^3/h
]

运输：

[
m,\quad m/s
]

输出：

[
s
]

所以必须统一到：

[
s
]

加工时间：

[
\frac{Q}{v}\times3600
]

而后：

[
\lceil\cdot\rceil
]

这意味着：

> 每道设备活动都应该先算真实持续时间，再取整。

而不是：

- 最后总时间算一次 ceil；
- 或者小时转秒后再统一四舍五入。

因为：

[
\lceil x\rceil+\lceil y\rceil
\neq
\lceil x+y\rceil
]

这会影响最终调度。

------

# 三十五、特别要关注“向上取整”的传播效应

看似只是 1 秒误差，但对于大量串联活动：

[
1s+1s+1s+\cdots
]

可能累积。

尤其问题4在两个方案之间可能只差几十秒时：

> 取整方式可能改变方案优劣。

所以秒级处理必须从底层数据开始贯穿到底。

------

# 三十六、参数化分析值得保留

题目数据都是固定的，但从建模研究角度：

## 参数1：运输速度

目前：

[
v=2m/s
]

可以考察：

[
v\in[1,4]
]

时的结果变化。

------

## 参数2：设备效率

例如如果某类设备效率提升：

[
+10%
]

是否比买一台新设备更值得？

------

## 参数3：设备数量

尤其：

- 传感机
- 抛光机
- 灌装机

------

## 参数4：预算

不一定永远是：

[
500000
]

可以考察：

[
B\in[0,500000]
]

得到：

[
T^*(B)
]

这实际上是一个非常漂亮的“预算—效率曲线”。

------

# 三十七、可以进一步做“瓶颈敏感性分析”

比如定义设备类型 (r) 的资源利用率：

# [ U_r

\frac{\text{实际工作时间}+\text{运输时间}}
{\text{总调度跨度}\times N_r}
]

甚至可以拆成：

[
U_r^{work}
]

和

[
U_r^{transport}
]

那么可以回答：

> 某种设备忙，是因为真的缺设备，还是因为大量时间浪费在移动？

这会比只看最终时间有解释力得多。

------

# 三十八、还应该区分“工作瓶颈”和“运输瓶颈”

这是很容易忽略的。

一种设备可能：

[
\text{工作时间很长}
]

但运输时间几乎为零。

另一种可能：

[
\text{工作不多}
]

但频繁：

[
A\rightarrow D\rightarrow B\rightarrow E
]

导致大量运输。

所以：

[
\text{瓶颈}
\neq
\text{仅仅是工作量最大}
]

而可能是：

[
\boxed{
\text{工作占用}
+
\text{移动损失}
+
\text{冲突损失}
}
]

------

# 三十九、一个非常值得保留的工程含义：设备集群化

如果几个车间距离很近：

[
C-D=520
]

那么可以形成：

> 某一类设备主要负责 C、D。

而：

[
B-E=720
]

也可能形成另一种区域耦合。

这意味着最优调度可能不是“平均分配设备”，而是：

[
\boxed{
\text{形成局部设备集群}
}
]

例如一台设备连续服务：

[
C\rightarrow D\rightarrow C
]

可能优于：

[
C\rightarrow A\rightarrow E\rightarrow D
]

即使前者某些工序稍晚开始。

------

# 四十、所以“最短加工时间”不一定等于“最短总任务时间”

例如方案 A：

[
加工时间=10000s
]

运输：

[
2000s
]

总：

[
12000s
]

方案 B：

[
加工时间=10500s
]

运输：

[
500s
]

总：

[
11000s
]

所以：

[
\boxed{
\text{局部看起来快的调度，不一定全局最优}
}
]

这应该成为整个模型设计的基本认识。

我认为后续至少可以有以下分类。

- B1
- B3

- C5

- D3
- D5
- D6

- E2

------

## 分类2：双资源工序

例如：

- A1

- C4

- D4

这两类工序的数学性质不同。

# 四十二、还可以按资源稀缺度分类

### 稀缺资源

- 传感机
- 抛光机

### 中等资源

- 输送臂

### 相对充足

- 清洗机
- 灌装机

然后观察：

> 是否可以先围绕稀缺资源建立调度骨架？

这以后可能成为启发式算法的重要依据。

但此刻**还不能把它直接定性为最终算法**。

------

# 四十三、可能存在的“局部交换”问题

假设某设备在：

[
A\rightarrow B
]

之间移动。

也许方案：

[
A\rightarrow B
]

优于：

[
A\rightarrow C\rightarrow B
]

但如果 C 正好存在该设备的大量任务，又可能相反。

所以调度优化其实具有一种：

[
\text{序列排序问题}
]

性质。

设备访问车间的顺序本身就是决策。

------

# 四十四、因此从算法分类上，它可能同时靠近几个经典问题

### 方向A：RCPSP

资源受限项目调度。

### 方向B：RCMPSP

多项目资源受限调度。

### 方向C：Multi-site RCPSP

资源跨空间站点移动。

### 方向D：Job-shop / flexible job-shop

任务与设备分配、设备冲突。

### 方向E：Routing + Scheduling

因为移动资源的路径和顺序也影响调度。

文献中确实存在将资源运输和调度同时考虑的 RCPSP 扩展。([科学直通车](https://www.sciencedirect.com/science/article/pii/S0377221722003897?utm_source=chatgpt.com))

所以以后没有必要强行说：

> “这就是一个标准 Job Shop。”

更准确的说法应该是：

> **一个具有移动资源与多资源同步需求的多项目资源约束调度问题。**

再根据最终数学表达形式选择具体术语。

------

# 四十五、算法方向目前至少应保留三条路线

现在不选择，但应该把它们都留在地图里。

## 路线1：精确优化

例如：

[
MILP / MIP
]

适合：

- 27道基础工序；
- 规模不大；
- 设备数量有限；
- 需要得到较强的最优性证明或至少可验证解。

多站点 RCPSP 本身就有基于 MILP 的研究。([科学直通车](https://www.sciencedirect.com/science/article/abs/pii/S0360835217303303?utm_source=chatgpt.com))

------

## 路线2：离散事件 / CP-SAT

尤其适合：

- precedence；
- no-overlap；
- resource capacity；
- interval variables；
- 可变设备分配；
- 联合资源任务。

------

## 路线3：启发式 / 元启发式

例如：

- 遗传算法
- 模拟退火
- 禁忌搜索
- 大邻域搜索
- 混合启发式

这类方法在 RCPSP 研究中非常常见，且多项目、多站点问题也存在专门的元启发式研究。([科学直通车](https://www.sciencedirect.com/science/article/pii/S0377221722007639?utm_source=chatgpt.com))

------

# 四十六、甚至可以存在“精确模型 + 启发式”的双层策略

规模本身并不算极端大，但如果：

- 每台设备身份显式建模；
- 每次移动都有转移；
- 双资源活动拆开；
- 问题4再加入购买变量；

组合数会迅速增长。

所以一种合理的后续策略可能是：

[
\boxed{
\text{小规模精确模型验证}
+
\text{启发式扩展}
}
]

但现在不需要决定。

------

# 四十七、一个评阅人很可能关注的问题：结果能不能验证

这道题不应该只给：

[
\text{最短时间}=xxxxx
]

最好还能证明：

### 约束满足

例如：

- 无设备冲突；
- 无工序逆序；
- 跨车间移动合法；
- 双设备均完成；
- 预算不超；
- 设备编号唯一。

### 目标合理

即：

[
T^*\le T_{\text{某个可行方案}}
]

如果使用精确求解器，还能进一步说明：

> solver 给出的最优值。

如果采用启发式：

> 则需要用下界、多个初始方案、局部搜索稳定性或与精确小规模模型比较进行可信度支撑。

------

# 四十八、一个非常值得建立的“下界”思维

任何最终方案都至少受到以下下界影响。

## 下界1：车间自身工序链长度

# [ LB_{\text{precedence}}

\max_w P_w
]

------

## 下界2：资源总工作量 / 资源数量

例如对某种设备：

# [ LB_r

\frac{\text{该设备所有必需工作总时长}}
{N_r}
]

------

## 下界3：空间运输不可避免时间

如果某些任务必须发生在不同车间，而设备必须移动，那么一定存在运输下界。

------

## 下界4：双设备工序中的慢资源

例如某工序：

[
p_1=100
]

[
p_2=200
]

那么即使完美并行：

[
C_i\ge200
]

所以：

[
\boxed{
\text{最大资源侧耗时}
}
]

本身就是局部下界。

------

# 四十九、这些下界非常适合以后用来判断“模型有没有离谱”

例如最终算出：

[
T^*=5000s
]

但理论下界已经：

[
LB=6500s
]

那么一定说明模型错了。

因此这些不一定进入正式论文主模型，但很适合作为：

> **结果校验层。**

------

# 五十、问题4还存在一个“预算约束到底是 ≤ 500000 还是 =500000”的语义点

题面：

> “追加总额 500000 元购置预算”

通常数学含义更接近：

[
\sum c_r x_r\le500000
]

而不是：

[
=500000
]

因为没有理由必须把钱花完。

但结果表又要求：

> 给出购买设备总费用。

所以应当记录：

[
Cost\le500000
]

而不是为了“用完预算”刻意购买无效设备。

这是一个非常容易产生错误的地方。

------

# 五十一、还有一个更深层的问题：购买设备属于哪个班组？

题目说：

> “为各班组补增设备”

因此应该存在：

[
x_{g,r}
]

其中：

- (g)：班组；
- (r)：设备类型。

而不是只有：

[
x_r
]

否则就无法表达：

> 为什么应该给班组1买，而不是班组2。

因为两个班组的初始空间分布不同。

所以问题4的购置变量很可能天然带有**班组维度**。

------

# 五十二、新购买设备的“出生位置”也需要确认

这是一个容易完全漏掉的问题。

如果给：

[
班组1
]

新增一台传感机：

它从哪里开始？

大概率：

[
\text{班组1驻地}
]

然后：

[
\text{班组1}\rightarrow车间
]

产生对应距离运输。

但题目没有在事实包里明确写：

> 新购设备在 00:00:00 时已经位于班组驻地。

这是一个合理但仍属于**建模假设**的地方。

------

# 五十三、类似地，原有设备的初始位置也需要明确

题目有：

[
班组1\rightarrow A/B/C/D/E
]

的距离。

所以非常自然的解释是：

> 设备初始都位于所属班组基地。

但如果附件“车间距离表”的列含义有特殊定义，也可能需要再次核对原始表头。

这一点我会列入正式求解前的“数据语义核验”。

------

# 五十四、运输是否占用班组，还是只占用设备？

题目明确的是：

> 同一台设备跨车间转移时间不可忽略。

并没有说：

> 班组在运输期间不能同时操作其他设备。

所以目前更合理的解释是：

[
\boxed{
\text{运输占用设备，而不是占用整个班组}
}
]

否则就会引入：

[
\text{班组调度约束}
]

但题面没有提供这种约束。

------

# 五十五、有没有运输车辆容量限制？

目前没有。

因此不能自行加入：

- 一辆车一次只能运一台设备；
- 多设备合运；
- 运输车辆数量有限；
- 运输路线冲突。

题面只提供：

[
distance/velocity
]

所以当前模型应该把运输理解成：

> **设备自身发生位置转换的时间成本。**

这与多站点 RCPSP 中“移动资源本身产生运输时间”的基本结构更加接近。([Springer](https://link.springer.com/article/10.1007/s10479-022-05109-0?utm_source=chatgpt.com))

------

# 五十六、一个很隐蔽的数学问题：设备迁移是否可以在工序未完成前规划？

当然可以提前知道。

但不能提前执行。

所以：

[
\text{planning}
\neq
\text{physical execution}
]

这意味着调度模型需要保证：

[
S_j\ge C_i+t_{loc(i),loc(j)}
]

而不能仅仅根据：

[
\text{预计未来需要该设备}
]

就把运输算进去。

------

# 五十七、设备可能出现“提前到达然后等待”的状态

例如：

[
A\rightarrow B
]

设备在：

[
5000s
]

到达 B，但 B2 要：

[
5300s
]

才能开始。

那么：

[
300s
]

是：

> 到达后的设备空闲等待。

这与“运输时间”不同。

因此设备状态应该至少区分：

[
work
]

[
transport
]

[
idle
]

------

# 五十八、进一步会产生资源利用率的三分解

最终很适合分析：

# [ T_{\text{total}}

T_{\text{work}}
+
T_{\text{transport}}
+
T_{\text{idle}}
]

这里并不是简单加法，因为多个设备可以同时工作，但对于单台设备生命周期可以这样统计。

然后可以问：

> 最优方案到底把时间浪费在哪里？

这是工程解释里非常有价值的一层。

------

# 五十九、可能需要考虑的数学结构：非连续时间调度

虽然最终精确到秒，但题目本身并没有规定：

> 所有工序只能在整数小时开始。

所以最自然的时间域是：

[
t\in\mathbb R_{\ge0}
]

但持续时间为整数秒。

也就是说：

[
S_i,C_i\in\mathbb Z_{\ge0}
]

也可能直接建为秒级离散时间模型。

不过：

> **不建议现在就默认采用逐秒时间索引。**

因为那会产生大量变量。

连续时间事件型模型可能更自然。

------

# 六十、还要留意“工序可以中断吗？”

题目没有明确写：

> 工序一旦开始必须连续完成。

但“持续工作时间”“设备完成工程量”以及普通制造语境下，通常默认：

[
\boxed{\text{不可抢占}}
]

即：

[
[S_i,C_i]
]

必须连续占用对应设备。

这个假设应该保留。

否则可以把：

[
500m^3
]

拆成多个片段进行加工，会完全改变问题性质。

------

# 六十一、设备效率是否允许按比例分摊工程量？

题目写：

> 每道工序所需设备及作业效率

以及：

> 同一时刻每台设备只能服务一道工序。

因此目前更合理的解释是：

> 一道工序需要一台对应类型的设备完成。

而不是：

> 同类设备可以同时分摊同一工序。

否则就会从：

[
\text{设备选择}
]

变成：

[
\text{连续产能分配}
]

这是另一个模型。

所以不能自行允许多台同类型设备并行分摊同一道工序，除非原附件另有说明。

------

# 六十二、这也是一个非常值得核查的专业语义点

比如：

> A1需要300 m³，灌装机效率200 m³/h。

是否意味着：

[
1.5h
]

由一台灌装机完成；

还是可以：

[
2\text{台}
]

共同工作，各完成150 m³？

题目“同一时刻每台设备只能服务一道工序”更倾向于前者——**设备可以并行服务不同工序，而非共同切分一道工序**。

但正式论文需要明确写成假设。

------

# 六十三、从评阅人角度，真正会检查的不是“公式漂亮”，而是这几个东西

## 1. 是否完整体现设备冲突？

如果只给每种设备一个变量，而不追踪设备数量，很危险。

------

## 2. 是否真的考虑跨车间运输？

如果只是给每个车间加一个固定运输时间，也很危险。

------

## 3. 是否处理双设备工序？

这是这道题的特色之一。

------

## 4. 是否处理 C3–C5 三轮？

漏一次就会直接改变数据规模和总工作量。

------

## 5. 问题4是否真的“联合优化购买和调度”？

不能先随便决定买什么，再调度，然后说“综合优化”。

------

# 六十四、从出题人角度，为什么要给两个班组？

并不仅仅是：

[
N\rightarrow2N
]

而是故意引入：

> **资源池之间的空间不对称性。**

因为：

班组1靠近：

- A
- C
- E

班组2相对靠近：

- B

同时 D 两者都差不多。

所以出题人很可能希望看到：

> **设备不是平均分配，而是根据车间空间关系进行调度。**

------

# 六十五、距离数据与效率数据结合以后，会出现“去远车间是否值得”的决策

例如某设备：

[
加工时间=400s
]

但远距离运输：

[
1000m/2=500s
]

那么：

[
\text{运输甚至可能比工作时间更长}
]

这意味着：

[
\boxed{
\text{一次任务是否值得跨车间调用某设备}
}
]

本身就有重要的经济 / 调度含义。

------

# 六十六、因此“资源共享”并不总是好事

通常：

> 更多共享设备 → 更高灵活性。

但如果共享产生：

[
\text{大量迁移}
]

那么：

[
\text{资源共享收益}
<
\text{运输损失}
]

也可能发生。

所以问题3加入班组2以后，理论上并不能仅凭：

[
\text{设备数量翻倍}
]

判断完工时间会怎样。

------

# 六十七、问题3特别适合进行一个反事实分析

以后可以比较：

### 场景A

两个班组完全独立。

### 场景B

两个班组设备共享。

### 场景C

设备不得跨班组。

虽然题面可能只要求 B，但做这种分析能够帮助解释：

> 第二班组的价值来自“新增资源”还是来自“资源空间覆盖”。

------

# 六十八、问题4则可以继续研究“买给谁”

例如：

[
x_{1,\text{sensor}}
]

和：

[
x_{2,\text{sensor}}
]

同样价格。

但是：

[
\Delta T_{1}
\neq
\Delta T_{2}
]

因为它们的初始位置不同。

所以问题4甚至可能出现：

> **同一种设备，买给不同班组，价值不同。**

这可能是整个题里最有建模味道的地方之一。

------

# 六十九、可能的“主导因素”需要用结果而不是先验判断

虽然目前看：

> 传感机 / 抛光机数量少。

但不能现在直接宣布：

[
\text{sensor = bottleneck}
]

因为真正瓶颈还受到：

- 工序出现次数；
- 工序持续时间；
- 车间并发结构；
- 运输距离；
- 两设备同步；
- 其他资源冲突；

共同影响。

因此正确态度是：

> 目前它们是**候选瓶颈**，不是已经证明的瓶颈。

------

# 七十、同理，不能先认定“运输是主要成本”

虽然距离较大，但如果设备大部分时间留在同一车间：

[
T_{transport}\ll T_{work}
]

运输就不是主控。

反过来，如果设备频繁在几个车间之间切换：

[
T_{transport}
\approx
T_{work}
]

甚至可能超过它。

所以：

[
\text{transport bottleneck}
]

同样需要求解后验证。

------

# 七十一、需要保留的专业知识核查清单

正式开始建模前，我认为最值得核查的是：

### 1. RCPSP

确认资源约束、precedence、makespan 的标准定义及常见建模形式。([科学直通车](https://www.sciencedirect.com/science/article/pii/S0377221721003982?utm_source=chatgpt.com))

### 2. Multi-project RCPSP

特别是多个项目共享资源池的情况。([科学直通车](https://www.sciencedirect.com/science/article/pii/S0377221722007639?utm_source=chatgpt.com))

### 3. Multi-site RCPSP

重点核查：

- mobile resources；
- transportation time；
- site-dependent scheduling。([科学直通车](https://www.sciencedirect.com/science/article/abs/pii/S0360835217303303?utm_source=chatgpt.com))

### 4. Resource-constrained scheduling with transfer times

用于判断“资源移动”到底应该建成哪一种时间关系。([科学直通车](https://www.sciencedirect.com/science/article/pii/S0377221722003897?utm_source=chatgpt.com))

### 5. Multi-resource scheduling

即一个 activity 同时需要多个资源的模型。已有经典的 multi-resource scheduling 文献脉络。([Wiley Online Library](https://onlinelibrary.wiley.com/doi/10.1002/9780470611050.ch9?utm_source=chatgpt.com))

### 6. Job-shop / Flexible Job-shop

用于对照“机器选择 + 设备冲突”的标准模型，而不一定直接套用。

### 7. No-wait / synchronized resource interpretation

主要用于确认双设备工序究竟应该采用：

[
S_1=S_2
]

还是：

[
C_i=\max(C_1,C_2)
]

这一语义差异。

------

# 七十二、目前值得保留的模型方向，不应过早删除

我会至少保留下面五个候选框架。

| 候选方向              | 核心思想           | 当前评价          |
| --------------------- | ------------------ | ----------------- |
| RCPSP                 | 项目 + 资源约束    | 基础母模型        |
| Multi-project RCPSP   | 五车间作为多个项目 | 很适合问题2–4     |
| Multi-site RCPSP      | 加入资源空间迁移   | 非常贴近题目      |
| Job/Flexible Job Shop | 设备身份与设备冲突 | 适合表达资源分配  |
| Routing + Scheduling  | 同时看设备移动顺序 | 问题2–4很值得保留 |

还有一个额外方向：

| 方向            | 用途                                 |
| --------------- | ------------------------------------ |
| 两层/分解式模型 | 上层决定车间资源分布，下层做时间调度 |

现在完全没有必要选出唯一答案。

------

# 七十三、我认为目前最核心的“统一视角”

如果暂时完全不写公式，这道题可以先抽象成：

[
\boxed{
\text{多个固定工艺链}
+
\text{有限设备资源}
+
\text{移动设备}
+
\text{设备空间状态}
+
\text{多设备联合工序}
+
\text{循环工序}
+
\text{离散投资}
}
]

然后最终目标统一是：

[
\boxed{
\min ; C_{\max}
}
]

其中：

# [ C_{\max}

\max_{\text{所有车间}}
{\text{最终工序完成时间}}
]

问题1–4只是逐渐扩大决策空间。

------

# 七十四、从建模设计角度，我会把数据结构先拆成六层

这不是最终模型，只是为了防止后面概念混在一起。

### 层1：工艺网络

[
\mathcal P
]

回答：

> 什么必须先于什么？

### 层2：任务需求

[
Q_i,\ R_i,\ p_{ir}
]

回答：

> 一道工序需要什么设备、多久？

### 层3：设备实例

[
k=1,2,\ldots,N_r
]

回答：

> 到底是哪一台设备？

### 层4：空间状态

[
L_k(t)
]

回答：

> 设备在哪？

### 层5：时间状态

[
S_i,\ C_i
]

回答：

> 什么时候做？

### 层6：投资

[
x_{g,r}
]

回答：

> 要不要增加设备？

这种分层对后续建模非常重要。

------

# 七十五、最后：**最容易整体漏掉的东西**

这一节我认为最重要。

## 1. 把“设备类型”当成“设备实例”

这是最危险的。

因为跨车间运输要求追踪：

[
\boxed{\text{设备编号}}
]

同类型设备并不意味着状态完全相同。

------

## 2. 忘记运输会占用设备

不是：

[
\text{加工结束}\rightarrow\text{下一处立刻可用}
]

而是：

[
\text{加工}
\rightarrow
\boxed{\text{运输}}
\rightarrow
\text{下一车间可用}
]

运输期间设备不能干别的。

------

## 3. 把五个车间串成一个项目

题目没有说：

[
A\rightarrow B\rightarrow C\rightarrow D\rightarrow E
]

它们原则上可以并行。

------

## 4. 把双设备工序当成普通单设备工序

例如 A1 不是：

[
p=\frac{300}{200}
]

简单结束。

它必须同时满足：

[
\text{灌装机完成}
]

和

[
\text{输送臂完成}
]

这是题目的特色约束之一。

------

## 5. 忘掉“双设备完成后”，但过度强制“同时开始”

题目明确要求的是：

> 两类设备都完成后工序完成。

并没有明确写：

> 两台设备必须同时启动。

因此这两个概念不能混为一谈。

------

## 6. 把“设备完成自己的工作”与“工序完成”混为一谈

双资源工序尤其如此：

[
C_{device}<C_{operation}
]

完全可能成立。

------

## 7. 忘掉 C3–C5 是三轮，而不是一轮

这会直接让：

- 工作量；
- 资源需求；
- 总工期；

全部发生系统性错误。

------

## 8. 忘记 C3–C5 三轮之间也有顺序

很可能是：

[
C3^{(1)}
\rightarrow C4^{(1)}
\rightarrow C5^{(1)}
\rightarrow C3^{(2)}
\rightarrow\cdots
]

而不是三个循环自由重排。

------

## 9. 只按工作量找瓶颈，不看运输

真正的瓶颈可能是：

[
\text{高工作量}
+
\text{高争用}
+
\text{高运输}
]

------

## 10. 把班组2理解为“班组1复制品”

参数虽然相同，但：

[
d_{1,w}\neq d_{2,w}
]

所以两个班组的设备并不具有完全相同的空间价值。

------

## 11. 问题4只优化“买什么”，不联合优化调度

正确的问题其实是：

[
\boxed{
\text{买什么}
+
\text{买给谁}
+
\text{什么时候用}
+
\text{去哪}
}
]

四者共同决定最终工期。

------

## 12. 强行把500000元花完

目标是：

[
\min C_{\max}
]

不是：

[
\max \text{购买金额}
]

所以应优先考虑：

[
Cost\le500000
]

而不是默认：

[
Cost=500000
]

------

## 13. 忘记新设备的初始位置

新增设备：

[
\text{属于哪个班组}
]

意味着其初始空间位置也不同。

这会直接影响问题4。

------

## 14. 把运输理解成“运输车辆问题”

目前题目并没有给：

- 运输车；
- 运输车数量；
- 装载能力。

所以目前更自然的是：

[
\boxed{\text{设备自身移动}}
]

而不是另建 VRP。

------

## 15. 直接选择算法，而没有先确定语义

这道题最容易出现的错误其实不是：

> “算法不够高级。”

而是：

> **对题意做了一个未经检查的默认解释。**

尤其是：

- 双设备是否必须同步开始；
- 设备完成自身工作后能否释放；
- C3–C5 重复逻辑；
- 新购设备初始位置；
- 原设备初始位置；
- 同一种设备能否共同承担一道工序；

这些如果没先钉死，后面的 MILP、遗传算法、CP-SAT 全都有可能是在“很认真地解一个错误的问题”。

------

# 目前形成的整体认识

我认为此时最合适的定位不是“这是一道 Job Shop 题”，甚至也不应该急着说“这是 RCPSP”。

更准确的方向性认识是：

[
\boxed{
\textbf{以资源受限多项目调度为母体，}
}
]

向两侧扩展：

[
\boxed{
\text{空间移动资源}
\quad+\quad
\text{多资源联合工序}
}
]

再在问题4增加：

[
\boxed{
\text{离散设备投资决策}
}
]

所以整个问题可以暂时看成一棵模型树：

[
\text{基础 RCPSP}
]

[
\downarrow
