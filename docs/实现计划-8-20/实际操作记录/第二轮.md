# 多工序协同作业问题｜方向性认知地图（收敛版）

> 定位：这是**建模前的主线地图**，不是最终模型。
> 核心原则：先统一题意口径，再决定数学表达；论文只保留**一个主建模主线**，其他方案用于验证/对照。

------

## 1. 显式任务与交付物

### 1.1 四个子问题

- 🔴 **问题1**：班组1独立完成 A 车间，最小完工时间 + 表1逐设备调度。
- 🔴 **问题2**：班组1完成 A–E，最小总完工时间 + 表2。
- 🔴 **问题3**：班组1+2共同完成 A–E，最小总完工时间 + 表3，增加班组字段。
- 🔴 **问题4**：预算 ≤500000 元，联合决定购置方案与调度策略，使总完工时间最小；表4调度、表5购置台数与总费用。

### 1.2 统一输出目标

- 🔴 四问本质都以 **makespan（最终完工时间）最小** 为核心。
- 🔴 表格必须落到**具体设备编号、班组、工序、起止时间**，说明设备实例本身是结果的一部分。
- 🟡 最终应给出四问结果之间的比较，而不仅是四个孤立答案。

------

## 2. 关键词与结构

- 🔴 **固定工序顺序**：车间内部 precedence，不是自由排序问题。
- 🔴 **有限设备数量 + 单设备不可并行**：典型资源容量/冲突约束。
- 🔴 **跨车间运输有时间、同车间为0**：资源具有空间状态。
- 🔴 **双设备工序**：属于联合资源需求，完成判据不是单设备完成。
- 🔴 **C3–C5 重复三遍**：形成显式循环链，是题目结构的特殊点。
- 🟡 **问题1→4逐层增加资源、空间、投资自由度**：明显具有同一模型递进设计。

------

## 3. 物理·数学机制

### 3.1 基本加工机制

- 🔴 每个“设备—工序”有确定加工时长：工程量 ÷ 设备效率，并统一转为秒后**向上取整**。
- 🔴 工序 precedence 与设备资源冲突同时存在。
- 🔴 工序不可被随意重排；默认采用**不可抢占、连续加工**口径。

### 3.2 移动资源机制

- 🔴 设备状态不仅有 `busy/free`，还隐含 `location`。
- 🔴 跨车间切换必须满足：前一任务结束 + 运输时间后，设备才能在下一车间可用。
- 🟡 运输期间设备不能执行其他任务，应视作设备被占用但不生产的状态。

### 3.3 双设备工序机制

- 🔴 工序完成由所有所需设备完成共同决定，可抽象为：
  [
  C_i=\max(C_{i,r_1},C_{i,r_2})
  ]
- 🟡 某设备完成自身工程量后是否立即释放，是影响最优性的关键细节。

### 3.4 C车间机制

- 🔴 应明确展开为：
  [
  C1\rightarrow C2\rightarrow(C3\rightarrow C4\rightarrow C5)^3
  ]
- 🔴 三轮应保持题定流程顺序，不能把三轮当成可自由重排任务。

------

## 4. 边界条件与口径歧义（含裁决倾向）

| 优先级 | 问题                               | 当前裁决倾向                                                 |
| ------ | ---------------------------------- | ------------------------------------------------------------ |
| 🔴      | 双设备是否必须同时开始？           | **不强制同时开始**；只要求两者都完成后工序结束。             |
| 🔴      | 设备先完成后能否释放？             | **倾向允许立即释放**，否则题面“完成后”与资源重复利用逻辑不自然。 |
| 🔴      | 同类多台设备能否共同分摊一道工序？ | **不允许**；默认一道所需资源类型由一台设备承担。             |
| 🔴      | 跨车间运输是否占用整个班组？       | **不占班组，只占具体设备**。                                 |
| 🔴      | 初始位置                           | **倾向认为所有原有/新增设备初始位于所属班组驻地**。          |
| 🟡      | 新购设备何时可用                   | 倾向于 00:00 起即拥有，并支付其前往首个车间的运输时间。      |
| ⚪      | “不考虑等待时间”是否等价于同步启动 | **不建议如此解释**；这是最重要的备选语义风险。               |

> 🔴 这些口径必须在正式论文“模型假设”中明确，否则不同解释会直接导致不同答案。

------

## 5. 约束间关系：谁主控、谁是判据、谁参与比较

### 5.1 主控约束

- 🔴 **工序 precedence**：决定任务何时“有资格”开始。
- 🔴 **设备容量/冲突**：决定哪些任务不能同时执行。
- 🔴 **设备运输**：决定具体设备何时具备下一车间的可用条件。

### 5.2 完成判据

- 🔴 **双设备联合完成**不是资源排序约束，而是“工序何时真正完成”的判据。
- 🔴 最终目标由所有车间最后一道工序的完成时间共同决定。

### 5.3 参与比较但不是独立目标

- 🟡 设备工作时间、运输时间、等待时间：用于解释瓶颈和方案差异，不应替代 makespan 成为主目标。
- 🟡 设备利用率、预算使用率：属于结果分析指标。
- 🟡 资源总工作量/理论关键路径：适合做下界和结果校验。

------

## 6. 小问间依赖与递进

- 🔴 **问题1是基础验证层**：单车间、单班组，检验 precedence + 多资源逻辑。
- 🔴 **问题2加入空间迁移**：多车间共享设备，真正进入移动资源调度。
- 🔴 **问题3加入第二资源池**：资源增加但初始空间位置不同，出现跨班组资源分配。
- 🔴 **问题4加入离散投资**：在问题3基础上增加设备数量决策。
- 🟡 因此四问最好共享一个统一母模型，只逐问开放不同变量/约束。
- 🟡 可以形成 (T_1,T_2,T_3,T_4) 与 (\Delta T_{2\to3},\Delta T_{3\to4}) 的递进解释。

------

## 7. 必须做的参数化·优化·敏感性

- 🔴 **核心优化始终是最小 makespan**：
  [
  \min C_{\max}
  ]
- 🔴 问题4必须将**购置台数 × 班组 × 调度**联合起来优化，而不是先买后排。
- 🟡 **候选瓶颈分析**：传感机、抛光机等稀缺资源优先检查，但不能先验认定为瓶颈。
- 🟡 至少做一次**资源数量敏感性**：设备增加1台对 (C_{\max}) 的边际改善。
- 🟡 至少做一次**运输敏感性**：运输时间变化对最优方案的影响。
- 🟡 问题4可进一步画：
  [
  B\rightarrow T^*(B)
  ]
  的预算—工期关系，判断500000是否处于投资临界点。

------

## 8. 容易忽略的工程含义

- 🔴 **设备类型相同 ≠ 设备状态相同**：跨车间运输使“设备编号/当前位置”真正有意义。
- 🔴 **运输成本可能改变资源分配**：最快加工设备未必应服务当前任务。
- 🟡 可能形成“C–D”“B–E”等局部设备集群，减少长距离搬运。
- 🟡 应区分：
  [
  \text{加工占用}+\text{运输占用}+\text{等待}
  ]
  而不是只看设备工作时长。
- 🟡 第二班组的价值不仅是设备数量增加，还来自**空间覆盖改善**。
- 🟡 问题4的“买给谁”本身可能成为关键决策。

------

# 9. 建议的建模方法族

## 🟢 主方向：移动资源扩展的多项目 RCPSP + MILP / CP-SAT 表达

- 🔴 **主线建议**：把 A–E 视为多个并行项目；设备是可重复使用资源；设备具有当前位置；跨车间形成 sequence-dependent transfer time；双设备工序拆成联合资源活动。
- 🔴 目标统一为：
  [
  \min C_{\max}
  ]
- 🔴 问题4在同一框架中加入整数购置变量与预算约束。
- 🟡 这种方向最容易同时统一表达：precedence、capacity、设备身份、运输、班组、采购。

### 不兼容点

- 🔴 **主模型采用“异步双设备完成”时，不能再同时把“双设备必须同步开始”作为正式约束。**
- 🔴 **主模型采用“设备可立即释放”时，不能同时把设备强制锁定到整道联合工序结束。**

------

## 🟡 对照候选A：Flexible Job-Shop / Job-Shop 风格

适合强调：

- 设备选择；
- 单机冲突；
- 工序—机器分配。

但其天然表达“多车间移动资源”的能力较弱。

### 不兼容

- ⚪ 若作为主线，就不能再把完整的移动资源空间状态当成一个独立子模型而不作统一耦合；否则会变成两个模型拼接。

------

## 🟡 对照候选B：两层分解模型

上层：

[
\text{设备去哪些车间/形成何种资源布局}
]

下层：

[
\text{具体时间调度}
]

优点是解释性强、适合启发式设计。

### 不兼容

- ⚪ 若作为主线，就不应再把所有资源分配与时间决策完全扁平化成一个“纯直接调度模型”来宣称同一建模逻辑；二者属于不同求解架构。

> **建议论文只选上面的 🟢 主方向作为正式主模型；Job-Shop 与两层分解最多作为求解/验证上的对照，不要并列成三个“主模型”。**

------

# 10. 待核查的专业知识与文献线索

- 🔴 **RCPSP / Multi-project RCPSP**：核查 precedence、renewable resource、makespan 的标准定义与 MILP/CP 建模。
- 🔴 **Multi-site RCPSP / mobile resource scheduling**：重点核查资源转移时间如何进入 precedence/disjunctive constraints。相关研究已明确讨论多站点资源移动与运输时间。
- 🟡 **Multi-resource / synchronized activity scheduling**：用于支撑双设备联合工序的数学表达。
- 🟡 **Flexible Job-Shop**：用于比较设备选择与资源冲突建模方式。
- 🟡 **大邻域搜索/元启发式**：若精确模型求解规模或问题4出现困难，可作为第二求解器路线。
- ⚪ **双设备“等待时间”语义**：这是更值得核查题面与竞赛官方说明，而不是仅靠经典文献自行推断的部分。

# 如果只把 5–8 个探索点写进论文

### **必须体现**

1. 🔴 **统一的多车间资源受限调度主模型**：这是整题主线。
2. 🔴 **设备实例 + 跨车间运输**：否则题目的核心特色基本丢失。
3. 🔴 **双设备联合完成机制**：必须明确“工序完成”与“设备完成”的区别。
4. 🔴 **C3–C5 三轮重复链**：这是容易整体出错的特殊结构。
5. 🔴 **问题1→4的递进关系**：同一模型逐层扩展，体现模型统一性。
6. 🔴 **问题4的购买—调度联合优化**：不能只做采购或只做排程。
7. 🟡 **瓶颈/敏感性分析**：说明为什么某些资源值得扩充。
8. 🟡 **方案的工程解释**：运输与空间布局为什么改变最优调度。

### **会冲淡重心的内容**

- ⚪ 同时把 **RCPSP、Job-Shop、遗传算法、MILP、CP-SAT、两层分解** 都写成独立“核心模型”。
- ⚪ 大量讨论并未实际采用的理论变体，例如 VRP、运输车辆容量、允许任务抢占、同工序多设备分摊。
- ⚪ 把“设备利用率、运输占比、预算利用率”等分析指标写成与 makespan 平行的第二目标。
- ⚪ 过多参数扰动实验；本题更需要**解释主模型和验证关键决策**，而不是做成参数研究论文。

------

## 最终收敛判断

这道题目前最值得锁定的认知不是“它属于哪一种经典调度题”，而是：

[
\boxed{
\text{多项目工序网络}
+
\text{有限设备资源}
+
\text{移动资源}
+
\text{多资源联合工序}
+
\text{离散设备投资}
}
]

**主线最好收敛到一个统一的“移动资源 RCPSP”框架，再用问题1–4逐级放开资源与投资决策。**
这样既能解释题目全部结构，又不会因为尝试太多模型而把论文重心冲散。
