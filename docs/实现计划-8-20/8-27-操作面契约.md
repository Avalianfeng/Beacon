# 操作面契约（P0 · D-002）

> **给谁**：人，或外部 agent。新题开工先读本篇；提示词与原则细节跟指针走，不在本篇复述。
> **写法**：只写**现在就能做**的命令与产物。缺命令、缺状态机、缺统一入口的能力标 **【待实现】**，不在这里发明做法。
> **决策**：D-002 —— 默认分阶段驱动；LangGraph `start`/`supervise` 是可选执行器，不是唯一入口。
> **父计划**：[8-27-流程介入面计划](8-27-流程介入面计划.md)

命令前缀（仓库根目录）：

```text
.venv\Scripts\python.exe -m math_agent.cli
.venv\Scripts\python.exe scripts\<脚本>.py
```

下文写作 `math-agent …` / `python scripts/…`。

## 0. 全局约定

### 0.1 目录

```text
problems/<题号>/
  source/                 原始题面+附件（归档后视为不可变）
  source/reference/       参考实现（S6 登记后才有）
  problem.md              题面事实层
  problem.json            spec（解释层，人可修）
  brief.json              方向约束（S4 之后才有）
  exploration.md          认知地图（人侧，不注入流水线）
  data_profile.md         数据探查（C 题有；无命令）
  逐问清点.md              清点表（C 题有；无命令）
  tables.json             交付表声明（S6 tables 需要）
  reference.json          参考实现入口登记（S6 add 写入）
runs/<run>/               某次执行产物（流水线或 reference）
```

题号：字母/数字/连字符，如 `mcm51-c`。

### 0.2 阶段状态

**【待实现】** 没有统一的阶段状态文件，也没有「当前停在第几棒」的命令。

当前可观察的状态 = **产物在不在磁盘上** +（若走了流水线）`math-agent status --out <run>`。
交棒方式 = 写好产物，下一个执行者读进入条件。

### 0.3 谁可以改什么

| 资产 | 谁改 | 改完怎么继续 |
|---|---|---|
| `source/` 已归档文件 | 原则上不改；必须改则重新 `import --force` 并重算哈希 | 从 S0 再走预检 |
| `problem.json` 解释层（title/questions/feasibility） | 人 | 再 `problem show` + `run --dry-run` |
| `exploration.md` / 清点 / 对撞记录 | 人主持，外部模型可写草稿 | 进入 S4 前人确认 |
| `brief.json` | 人（可让模型起草） | 必跑 `brief check`；方向错了**回 S4 改 brief**，不在体系内投票（原则 8） |
| 求解脚本 | 人 / 解题 agent | 独立复核通过后再 `reference add` |
| 流水线 checkpoint | `pause` / `recover` / `restart` / `resume` | 见 S9 |

### 0.4 失败怎么交棒（现有）

| 情况 | 现有动作 |
|---|---|
| 方向/口径错 | 改 `brief.json` → `brief check` → 从 S5 或 S6 重来；不在节点里投票 |
| 求解脚本错 | 修脚本 → 重跑参考实现 → 再登记；已 `reference add` 的用 `--force` |
| 论文数字无溯源 | `check_paper_numbers.py --strict` 未过 → 改论文或补证据，不放行 |
| 流水线节点失败 | `status` / `watch` 看 `failure.json`；可 `recover` 或 `restart --from coder`（仅门禁停机态） |
| 人审停 | `resume --approve/--no-approve` 或 `supervise-resume` |
| 能力不可达 | `problem.json` 的 `feasibility.blockers` 非空 → `run --dry-run` 拒绝启动 |

**【待实现】** 跨阶段「回退到 Sx」的机械命令（现在靠人记住从哪重来）。

### 0.5 本契约不覆盖

- 前端 / Web 入库（10 暂缓）
- `brief extract`（方向已定、未实现）
- RAG `ingest`（原则 4：当前不启用）
- `bench`（回归基准，不是做题路径）
- 图体系重设计、M2/M3/pilot 自动解冻

## 阶段总表

| 阶段 | 名称 | 默认执行者 | 命令是否齐 |
|---|---|---|---|
| S0 | 导入 | 人 | 有 CLI（含 `stage`） |
| S1 | 数据探查 | 人 / 外部 agent | **【待实现】** 无命令；写 md |
| S2 | 探索（开放探索 → 消化 → 对撞 → 清点） | 人主持 + 外部强模型 | 无 CLI（协议在 playbook） |
| S3 | 方向收敛 | 人 | `brief init/check`；`dialogue` 仅 TTY |
| S4 | 启动前预检 | 人 / agent | `run --dry-run`（落盘 preflight.json） |
| S5 | 求解验证 | 人 / 解题 agent | `reference verify` v0；写脚本仍靠人/agent |
| S6 | 登记装配 | 人 / agent | `reference add/run/tables/paper` |
| S7 | 评审 | 人 / 评审 agent | `review-check` 包装脚本 |
| S8 | 人审与提交 | 人 | 论文在磁盘上即可；流水线才有 `resume --approve` |
| S9 | 可选流水线 | 监督进程 | `start`/`supervise`/`pause`/`watch`/`status` |

默认新题路径：**S0→S1→S2→S3→S4→S5→S6→S7→S8**。S9 可选，不挡交付。

## S0 导入

- **目标**：题面与附件进入 `problems/<题号>/`，带哈希。
- **进入条件**：手里有题面文件（md/txt/pdf/docx）和可选附件目录。
- **输入**：题面文件；`--attachments` 目录（可选）。
- **命令**：

```text
math-agent problem import <题面文件> --problem-id <题号> [--attachments <附件目录>] [--force]
math-agent problem show <题号>
math-agent problem stage <题号> [--json] [--runs <runs根>]
```

- **产出**：`problems/<题号>/source/`（含 sha256 清单）、`problem.md`、`problem.json` 骨架。
- **人必须补的**：`problem.json` 的 `title` / `background` / `questions` / `feasibility`。import **不做 AI 起草**。
- **完成判据**：`problem show` 能读出题号；`questions` 非空；`feasibility.blockers` 已填（无可达障碍则保持空）。
- **介入点**：解释层随时可改 json；改完再 `show`。原始 `source/` 不要手改。
- **失败**：题号已存在且未 `--force` → 换题号或确认覆盖。
- **【待实现】** `brief extract`（入口 B：题目直入体系再提取 brief）。`brief init` 按小问预填骨架——00 设计写了，**当前代码只写空八字段**。

C 题对照：`problems/mcm51-c/{problem.md,problem.json,source/}`。

## S1 数据探查

- **目标**：在选方法之前，先把附件变成可对撞的证据（列、缺失、量纲、异常、可当锚点的读数）。
- **进入条件**：S0 完成，附件在 `source/`。
- **输入**：`problem.md` + `source/` 下表格/数据文件。
- **命令**：无。C 题是人/agent 读 Excel 后写成 `data_profile.md`。
- **产出（约定路径，无强制校验）**：`problems/<题号>/data_profile.md`。
- **完成判据**：人认为后续对撞能拿这份文件当「数据证据包」；关键交付表若有指定单元格，应记下可读锚点（C 题：表 1.1 的 B 同刻读数）。
- **介入点**：人可改、可让另一 agent 重做；不注入 brief、不注入流水线。
- **失败**：探查不足就进 S2 → 对撞容易变成「方法名 PK」。发现探查错了，停在本阶段重写 md，不必重 import。
- **【待实现】** 数据探查命令或固定 schema（现在只有一篇 md 的惯例）。

C 题对照：`problems/mcm51-c/data_profile.md`。经验：先 EDA 再对撞（docs/18 §11.1）。

## S2 探索（方向生产 · 协议层）

- **目标**：扩大认知空间，再收敛成地图与清点表。**不解题、不写论文、不注入流水线。**
- **进入条件**：S0 完成；有附件题建议 S1 先做完。
- **输入**：`problem.md`、附件、`data_profile.md`（若有）。
- **命令**：无。协议与提示词：[brief-playbook](../brief-playbook.md) 阶段 1→1.5→2→3。口径防线 v3 必守（假设分级、弱依据禁令、题面信号清单、备选口径）。
- **产出**：

| 文件 | 作用 |
|---|---|
| `problems/<题号>/exploration.md` | 认知地图（消化后，不是第一轮思考流） |
| `problems/<题号>/逐问清点.md` | 逐问 checklist / 问题分解表 |
| 对撞记录 | C 题例：`口径风险-第二读者.md`；路径未强制 |

- **完成判据**：人主持过 diff；互不兼容项已标出；「最容易整体漏掉的东西」有一节；**没有**把官方答案写进这些文件（原则 1）。
- **介入点**：人决定再开一家模型、或指定角色（出题人/评阅人/怀疑者）。外部 agent 只交草稿，人拍板。
- **失败**：探索变成「一次性完美方向」→ 停，按 playbook 重跑探索，不要直接填 brief。
- **【待实现】** 探索/对撞/清点的机械入口；多模型对撞的编排器。

C 题对照：`exploration.md`、`逐问清点.md`、`口径风险-第二读者.md`。

## S3 方向收敛（brief）

- **目标**：把已拍板的方向压成可注入的 `brief.json`。
- **进入条件**：S2 产物人已确认。
- **输入**：认知地图、清点表、`problem.json`。
- **命令**：

```text
math-agent brief init --problem problems/<题号>/problem.json --out problems/<题号>/brief.json
math-agent brief check --brief problems/<题号>/brief.json
```

- **`brief dialogue`**：TTY 逐字段问答，可 `--assist` 让 LLM 起草。适合人坐在终端；**外部 agent 不要走这条**（要交互 stdin）。
- **产出**：`problems/<题号>/brief.json`（八字段 + 可有 `background_knowledge` / `redline_rules`）。
- **完成判据**：`brief check` 打印 `[OK]`；`problem_id` 与题目匹配（不匹配只 WARN 不阻断，人应修）；空 brief 会 WARN「不会注入任何约束」。
- **介入点**：人改 json 任意字段；改完必须再 `check`。口径分叉写进 brief（备选口径 + 数量级差），不要假装已唯一正确。
- **失败**：check 失败 → 修 json，停在 S3。方向后来被求解证伪 → **回本阶段改 brief**，从 S4/S5 重来。
- **【待实现】** 入口 A 的「探索 md → 一次调用出完整 brief.json」（`brief extract`）。pilot 模式（`run --pilot`，09 有设计，CLI **没有**该旗标）。

C 题对照：`problems/mcm51-c/brief.json`（`brief check` [OK]）。

## S4 启动前预检

- **目标**：烧 token / 开求解之前，机械检查 spec、brief、可达性、附件、缺库。
- **进入条件**：S0 + S3 完成（无 brief 也能 dry-run，但不推荐）。
- **命令**：

```text
math-agent run --problem problems/<题号>/problem.json --brief problems/<题号>/brief.json --out runs/<run名> --dry-run [--force]
```

- **行为**：不调用解题 LLM。`feasibility.blockers` 非空 → 拒绝启动。缺 sklearn 等只 **WARN 不阻断**（A3）。写入 `runs/<run>/preflight.json`，若 `--problem` 指向 `problem.json` 则同时写入同级 `preflight.json`（供 `problem stage` 认 S4）。
- **产出**：终端报告；不写论文。
- **完成判据**：打印 `[OK] 全部通过`。WARN 缺库时，S5 求解 prompt/脚本必须避开这些库。
- **介入点**：修 spec/brief/附件后再跑同一条命令。
- **失败**：预检失败不得进入 S5/S9。
- **【待实现】** 预检结果的更多字段（现在已有 `preflight.json`：ok/warns/blockers/brief_path）。

## S5 求解验证

- **目标**：写出能跑的求解脚本，得到**自己执行出来的数字**，并独立复核。不写论文。
- **进入条件**：S4 通过；brief 已冻结一版（之后改 brief 须重做本阶段）。
- **输入**：附件、`brief.json`、`data_profile.md` 锚点（若有）。
- **命令**：`math-agent reference verify --problem <spec> [--evidence <evidence.json>] [--out <package.json>]`（v0 机械三项）。无求解器重跑；缺 evidence 则默认 `runs/<id>-reference/evidence.json`。
- **产出**：默认 `problems/<题号>/evidence-package.json`。脚本草稿仍常在 `runs/<题号>-skill-v1/solve/` 或 `source/reference/`；运行输出为 RESULT/Q 行。独立复核记录仍无命令（T-09）。

- **完成判据（人检，非机器门）**：exit=0；无 NaN/Inf/硬编码答案；关键交付表能被独立锚点逐格对上（C 题教训：整模型 RMSE 好看仍可能表 1.1 全错）。确定性复现、下界对照见 docs/19 验证标准——**尚未做成验收命令**。
- **介入点**：主会话可打断子 agent、带数值判据返工（docs/18 §11.1–11.2）。换执行者 = 交出脚本 + 输出，不交出「自报分数」。
- **失败**：脚本错 → 停在 S5 修；不要用流水线 coder 再生成一层包装来「绕过」（docs/19：生成包装是停机源）。
- **【待实现】** 独立复核的机械入口（T-09）。**【待实现】** 子 agent 派发/工作目录约定的体系命令（T-10）。docs/19 全量 evidence-package（sensitivity/honesty/口径 checklist）仍未做。

C 题对照：`problems/mcm51-c/source/reference/`（q1–q5 + `_entry.py`）；主会话抓到 Q1 β1 退化后返工。

## S6 登记装配

- **目标**：把已验证脚本登记为题参考实现，抽出 evidence，装配表，出论文骨架。纯代码，无 LLM。
- **进入条件**：S5 脚本人已接受；`tables.json` 若要出表必须先有（题级声明）。
- **命令**：

```text
math-agent reference add --problem problems/<题号>/problem.json --solver <脚本目录> --entry <入口相对路径> [--force]
math-agent reference run  --problem problems/<题号>/problem.json [--out runs/<题号>-reference]
math-agent reference tables --problem problems/<题号>/problem.json --evidence <evidence.json> [--out …]
math-agent reference paper  --problem problems/<题号>/problem.json --evidence <evidence.json> [--brief …] [--out …]
```

- **产出**：

| 命令 | 产物 |
|---|---|
| add | `problems/<题号>/source/reference/`、`reference.json`、更新 `problem.json` 哈希 |
| run | `evidence.json`（默认 `runs/<题号>-reference/`） |
| tables | 交付表 md/csv（依 `tables.json`） |
| paper | `paper.md` 骨架（分析 prose 为【待展开】占位） |

- **完成判据**：`reference run` 的数字与 S5 锚点一致；`tables` 逐格能对题面指定表；`paper` 可用 `check_paper_numbers` 溯源。
- **介入点**：换脚本 → `add --force` 后重跑 run/tables/paper。不要手改 `evidence.json` 里的数字。
- **失败**：缺 `tables.json` → tables 无法按声明装配。表 3.2 这类「清单型」输出，参考实现若没打印对应行，装配补不上。
- **【待实现】** 论文骨架 → 终稿 prose 展开（模块 8 残项）。**【待实现】** A2 锚点闸门（暂缓）。**【待实现】** 表 3.2 类清单的自动输出约定。

C 题对照：`reference.json`、`tables.json`、`runs/` 下 reference 产物；附录 A 溯源 20/0。

## S7 评审

- **目标**：口径、数字、假设在放行前过闸。写作漂亮不是本阶段目标。
- **进入条件**：有论文 md + 证据文件（S6 的 `evidence.json` / 求解 stdout / 敏感性 json，有什么给什么）。
- **命令（统一入口 + 底层脚本）**：

```text
math-agent review-check --paper <paper.md> --evidence <文件>… [--strict] [--json] [--out <report.json>]
python scripts/check_paper_numbers.py --paper <paper.md> --evidence <文件> [<文件>…] [--strict]
python scripts/check_assumption_claims.py --paper <paper.md> [--strict]
python scripts/check_gap_trigger.py --json <证据.json> [--threshold 15] [--strict]
python scripts/report_calibration_diff.py --official problems/<题号>/calibration/official_answers.json
```

`review-check` 只包装前三个脚本（D-003）。根命令 `review` 仍是流水线人审接管，不要混用。

- **清单（无命令，人/评审 agent 必答）**：[8-26-C类-评审口径核查必答项](8-26-C类-评审口径核查必答项.md) 四问。C3 注入流水线 prompt **待模板确认**。F 类得分点：无细则时由评审 agent 按题面交付物自检，**体系侧不建工具**。
- **产出**：终端报告 + 评审结论 md（路径未强制；C 题由评审 agent 写）。
- **完成判据**：`--strict` 下数字溯源与假设自相矛盾规则通过；C 类四问都有书面回答；人决定放行或列出修订项。
- **介入点**：不放行 → 回 S5 修脚本或回 S3 改口径或回 S6 重出骨架/表。表述误导但数字对：改论文，不必重算（docs/18 §11.5 两层防线）。
- **失败**：把大 gap 写成「诚实加分」不算过关（C 类 Q2）。
- **【待实现】** C3 必答项注入轨 A 节点。`check_gap_trigger` 目前按调度题「下界 vs makespan」键名扫描；预测题要靠人改用口径差，**无通用适配命令**（T-16）。

`report_calibration_diff.py` 仅赛后有官方答案时用，**不进入正常做题路径**。

C 题对照：三闸门 + 四必答项；`check_assumption_claims` 0 矛盾。

## S8 人审与提交

- **目标**：交付 `paper.md`（主产物）。PDF 只做编译预览，不承诺可提交（原则 7）。
- **进入条件**：S7 放行。
- **命令**：
  - 分阶段路径：没有单独的「提交」命令。人把 `paper.md` 拷去后续 Word/LaTeX 流程。
  - 若走了 S9 且停在 `human_review`：

```text
math-agent resume --out runs/<run> --thread <thread> --approve|--no-approve [--notes …]
math-agent supervise-resume --out runs/<run> --thread <thread> --approve|--no-approve
```

- **产出**：分阶段路径 = 已放行的 md；流水线路径 = 批准后才跑 latex/finalizer。
- **完成判据**：人接受 md；需要 PDF 时再编译，失败不否定 md。
- **介入点**：拒绝批准 → 回 S7 修订清单。不要在人审里改方向（回 S3）。
- **【待实现】** 分阶段路径的人审登记（谁在何时放行、放行的是哪份 sha256）。现在只有流水线 checkpoint 里的 `human_decision`。

## S9 可选：LangGraph 流水线

- **目标**：在已有 brief（建议已有参考实现）时，用图跑分析→建模→编码→图→论文→人审→LaTeX。
- **默认**：新题**不**把本阶段当主路径。轨 A 出好论文已降级（07 行 21）。
- **进入条件**：S4 通过。无参考实现也能跑，但 coder 会 LLM 生成，失败模式见 docs/18。
- **命令**：

```text
math-agent start     --problem … --brief … --out runs/<run> --thread <id> [--force]
math-agent supervise --problem … --brief … --out runs/<run> --thread <id> [--force]
math-agent watch     [--out runs/<run>] [--thread <id>]
math-agent status    [--out runs/<run>] [--thread <id>]
math-agent pause     --out runs/<run>
math-agent recover   --out runs/<run> --thread <id>
math-agent restart   --out runs/<run> --thread <id> --from coder --reason <原因>
math-agent report    --out runs/<run> --thread <id>
```

- **`run`**：前台跑完整图（相对 `supervise` 无自动崩溃续跑）。`--no-interrupt` 跳过 human_review。
- **产出**：`runs/<run>/paper.md`、`trace.json`、checkpoint、`supervisor.json`（若 supervise）、可能 `failure.json`。
- **完成判据**：`status` 为 completed/degraded/rejected/blocked 之一；人审前不要当交付。
- **介入点**：`pause` 在当前**节点边界**停；之后 `recover`。`restart --from` **目前只支持 `coder`**，且仅门禁停机态。
- **失败**：同一节点反复空 content / 门禁耗尽 → 不要盲 recover。看 `failure.json` 与 docs/18 故障谱。
- **【待实现】** 从任意节点重启。**【待实现】** 流水线在 S6 已有冻结参考实现时跳过 LLM 生成、直接执行资产（docs/19 推荐方案，待确认）。**【待实现】** 控制面/编排面（中枢遗留：默认仍是无人值守 start/supervise）。

观察面：`watch` / `progress.jsonl` / `insights/`（docs/03）。非 TTY 的 watch 不是 `tail -f`（已知遗留）。
