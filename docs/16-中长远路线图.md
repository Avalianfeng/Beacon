## 一、战略三选项（互斥终态，由数据决定，不提前押注）

| 终态 | 定义 | 胜出条件（Go） | 投入量级 |
|---|---|---|---|
| **A 专家副驾驶** | 定位收缩为「建模副驾驶 + 受控自动执行器」：人工定方向、检查点介入，体系负责执行与兜底 | 副驾驶显著胜出自动模式 | 3–4 人 × 6–9 月（24–36 人月） |
| **B 全自动求解器** | 升级「AI 自动完成竞赛题」定位 | 自动模式盲测稳定接近副驾驶 | ≥5–7 人 × 12 月（50–70 人月）；**盲测通过前不批准** |
| **C 收缩薄产品** | 保留 runner/证据链/恢复，砍 LangGraph 角色数量，重构为更薄的产品 | Beacon 对强模型+工具基线无稳定优势 | 未定（以重构为主） |

> 6 个月内的**正式产品定位**按 A 执行（副驾驶为正式定位、低人工自动模式为实验分支）；若盲测推翻则按 C 收缩。
> 本定位为规划基线（决策点 D1），不改变近期执行顺序。

## 二、门控决策与治理阈值（阶段 1 盲测产物，通过后才推进全自动）

晋级门槛（相对「强模型 + Python/工具」简单基线）：

- 盲评中位数提升 **≥10 分**；
- 严重错误率 **<10%**、完整交付率 **≥90%**；
- token 成本 **≤2×** 简单基线；
- 人工时间中位数 **≤45 分钟**；
- 最差 20% 题目不出现系统性崩塌。

> 以上为**建议治理阈值**（评估 H18），不是已有事实；盲测前任何人不得引用为「已达标准」。

## 三、阶段 0–4

### 阶段 0：0–6 周——停止假成功，建立测量基线（与 00 §六 阶段一~四合并执行）

- P0：机制修复（M1–M6）落地进度（2026-08-21，v2 重排）：**已完成 M1 编译 / M6 回归数值（当前题要求）/ M5 量纲 prompt 层**；
  主线 = **M3 红线（批次 1）→ M2 图表注入（批次 3 §3.1 单拎）→ pilot 模式（09）**，均在第一次真跑前落地；
  **M4 对照通用化冻结**（前几题手工补对照 + 诚实记录）。
- 每次 run 汇总：节点 token、调用次数、重试原因、墙钟时间、人工分钟、废弃调用、质量变化（成本遥测，见 docs/17 #1）。
- 严重失败定义：红线违规 / 单位混比 / 附件未读 / 虚假证据 / 必需图缺失 / 基线未执行却声称存在 / 人工修补后才交付。
- 验收：严重失败不再标 completed；degraded 原因机器可解释；能回答「一分质量提升花了多少 token/时间/人工」。
- 投入：2 工程师 + 1 建模评测负责人，约 1–1.5 人月。

### 阶段 1：1.5–3 个月——无参考盲测（本路线图核心前置）

> **2026-08-21 用户拍板降级**：原「12–20 题、双外部评审、多种子」的大盲测基建冻结；
> 改为 **3 道干净新题、输出冻结后自评**（约 80% 信号、5% 成本——按单人+AI 的执行现实收缩治理规模）。
> 条件④检查点 2（首个数值证据后人工检查）已**提前为常规 pilot 模式**（实现计划-8-20/09）。
> 下方原条款保留为「将来重建完整盲测时」的规格参考，当前不执行。

- 数据集：12–20 题、≥4 类题型；**MCM-51 移入「已污染开发集」**，不得再作泛化证据（H16）。
- 四条件对比：①强模型+工具基线；②Beacon 无 brief；③Beacon+限时合法 brief（不含答案）；④Beacon+三个人工检查点（H07）。
- 流程：评分标准与参考结果在输出冻结后揭盲；≥2 名外部评审独立评分；2–3 个随机种子。
- 检查点 2（首个数值证据后人工检查残差/单位/边界/失败假设）在此阶段接入，作为条件④的一部分。
- 产出：评测设计文档（盲测集、揭盲协议、评分表）→ 第一轮盲评报告 → 门槛判定（D4）。

### 阶段 2：3–6 个月——主张—证据系统（brief 账本化）

- 兼容现有 brief 接口，内部转结构化账本：每条要求记录 来源/置信度/假设/责任节点/预期产物/验证器/最终状态（H05）。
- 方向从「不可质疑命令」变「待验证假设」；首轮只跑低成本 pilot 检查可识别性/残差/量纲/边界/竞争模型（C2 批准后实施）。
- 关键数值可追溯到附件/公式/执行结果/明确人工输入；图、基线、敏感性作为一等证据，不再依赖 analyst 转述。
- 验收：95% 以上要求可追踪到产物或明确失败原因；故意注入错误 brief 时系统能反证而非照单全收；
  figure_plan/data_notes/scoring_notes 不再静默丢失。

### 阶段 3：4–9 个月——可验证方法能力库

- 沉淀并测试的模块：变点检测、回归诊断、单位换算与量纲分析；优化可行性检查、小实例精确对照；
  敏感性/稳健性/不确定性分析；图表完整性与数值一致性检查。
- 知识获取：来源明确的题目资料包、方法卡片、全文检索或小型受控检索；**embedding 是否使用是实现选择**，
  不作长期原则（C4 批准后改写原则 4）。
- 验收：同类方法跨题复用不再重复生成/修复基础实现；确定性验证覆盖主要数值与物理不变量；
  不降盲评质量的前提下无效重试 token 降 **≥40%**。

### 阶段 4：9–12 个月——真实竞赛模拟与去留决策

- 完整限时模拟：严格记录允许的外部资料、人工参与、最终提交格式。
- **Go/No-Go 三选一**（见第一节表）：自动≈副驾驶 → B；副驾驶显著胜出 → A（正式定位「AI 建模工作台」）；
  无优势 → C（收缩）。
