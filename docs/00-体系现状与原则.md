## 一、我们在做什么（一句话）

优化 Beacon 数学建模自动化体系：把「知识闭包内自转的求解器」改造成
**「以方向生产为前置、人机协同确定建模边界、并通过执行证据与后置确定性机制共同保证质量」** 的体系——
前置（人+强模型+联网）先做**题目探索**（先问「这道题可能要求我们看到什么」，再问「怎么解」），
产出方向性认知地图与 Modeling Brief；质量靠执行证据与后置机制（门禁/评审/校验）兜底。

> 现状更准确的说法：**受人工策略约束的建模执行与论文生产平台**——编排与证据管理成熟，
> 通用求解能力待无参考盲测验证（智慧中枢评估 H01/H02，见 [docs/15](15-智慧中枢评估与处置.md)；路线图见 [docs/16](16-中长远路线图.md)）。
> 方向生产协议见 [docs/brief-playbook.md](brief-playbook.md)（题目探索 → 多视角对撞 → 逐问清点 → 方向收敛 → brief，2026-08-21）。

## 二、核心原则（约束；改动需论证）

1. **参考答案不可得**：brief-v1 的数值命中是意外特例，不是通用能力；不得把数值注入写进通用路线图。
2. **以工程完善体系为第一目标**：前置质量（**题目探索 + 方向生产**）+ 竞争假设 + 运行证据 + 后置校验**四层共同防御**（不把质量责任单向后移）；单次任务的成功不得污染通用设计。（C1 已采纳，2026-08-20）
3. **不重写架构、不开新项目**（近期约束；Go/No-Go 决策点可重议，C3 已采纳）：节点与证据链机制是 11 轮踩坑积累，重写=重踩 P01–P20。**豁免：前端壳允许整体重设计**（D6 已批准，2026-08-20——前端是交互层、不承载求解逻辑，不在体系讨论范围；核心流水线仍守本原则）。
4. **当前不启用向量检索**（实现选择：embedding 网关不支持；C4 已采纳）：检索需求由文本资料包前置注入满足（本质是受控检索）；网关可用后重评估。
5. **前置只承诺方向级+实现级**；验收级数值锚点只能从题目自带数据+量纲一致性+领域常识重建。
6. **brief 产出路径：题目探索 → 认知地图文档 → 提取 brief**（文档+提取为主，对话兜底）；探索由人+强模型+联网在前置完成（先扩大认知空间，再收敛方向）；`brief extract` 命令方向已定、暂不实现。
7. **最终产物以 .md 为主**：`paper.md`（+`paper.tex` 源码）是交付物；PDF 仅用于 LaTeX 链路验证与预览，**不承诺完整可交付**；版式/格式调整由后续人工流程手动进行，提交前必有再处理流程（2026-08-20 确认，H15）。
8. **方向在源头定，错了回源头改 brief 重跑**；体系内不做**无依据的 LLM 投票式**方向评审，但允许基于确定性证据（残差/量纲/边界/对照实验）的方向反证（C2 已采纳，2026-08-20）。
   **前置多模型对撞 ≠ 体系内投票**（2026-08-21 明确边界）：对撞在前置、人主持、目标是**暴露遗漏、扩大搜索空间**（先问「A/B/C 之外是否还有看不见的 D」）；多模型一致不构成方向正确性证据——**多模型负责发现更多可能性，确定性证据负责淘汰错误可能性**。

## 四、体系怎么工作（模块与链路）

- **前置方向生产层（2026-08-21 明确，在流水线之外、之前）**：题目探索（人+强模型+联网，先扩大认知空间）→ 方向性认知地图（`problems/<题号>/exploration.md`，人侧文档）→ Modeling Brief（压缩为方向级约束）——协议见 [docs/brief-playbook.md](brief-playbook.md)；体系在方向确定之前**不提前开始解题**。
- **流水线**：analyst（读题出蓝图）→ blueprint_critic → modeler → model_critic → coder → model_code_consistency → sensitivity → figure → writer → paper_critic → evaluation → human_review → latex → finalizer。
- **核心机制**：证据链（checkpoint + 哈希 + 步骤日志）；确定性门禁（runner 硬限制 / 篇幅 / 质量分 / brief_coverage / 无主证据硬停）；角色隔离（primary/baseline/supporting）；崩溃恢复（SQLite checkpoint，recover/supervise-resume）。
- **brief 注入**：六处 prompt（analyst/blueprint_critic 全量、modeler 方向+公式、model_critic/coder 公式+红线、writer 讨论点分组）；门禁在 blueprint_critic 后（缺回应→retry≤2→stop）。
- **模块清单**（详细职责见 PROJECT-STATUS 历史版或各模块源码）：`state.py` 数据契约；`brief.py`/`brief_dialogue.py` brief 全栈；`cli.py` 命令入口；`graph.py`/`routing.py` 图与路由；`checkpointing.py` 序列化白名单；`supervisor.py` 后台监督；`llm.py` LLM 封装；`config.py` 阈值；`nodes/` 各节点；`prompts/` 提示词；`rag/` 五件套（已决策不启用）；`runner/` 执行沙箱。
