- 定位：**方向生产的可复用协议（与代码同等重要的工程资产）**。体系已被证据定位为「方向决策的高保真
  执行器」（brief-v1：无 brief 35–40 分 → 带参考值 brief 74–86 分，H02）——**每道题最贵的智能必须花在
  方向生产上**，体系只承担「忠实执行 + 确定性校验 + 廉价早期反证」。本手册规定「先探索、再收敛」的完整流程。
- 使用对象：用户（人）+ 网页版最强模型（**2–3 家不同家族**）+ 联网搜索 / 论文检索。
- 与体系接口：产出物 = `problems/<题号>/exploration.md`（方向性认知地图，**人侧工作文档，不直接注入**）+

  `brief check` 校验；`run --dry-run` / `--pilot` 预检（见
  [实现计划-8-20/00](实现计划-8-20/00-新题上线流程设计.md)；
  pilot 设计已归档 [archive/8-20执行批次/09-pilot模式与早期反证.md](archive/8-20执行批次/09-pilot模式与早期反证.md)，CLI 已拍板不做）。
- 核心原则（2026-08-21 与外部讨论收敛，不可跳过）：
  1. **先问「这道题可能要求我们看到什么」，再问「我们应该怎么解」**——先扩大认知空间，再收敛建模方向。
  2. **探索负责避免看不见；验证负责避免做错**——两个阶段职责不同，不可互相替代。
  3. **拒绝「一次性产出完美方向」**：强模型在开放式建模题上的典型失败 = 自洽、优雅、但偏离出题人问的
     东西，且自我审查发现不了（H04；MCM51-A 的 1.2/3.1/3.2/4 四问空白 40 分的共同特征不是算错，而是
     **建模视角根本没进入认知空间**）。方向质量靠结构保证，不靠模型天赋。
  4. **探索 ≠ 推测答案**：探索产出独立于最终模型的「方向性认知地图」，绝不倒推官方参考答案/评分标准
     （防泄漏条款，原则 1）；已公开题目属污染开发集，只能用于机制调试（H16）。
  5. **多模型负责发现更多可能性，不通过投票制造正确性**（C2 边界：对撞在前置、人主持、目标=暴露遗漏；
     方向正确性只由确定性证据淘汰——残差/量纲/边界/对照实验/题面约束）。

## 〇、新题开工前选型 checklist（D-015 / D-018 · 每次开题强制过一遍）

> 动机：口径裁决 / 命题者特设答案命中，只能靠前置输入质量（docs/20 §四 H1–H3），体系无法归零。
> 本表把「人 + 模型 + 外部经验」选型流程化；**在阶段 0 素材盘点之前或同时完成**，勾完再进开放探索。
> 来源：大模块 9（D-015）+ 设计债 B25 / 17#10（D-018）。

### 0.1 读题与对撞人力（选一种主路径，写进开题记录）

| 勾选 | 项 | 怎么做 | 为何 |
|---|---|---|---|
| □ | **双人双读** | 两人各自独立通读题面+附件说明，再交叉对照「我看到的关键约束 / 弱线索 / 可能歧义」 | 同一人二次通读易漏同一盲区 |
| □ | **人机分读**（推荐默认） | 人先读并标疑点；再发 **2 家不同家族**强模型各做一版「只列约束与歧义、不解法」；人主持 diff | 多模型暴露遗漏，不投票定口径 |
| □ | 单人 + 单模型 | 仅当时间极紧；须在 brief 假设里显式标高风险 | 口径误判概率高，赛后难辩 |

### 0.2 历史真题与细则前置

| 勾选 | 项 | 怎么做 | 为何 |
|---|---|---|---|
| □ | **同届 / 同型历史真题参照** | 扫一眼同届另一题或同型旧题的教训卡片 / calibration（若有）；记下命题风格线索（如「买满关键类型」vs「最小花费」） | H2：特设答案命中靠先验，不是靠流水线 |
| □ | **评分细则 / 官方提示前置收集** | 若赛方赛前公开细则、算法提示、提交说明——**先收集再建模**；细则中的分配/分摊措辞可反推口径 | H2：细则反推是可制度化的前置智慧 |
| □ | **关联题教训卡片** | 读 `problems/<关联题>/教训卡片.md`（或图景 05 交叉引用）至少一通 | 避免同届重复踩坑 |

### 0.3 真实比赛规则确认（B25 · 开题当日必须钉死）

在开题记录（可写在 `exploration.md` 头部或题目录 `比赛规则.md`）写清下列四格；**未确认前不假设「随便用 AI / 随便联网」合法**：

| 勾选 | 规则项 | 须记录的结论 | 备注 |
|---|---|---|---|
| □ | **AI 使用** | 允许 / 禁止 / 仅本地 / 须声明 | 影响能否用外部网页模型做对撞 |
| □ | **联网 / 外部资料** | 允许检索范围；是否可引论文/公开数据 | 影响 `background_knowledge` 与 reference_direction |
| □ | **提交格式** | 论文主格式（本仓默认 **.md**；PDF 仅预览）、支撑材料、页数/字数、命名 | 挑战⑦ 已决：.md 为主，格式精排走人工/外流程 |
| □ | **其它边界** | 是否允许多人协作、代码是否提交、是否盲审等 | 有则记，无则写「赛方未规定」 |

确认后：若规则与当前工具链冲突（例如禁止外部 AI），**当场收缩对撞路径**（改纯人读或仅本地模型），不要跑到 S5 再改。

## 一、总流程（一次题目，六个阶段）

```
0. 素材盘点（题面 md + 附件清单 + 交付格式）+ **§〇 选型 checklist**  —— 实现计划-8-20/00 演练步骤 1
1. 开放探索（§二）——不急于选方向：出题人/评阅人/建模者多角度，扩大认知覆盖
   → 原始探索产出（思考路径，可能数千行、数十个互不兼容的候选点）
1.5 探索消化（§2.5，第二轮追问）——同一会话追问，把思考流收敛为
   「认知地图 v1」：结构化、标重点、分优先级、标注互不兼容项（≤150 行）
2. 多视角对撞（§三）——2–3 家不同家族 + 角色分工，互不看，独立产出；人主持 diff，暴露遗漏
3. 逐问清点（§四）——checklist 逐问过「有没有可能完全没看到某个重要因素」→ 问题分解表
4. 方向收敛与写入 brief（§五）——主方向/次方向/必须考虑/风险/待验证假设 → 字段映射 → brief check
5. pilot 验证 → 全跑 → 评估简报 → 外部评估回填（§六）——错了回源头改 brief 重跑（原则 8）
```
## 二、阶段 1：开放探索（Problem Exploration）——最关键的一步

- 目标不是「怎么解」，而是**「这道题究竟有哪些值得考虑的东西」**。MCM-51 反例：r11 不是算错，而是
  1.2 变点视角、3.1 调心垫圈、3.2 偏心修正、4 围岩分级**在建模前就没进入认知空间**。
- **阶段 1 的产出不是认知地图，而是「思考路径」**（2026-08-21 实操反馈）：第一轮探索可能输出数千行、
  数十个互不兼容的候选方向——它们不能直接进 brief，也不能全写进论文（论文重心会跑偏）。
  **认知地图是 §2.5 第二轮消化后的收敛产物**：先扩大认知空间（阶段 1），再消化为可读地图（阶段 1.5），
  之后才能谈收敛与选择（阶段 2–4）。
- **关键实验证据（2026-08-21 外部讨论）**：同一题目，直接说「请开始建模」→ 模型快速进入熟悉的解题
  套路；加上「现在先不要急着解，请站在出题人、评阅人和建模者多个角度，系统探索这道题可能要求我们
  考虑哪些方向、隐藏结构和容易遗漏的点」→ 在不知道官方参考答案的情况下，模型自然注意到
  「前期非线性、后期稳定线性→变点/分段」「多失效条件→统一约束/可行域」「偏心→附加弯矩」
  「调心垫圈→定量价值」「围岩分级→主控模式分区」——与官方评分高度接近。
  **模型未必需要事先知道答案；更重要的是给它正确的认知任务。**

### 2.1 探索提示词（发给任一强模型先跑；可单用，也可 2–3 家并行后对撞）

> 现在先不要急着确定模型，也不要开始解题。请站在**出题人、评阅人和建模者**多个角度，系统探索这道题
> 可能要求我们考虑的全部重要方向：
> 1. 题目显式要求什么（逐小问列出）；题目中值得重视的关键词与结构；
> 2. 可能存在的物理 / 几何 / 数学机制、边界条件、分段 / 临界现象、变量之间的耦合；
> 3. 多个约束之间可能存在的关系（谁是主控、谁只是判据、谁参与比较）；
> 4. 各小问之间潜在的前后依赖与递进关系；
> 5. 可能需要参数化 / 分类 / 优化 / 敏感性分析的地方；容易被忽略的工程含义；
> 6. 值得进一步核查的专业知识与术语（允许联网搜索与论文检索，引用注明来源）；
> 7. 尚无法确定但应保留的备选方向。
> 此阶段**不要求做最终选择**。输出一份「方向性认知地图」，并在最后单列一节「最容易整体漏掉的东西」。
>
> 题目：
> <粘贴题目 md + 附件数据>

### 2.2 多视角角色清单（对撞阶段分配角色用）

数学建模者 / 工程专家 / 物理专家 / 数据分析者 / **出题人** / **评阅人** / **怀疑者（反方）**——
目的不是投票，而是**暴露遗漏**；每个角色从自己的立场独立产出或增补认知地图。

### 2.3 探索输出：方向性认知地图（人侧工作文档，不直接注入流水线）

包含：显式任务；关键词与结构；物理机制；几何关系；边界条件；分段/临界现象；变量耦合；约束间关系；
小问间依赖；参数化/分类/优化/敏感性需求；易忽略的工程含义；待核查专业知识；备选方向。
落盘 `problems/<题号>/exploration.md`（人工审阅后）。
**它不负责决定最后答案，它负责告诉后续建模系统：「不要忘记这些东西」。**

### 2.4 探索的边界（三条，违反即作废重来）

1. 不推测官方答案；不检索 / 引用官方参考答案与评分标准文件（防泄漏）；
2. 不投票定方向——多模型一致 ≠ 方向正确（可能共享训练偏差 / 常见套路 / 信息盲区）；
3. 联网只用于「题目内部理解 + 外部知识核查」（工程标准 / 装置原理 / 专业术语 / 失效模式），
   不是为了找答案。

### 2.5 探索消化（第二轮追问）：从思考路径到认知地图 v1

- **为什么需要（2026-08-21 mcm51-b 实操实证）**：第一轮探索在 GPT 上产出了 3364 行、75 个候选点的
  思考路径——信息极丰富但**未收敛**：大量方向互不兼容，不能同时作为主方向写进论文（论文只能有一个
  主线，探索点过多会冲淡重心）。原始输出已归档（实现计划-8-20/实际操作记录/第一论.md，只作证据，
  不读全量）。
- **关键实操**：**在同一个会话里继续追问**（模型上下文自带第一轮产出），不要新开会话重来——
  强模型一次会话内的「探索 + 消化」即可接近 brief 初稿（2026-08-21 判断）。
- **第二轮追问提示词**：

> 你刚才的探索非常全面。现在进入**收敛阶段**：请把上面的思考消化为一份「方向性认知地图」，做到：
> 1. 结构化输出，每节收敛到 3–6 条重点（**不要罗列所有可能性**）：
>    显式任务与交付物 / 关键词与结构 / 物理·数学机制 / 边界条件与口径歧义（含你的裁决倾向） /
>    约束间关系（谁主控、谁只是判据、谁参与比较）/ 小问间依赖与递进 / 必须做的参数化·优化·敏感性 /
>    易忽略的工程含义 / 建议的建模方法族（1 个主方向 + 2 个对照候选，标注不兼容处）/
>    待核查的专业知识与文献线索；
> 2. 每条标优先级：🔴 必做（不写必丢分）/ 🟡 应做（加分或完整性）/ ⚪ 存疑（保留为对照或风险）；
> 3. 明确标注**互不兼容的候选方向**——它们只能作为对照方案，不能同时作为主方向写进论文；
> 4. 最后给出「如果只把 5–8 个探索点写进论文，哪些必须体现、哪些会冲淡重心」；
> 5. 输出总长控制在 100–150 行以内。

- **判据**：若第二轮仍 >200 行或 🔴 超过 15 条 → 再追问一轮压缩（第三轮只压缩、不新增内容）。
- **产出**：认知地图 v1 → 落 `problems/<题号>/exploration.md`；第一轮原始输出归档
  （`实际操作记录/第N轮.md`），防止丢失。
- **与 brief 的关系**：认知地图 v1 仍不直接注入流水线；它是对撞（阶段 2）与逐问清点（阶段 3）的
  共同输入，最终只把压缩后的方向级条目写入 brief（§五 5.1）。

## 三、阶段 2：多视角对撞

- **对撞输入 = 各模型的认知地图 v1（§2.5 消化后）**，不是原始思考流——先把各自的 75 点压到 100–150 行
  再并排 diff；原始探索只在自家会话里消化，不外传全量。
- **对撞的首要目标**：回答「A/B/C 之外是否还存在一个从当前思路根本看不到的 D」，其次才是从已见
  选项中选优（先扩大搜索空间，再进入空间内的优化）。

### 3.1 提案提示词（每家模型同构发送；角色可不同，**互不看彼此输出**）

> 你是数学建模竞赛参赛队的主建模手（本次分配角色：<建模者/工程专家/物理专家/数据分析者/出题人/
> 评阅人/怀疑者 选一>），独立完成下面这道题的**全套方向方案**（只做方向与建模设计，不写论文）。
> 不要提及任何其他 AI 或他人的方案。按以下结构输出：
> 1. 先给「方向性认知地图增补」：在给定认知地图之外，你认为还有哪些被忽略的视角、隐藏条件与
>    潜在评分点（没有则明确说没有）；
> 2. 逐小问：选定方向一句话 + 建模方法 + 关键变量/约束/公式符号 + 关键假设 + 交付物；
> 3. 每小问的候选对照方案（与主方案不同方法/不同假设，供敏感性对照）；
> 4. 全局假设清单（逐条一句话理由 + **假设分级**：①题面原文引用——带引号与出处 / ②合理推断——显式标注"推断" / ③经验假设——标注无题面依据；对题面未明说的口径点给出**裁决 + 备选口径 + 备选口径下的预期数值差异（数量级）**）；
> 5. 图/表计划（每张图对应哪一小问、画什么、标注什么；题目指定交付表的格式要求）；
> 6. 红线：数值/符号/口径上绝对不能出现的做法；
> 7. 风险清单：哪里最可能错、错了怎么自查（含结果数量级 sanity check）。
> 全程允许联网搜索与论文检索（方法细节、工程标准、竞赛惯例），引用注明来源。
>
> 题目与认知地图：
> <粘贴题目 md + 附件数据 + 阶段 1 的认知地图>

### 3.2 执行规则

- 2–3 家**不同家族**前沿模型（按当时可用最强组合选）；**互不看彼此输出**——独立性是对撞有效的前提。
- 给每家同一份题目 + 附件 + 认知地图；输出结构固定（3.1）。
- 模型可以联网搜索 + 论文检索——这是流水线刻意不具备、而方向决策恰恰需要的能力。

### 3.3 diff 方法（人主持）

- 把 2–3 份产出**并排、按小问逐行**对比；**分歧点 = 最危险的地方**（也是遗漏高发区），逐个裁决。
- **对撞的首要目标是回答「A/B/C 之外是否还存在一个从当前思路根本看不到的 D」**，其次才是从已见
  选项中选优——先扩大搜索空间，再进入空间内的优化。
- 裁决依据优先级：题面措辞 > 附件数据 > 领域常识 > 文献/竞赛惯例。
- **禁止性假设的裁决纪律（v3 口径防线，2026-08-26）**：以"题面没有此机制""题面未要求"为由的禁止性假设
  （如"不允许多台同类设备分摊"），一律视为弱依据（分级②/③），必须：① 在对撞中显式列为分歧点；
  ② 记录备选口径；③ 写入 brief 的 prohibition 文本时注明分级与依据，**禁止写成"题面明确要求"**
  （"题面明确要求"字样只允许出现在分级①条目，带引号+出处）。
  **为什么"题面没有此机制"是弱依据**：题面没有写"允许拆分" ≠ 题面禁止拆分。题面未明说的自由度
  （一道工序由几台设备完成、任务可否拆分）在没有禁止表述时是**开放的**，建模者可以选择最有利且可辩护的
  解读；选择收紧解读（如禁止分摊）会**系统性抬高时长、低估优化空间**（mcm51-b：Q1 +4320 s、Q2 +50.6%、
  Q3 +74.4%、Q4 +302%，39 分结果分丢失），且论文无法引用任何原文为收紧辩护。
  **判据：想禁止一个自由度时，先自问"题面哪一句话禁止了它？"——答不出，就是分级②/③，必须记录备选口径。**
- **每裁决一个口径分歧，必须同时记录备选口径 + 备选口径下的预期数值差异（数量级）**，写入
  exploration.md 的"待验证假设 / 备选口径"节（mcm51-b 教训：假设 9 若记录"备选口径 = 允许分摊，
  A1 可压缩约 4320 s"，口径风险在 pilot 前即可见，而不是赛后评估才发现）。
- 每问输出：**选定方向 + 淘汰方案及理由 + 保留为对照方案的候选**（M4 冻结期手工补对照，见 §六）。

### 3.4 常见分歧类型（提前知道要裁决什么）

| 类型 | 例子 | 裁决依据 |
|---|---|---|
| 方法族之争 | 解析 vs 数值；启发式 vs 精确优化；MILP vs 元启发式 | 题面规模/精度要求/交付物类型 |
| 假设之争 | 某因素可否忽略（运输时间、失效模式） | 题面措辞与数据量级 |
| 口径之争 | 单位/起点/取整规则 | 题面表格格式与常识 |
| 交付格式之争 | 表怎么填、图怎么标 | 题面指定格式为准 |
| 单向约束逆命题 | "同一时刻每台设备只能服务一道工序"推不出"一道工序只能由一台设备服务" | 区分约束作用层级（类型级 vs 实例级）；题面只给单向表述时禁止反向引申，反向约束必须另有原文依据（分级①） |

> **「单向约束逆命题」为什么推不出、如何判定（v3 口径防线，2026-08-26）**：
> 调度类题面的容量约束通常声明"资源（设备）→ 任务（工序）"方向——"同一时刻每台设备只能服务一道工序"
> 是一条**设备容量约束**，只限制"一台设备同时只能干一件事"。反向命题"一道工序只能由一台设备服务"是
> "任务 → 资源单实例"约束，**推不出**前者：多台设备同时干同一道工序并不违反任何一台设备的容量（每台都在
> 服务这一道工序）。要收紧为单实例，必须另有题面原文（分级①引用，如"每道工序仅由一台指定设备完成"），
> 否则默认允许分摊/轮换。**类型级 vs 实例级**：约束作用在设备"类型"（如"两类设备须分别完成该工序对应
> 工程量"）≠ 作用在"实例"（某一台具体设备）——类型级约束只规定哪几类参与、每类完成多少工程量，
> **实例如何分配（一台做完全部，还是多台并联分摊）是开放的**（mcm51-b 官方口径：A1 由 4 台输送臂 + 5 台
> 灌装机同时执行各 1080 s；我们误判为单台 5400 s → 四问时长系统性偏高，赛后评估 57–60/100）。
> **操作方法**：对 brief 中每条约束问两个问题——① 主语是"资源"还是"任务"？② 若主语是资源，是否有人把它
> 反转为任务约束？反转必须出示分级①的原文依据。

### 4.3 checklist 要点（MCM-51 教训提炼，逐问对照）

- **交付物类型先行**：r11 的 1.2 拿了 0–1 分，不是算错，是「做了力学 min、官方要变点检测」——
  类型错了整问归零。
- **题面措辞线索**：「突变点」三个字直接指向变点检测；漏读措辞 = 漏做官方要求的建模。
- **方法族 ≥2 + 淘汰理由**：写进 brief 的 `per_question_direction`（选定方向 + 禁止方向）。
- **单位口径逐问写明**：应力 vs 力矩、kN vs N、秒 vs 分钟（brief-v1 的 3.2 单位混比实证）。
- **必配图表**：评分标准类题目普遍按图给分；题面指定交付表格必须与题面格式对齐
  （如 mcm51-b 的表 1～表 5 排程表）。
- **数据使用注意**：附件表怎么读、要不要均值化/清洗、缺失值怎么处理 → `data_notes`。
- **题面信号清单（v3 口径防线，2026-08-26；机械检查，逐项记录 支持/反对/中性，结论写入 exploration.md，禁止只存在于对话中）**：
  ① **交付表模板是否注明"可加行"**——若交付表是"一工序一行"的固定结构，行数由工序数决定，不需要"可加行"声明；题面特意写"每个表格可以根据需要添加行数"，暗示一道工序可能对应多台设备、多行记录（mcm51-b 题面原样写了"可加行"，但没有任何环节把它读成"一工序多设备"的证据）；
  ② **同类设备台数与单工序需求的冗余**——班组配置表里同类设备多台（如 5 台灌装机），若该类设备服务的工序串行且不允许同工序并联，多台设备的价值只剩"跨车间并行"；若某类型设备是瓶颈工序的唯一执行者，单机完成时长会显著偏长。**问法：把多台同类设备换成 1 台，结果差多少？差异巨大而题面又配了多台 → 并联分摊是被预期的**（mcm51-b：A1 单机 5400 s vs 9 台并联 1080 s）；
  ③ **类型级 vs 实例级表述识别**——"某类设备完成 X 工程量"是类型级表述（"精密灌装机"是类型名，可数台），实例分配未定，需要裁决而不是默认单台；
  ④ **工程量守恒验证**——效率 × 台数 × 时长 = 工程量 必须能自洽；单台假设下若某工序时长与题面例子暗示的量级明显不符，应主动怀疑单台假设。
- **假设分级与禁令依据（v3 口径防线）**：写入 brief 的每条 prohibition 必须带分级与依据；弱依据（②/③）禁止某自由度时，必须同时给出备选口径（见 §3.3 裁决纪律）。

## 五、阶段 4：方向收敛与写入 brief

### 5.1 从认知地图到 brief 的压缩规则

- 认知地图（`exploration.md`）**不直接注入**流水线（容量：brief 每条 ≤200 字符、整块 ≤1500 字符级）；
  只把以下压缩后的条目写入 brief：
  - 主方向 → `per_question_direction`（选定 + 禁止）；
  - 次方向 / 备选 → 保留在 exploration.md；可作对照候选（M4 冻结期手工对照）；
  - 「必须考虑事项」→ `required_discussions` / `data_notes`；
  - 风险与口径红线 → `red_lines` + 机器可读 `redline_rules`（M3 批次 1 落地前先存文本）；
  - **假设/禁令条目保留分级标注（v3 口径防线，2026-08-26）**：prohibition 文本内注明"分级②：合理推断，无原文依据；备选口径=……"；"题面明确要求"字样只允许出现在分级①条目（带引号+出处）。
    示例（mcm51-b 假设 9 类条目的正确写法）：
    `"prohibition": "一道工序由多台同类设备共同分摊工程量（分级②：合理推断，无题面原文依据；备选口径=允许分摊，预期 A1 由 5400s 压缩至约 1080s，各问时长将显著下降）"`
  - 待验证假设 / 关键公式 → `formula_notes`（数值锚点只能从题面+附件+常识重建）。
- **未来自动化（双入口路线 A，07 行 19；2026-08-21 实操确认）**：第二轮（认知地图 v1）与第三轮（逐问清点）
  这两份收敛文档本身就是 `brief extract` 的理想输入——把 md 直接传入，一次 LLM 调用按上表映射生成
  brief.json 初稿，人工确认后落盘。mcm51-b 本轮先手工映射（2026-08-21 已产出 40 条初稿，`brief check` [OK]），
  命令实现后即成为标准入口。

### 5.2 字段映射表

| brief 字段 | 从哪来 | 注意 |
|---|---|---|
| `per_question_direction` | 方向结论表（选定+禁止） | 每条稳定 id：`<question_id>-direction` |
| `formula_notes` | 关键公式/参数 | 数值锚点只能从题面+附件+常识重建（防泄漏） |
| `required_discussions` | 出题人想看什么 + 分歧裁决 | `sections` 用白名单：abstract/problem_restatement/assumptions/notation/model_section/solution/sensitivity/conclusion/references |

| `scoring_notes` | 自拟 rubric 要点（**不是官方答案**） | 通用场景 = 从题面 + 探索推断的评分点 |
| `data_notes` | 附件使用注意 | 均值化/清洗/口径 |

| `background_knowledge` | 领域常识 + 专业背景 | 来源分级标注（human/model_draft） |
| `comparison_baselines` | 对撞中淘汰的候选方案 | M4 冻结期手工补对照（§六），字段暂不进 schema v2 |
