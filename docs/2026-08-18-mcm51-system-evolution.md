# Beacon 体系流程优化报告：外部知识注入与多视角推演

- 建立日期：2026-08-18
- 关联：MCM-51 锚杆题 r1–r11 全程实证
- 定位：体系级（非单题）优化探讨。回答三个问题：① 现有体系能否继续优化？② 未来多角度推演能否灌输外部信息，而非完全依赖题面？③ 哪些视角是体系自身无法拓展的？

---

## 一、现状盘点：体系的知识来源（代码事实）

当前 Beacon 流水线的知识输入通道，按 `src/math_agent` 代码逐一核实：

| 通道 | 位置 | 状态 | 容量 |
|---|---|---|---|
| 题面文本（problem/background/questions） | `run` 初始状态 → analyst/modeler 全链 | ✅ 主通道 | 全文 |
| 附件数据摘要（data_hint：列名/行样例/稀疏键提示） | `prompts/coder.py` 等 | ✅ 主通道 | 结构化摘要 |
| LLM 预训练知识 | 所有 `complete()` 调用 | ✅ 隐含 | 模型权重内 |
| 反馈循环（评审→重试→定向修复） | critic/consistency/low-score 通道 | ✅ 运行时 | 见 P01–P20 |
| **RAG 外部语料检索** | `rag/retrieve.py`；analyst/modeler/writer 注入点 | ⚠️ **默认关闭**（`RAG_ENABLED` 默认 `"0"`）；51mcm 从未启用 | TOPK=4，analyst/modeler 各 1500 字符、writer 800 字符 |
| 学术文献检索 | `tools/scholar.py` + `references.py` 静态库回退 | ⚠️ 仅 writer references 分组 | ≤10 条 |
| 历史教训沉淀（P 系列、docs） | `docs/` | ❌ **人读，不注入体系** | — |
| 官方评分标准 / 参考思路 / 获奖论文 | 无通道 | ❌ **完全缺失** | — |

**结论（事实）**：体系的"知识闭包" = 题面 + 附件摘要 + 模型预训练 + 反馈循环。RAG 通道**机制上已存在**（`math-agent ingest` 可把任意语料目录嵌入 `runs/rag.sqlite`），但默认关闭、容量有限、且只注入"检索上下文"而非结构化约束。**评分标准这类"比赛元知识"没有任何注入通道。**

## 二、实证缺口：r1–r11 证明的"视角盲区"

以本题官方评分标准为对照，列出体系 11 轮运行中**从未自发产生**、但外部资料中明确写明的视角：

| 视角 | 外部资料中的答案 | 体系表现（r1–r11） | 性质 |
|---|---|---|---|
| 问题1.2 应做**变点检测/分段回归**（非 min 力学模型） | 官方评分标准明确"突变点识别模型"，岩石 T_c∈[100,150]、煤体∈[150,200] | r11 仍用工况A参数直接算 600.71，方向性错误 | **方向盲区**：题面只说"给出临界预紧力矩"，未提示方法 |
| F_bond 用**钻孔直径** D_hole（非锚杆直径） | 附录2 公式 F_bond=π·D_hole·L_bond·τ；工况A=334.27kN、B=169.65kN | r11 用锚杆直径，数值错 245~565 倍 | **细节盲区**：题面公式存在但未强调参数选择 |
| 问题3.1 **调心垫圈定量分析**（10 分） | 评分标准：e=0 参考线、e_cr≈3.66mm、e=5mm 提升 233%、150 N·m 规范线 | r11 完全未提及调心垫圈 | **概念盲区**：题面附录1 符号表有"调心垫圈"，但问题3 正文未提 |
| K 按直径使用（工况A→K₂₀、B→K₂₂） | 评分标准参考结果三组 K | r11 全用整体 K=0.176681 | **粒度盲区** |
| 问题4 应建 **min 四约束统一模型** + 围岩分级 | 评分标准：T_opt(f)=min{T₁..T₄}，软/中/硬三级 | r11 用拍脑袋 T_opt=0.8·T_max | **结构盲区** |
| f→E 必须**参数化假设 + 敏感性**（不能拍脑袋） | 评分标准开放性说明；官方思路强调"不要伪装成唯一确定" | r11 用 E=f×1e9 被 sensitivity 校验拦截 | **严谨性盲区** |
| 压陷公式 δ=P(1-ν²)h₀/(E·b²)，h₀=900mm 载荷影响深度 | 附录2 明示 | r11 用 k·A_b 近似，h₀ 参数未用 | **公式盲区** |

> **核心事实**：这 7 项没有一项需要"更聪明的模型"——全部是**外部资料中已写明、但体系无法获取的信息**。r1–r11 的反馈循环只能在"题面+预训练"闭包内试错，闭包外的视角（调心垫圈、变点检测）无论跑多少轮都不会自发出现。这直接回答了"依赖于体系本身完全无法拓展"的担忧——**属实，且已实证**。

## 三、为什么体系无法自行拓展这些视角

1. **输入即边界**：analyst 的 blueprint 只由题面+背景+问题生成（`prompts/analyst.py`），没有"评分标准/参考解法"输入项。模型只能从题面和预训练知识猜测出题人意图。
2. **反馈循环是闭包内的**：评审（model_critic/paper_critic）也是同一个模型家族，其判断基准同样是"题面+预训练"——它不知道评分标准要求变点检测，就不会因为"你没做变点检测"而拒绝。r11 一致性评审自认"未实现分段拟合"仍给 9 分（P17），正是闭包内评审的体现。
3. **RAG 通道存在但从未启用**：51mcm 全程 `RAG_ENABLED=0`。即便启用，也需先有人把评分标准/参考论文/领域文献 ingest 进库——**"谁来准备语料"本身就是人工环节**。
4. **多视角机制不存在**：全链单 analyst、单 blueprint、单 modeler 路线。没有"数据驱动视角 vs 力学视角 vs 工程视角"的并行推演或反方论证。

## 四、优化方向（设计建议，本轮未实现）

按"投入产出比"排序：

### A. 外部资料包注入（最高优先，改动最小）
- 题目 spec（`run --problem` 的 JSON）增加可选字段 `reference_material`（评分标准/参考思路/领域知识/获奖论文摘要的文本或文件路径）。
- analyst 与 blueprint_critic 的 prompt 注入该资料包，并加硬性指令："参考资料中的方法要求优先于你的默认建模直觉；若与题面冲突，在 blueprint 中标注来源"。
- 同时注入 modeler/coder 关键节点，作为建模路线约束。
- **效果**：本题若注入官方评分标准，1.2 变点检测、3.1 调心垫圈、2.2 钻孔直径 7 项盲区可一次性消除（无需多轮试错）。

### B. RAG 常态化（机制已有，补齐启用与语料）
- `MATH_AGENT_RAG_ENABLED=1` + `math-agent ingest` 把 `docs/`、官方资料、参考论文嵌入 `runs/rag.sqlite`。
- 现状限制：TOPK=4、每节点 ≤1500 字符——对"评分标准全文"这种高密度约束可能截断，需按题型分层（评分标准走结构化注入 A，领域知识走 RAG）。
- 检索 header 已有"仅供启发，不可照抄"声明，符合竞赛诚信。

### C. 评分标准 → 机器可读门禁（衔接 O06）
- 把评分标准中的"参考结果范围"（如 T_c∈[100,150]、F_bond,A=334.27kN±5%）解析为 blueprint 的 `validation_mapping` 数值区间，进 coder 提示 + 一致性门禁（确定性校验）。
- 这正是 O06"pass_criteria 机器可读提取"的落地路径，且能直接修掉 P17（评审放行"自认缺失"）。

### D. 多视角并行推演（中期，工作量中等）
- analyst 阶段并行产出 2–3 份 blueprint（如：数据驱动视角 / 力学解析视角 / 工程实用视角），blueprint_critic 综合择优或融合。
- 或增加"反方推演"节点：对已通过 blueprint 主动提出"出题人可能期待的另一种解法"。
- 注意成本：每视角一次 LLM 调用，需与收益权衡。

### E. 知识沉淀回灌（长期，成本最低）
- 每题的教训（如本题 9 条转向清单）写入 `docs/`，并通过 A/B 通道注入后续题目。
- 沉淀文件本身可 ingest 进 RAG 库，形成跨题经验库。

## 五、风险与边界

| 风险 | 说明 | 对策 |
|---|---|---|
| 外部资料误导 | 非官方推演（如 GPT 思路）可能错误；评分标准也可能有不同解读 | 资料包来源分级：官方文件 > 人工整理 > 模型推演；analyst 需标注引用来源 |
| 照抄违规 | 参考论文/思路直接进论文 | RAG header 声明 + table_assembler 禁用词清洗 + writer 数值溯源硬约束（已有） |
| 信息过载 | 大段资料挤占模型上下文，稀释题面注意力 | 容量上限（1500 字符级）+ 仅关键节点注入 + 结构化为要点而非全文 |
| 依赖人工准备语料 | 资料包/RAG 语料需人工整理 | 每题一次准备成本，多题复用（E 通道） |

## 六、结论

1. **体系可以继续优化**，且突破口不在"更严格的评审/更多重试"（P01–P20 已证明这条路在收敛），而在**打破知识闭包**——让外部信息（评分标准、参考解法、领域知识、历史教训）进入建模决策。
2. **"灌输外来信息"在机制上可行**：RAG 通道已存在（默认关闭），学术检索已有雏形；缺的是①题目级资料包注入（A）、②评分标准的机器可读化（C）、③多视角推演（D）。
3. **体系自身无法拓展的视角已被 r1–r11 实证**：7 项盲区全部是"外部资料写明、体系闭包内不可达"的信息。**这不是模型能力问题，是输入设计问题**——输入即边界。
4. 建议下一题或下一轮迭代前，先落地 A（资料包注入，改动最小、收益最大），C（评分标准门禁化）随 O06 一起做；D 视成本评估。
