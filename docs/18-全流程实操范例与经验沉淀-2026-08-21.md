## 四、阶段 2：轨 A（流水线）实操——5 次运行的故障谱

| # | 运行 | 停点/结果 | 根因 | 修复 | 成本 |
|---|---|---|---|---|---|
| 1 | supervise（初始 brief 40 条） | 一致性门禁 0/10 停机 | **total_cost 守卫误杀**：非物流题输出校验把通用成本名当物流指标整份拒绝 → 无主证据 | `_GREEN_METRIC_NAMES` 移除 total_cost（**校验要落语义，不能只看名字**） | 356k tokens |

| 6 | 全新 run（冻结版，05:31） | **全流程首次跑通**：一致性 score=9 通过 → sensitivity/figure/writer/evaluation → **degraded 终态**（completion.json：有效对照方案 0、论文评审 7/10、结果正确性 6、LaTeX 10 处严重溢出；paper.md/tex/pdf 已产出，82 调用 / 536.2k tokens） | 机制成功但内容三缺陷：① 模型章声称 CP-SAT/MILP 精确求解 vs 实际 exec 参考求解器（启发式）——违反 rl-greedy 红线；② 敏感性基准 124943.7 与主方案/Q3 均不符（**脚本根因已查证：budget 参数未用、未取整、C 展开错序**）；③ 40.9%/41.0% 无依据且不一致；**④（G10b）coder 早于参考实现两轮 bug 修复执行，论文数值含旧 bug 无效** | **处置待决策（2026-08-26）**：degraded 产物数值无效 → 建议归档放弃、全新重跑验证修复效果（19a 轨 A 结论依赖有效数值）；A/B 互补评审报告见 runs/mcm51-b-brief-v1/A-B互补评审报告.md | 536.2k tokens |

**机制级教训**：
1. **门禁停机（无主证据）→ `recover` 空转**（checkpoint `next=()`，B05 语义）——修根因后只能全新 run；
2. **每次 brief 变更 → restart 输入不变性校验拒绝** → 全新 run，单次成本 35–50 万 tokens——小修复的大代价，
   这正是恢复性机制（计划 11：pause/restart 人工放行）与「人工放行重试 coder」的价值来源；
3. **coder 对新题型的不可靠是结构性的**（4 次失败全部是生成代码 bug：守卫、键名、解析、契约）——
   **参考实现（人工供给）是可靠的降级路径**，且与「方向生产外置」是同一哲学：最贵的智能放在前端；
4. 修 prompt 能 recover、修 brief 只能重跑——输入不变性校验本身是对的，但要提前算进成本。

**产物独立文件夹**：`runs/mcm51-b-skill-v1/`（与轨 A 的 `runs/mcm51-b-brief-v1/` 平行对比）。

### 5.1 分工设计（子 Agent 三分离）

| Agent | 职责 | 关键产物 |
|---|---|---|
| 数据 | 跑参考求解器 + 敏感性（资源/速度/预算曲线/CPM 下界）+ 证据清单 | `data/solver_full_output.txt`、`data/sensitivity.json`、`data/evidence.md`（每个数字→来源文件+行号） |
| 写作 | 按 brief 八条 required_discussions + 章节白名单写论文 | `paper.md`（表 1–5 从真实输出逐行摘录，自查回源） |
| 评审（待启动） | 参考实现 vs brief 口径系统审计 + 论文数值回源/一致性/诚实性 | 核查报告 |

### 5.2 多 Agent 交叉审查的价值（本轮最大收获）

**写作子 Agent 独立抓出参考实现两处隐蔽 bug**（探索层早就写对、实现层漏掉的口径错误）：

1. **C 循环链只展开 C3**：题面备注「C3–C5 完成 1 遍后需再重复 2 遍」= 三种工序整体三轮（9 活动），
   实现只把 C3 展开三轮、C4/C5 各一次 → 修复为 C1→C2→(C3_1,C4_1,C5_1)→…→(C3_3,C4_3,C5_3) 共 11 道活动；
2. **C1/C2 键名不匹配排到链尾**：排序键用短名 `"C1"` 查活动全名 `"C1.旧涂层剥离"` → 回退 99 → 链序变
   C3_1→…→C5_3→C1→C2 → 修复为前缀正则键 → 链序正确（Q3：144859→127085，-17774s）。

**结论：独立 agent 交叉检查能发现同源自审发现不了的口径错误（H04 相关判断者的正面解法）——
参考实现交付前必须做「实现 vs 口径」系统审计（评审 Agent 的固定职责）。**

### 5.3 数值演化（三轮重算，最终口径）

| 问 | 初版（C3 只展开） | 修复 1（整体三轮但链序错） | **最终（链序修正）** |
|---|---|---|---|
| Q1 | 41600s | 41600s | **41600s**（精确最优，CPM 差距 0%） |
| Q2 | 147143s | 215303s | **215303s**（差距 74.2%，单班组容量不足） |
| Q3 | 135068s | 144859s | **127085s**（差距 2.81%） |
| Q4 | 116209@75000 | 123844@155000 | **123844@155000**（多功能机×1+抛光机×1 班组1；距 CPM 下界 0.19%） |

**敏感性发现（可迁移的建模素材）**：
- **瓶颈判断**：自动传感多功能机 +1 → −1.68%（唯一有效单台增量）；高速抛光机单独 +1 无效；
- **互补瓶颈效应**：抛光机作为第二台购置（多功能机之后）再省 ~1100s——**单台边际分析会低估组合购置价值**，
  预算-工期曲线因此呈**双拐点**（100000/200000）而非单拐点；
- **速度敏感性极弱**（1.5→3.0 m/s 仅 −0.38%，边际递减）——瓶颈是加工容量而非转运；
- **CPM 无容量下界对照**：关键链 C=123614（取代 D）；Q4 距下界仅 230s（0.19%）——启发式在双班组+购置下几乎达无容量下界。

## 六、失败模式与反模式清单（⚠️ 可迁移，最重要）

1. **校验只看名字不看语义**：`total_cost` 通用成本名被物流指标黑名单误杀（守卫误伤类问题的通用教训：
   确定性校验要落在语义/组合信号上——M3 红线机器化设计时沿用）；
2. **键名混用**：全名 vs 短名、别名、大小写——生成代码与数据字典必须同一套键（C1 vs C1.旧涂层剥离）；
3. **隐藏结构未在实现层验证**：C 循环链——探索层（第三轮）写对了「9 活动」，实现层漏了；
   凡是 brief/认知地图标注 🔴 的结构性口径，参考实现交付前逐条核对；
4. **生成代码臆造契约**：包装代码自己发明 RESULT 格式 → **契约显式化**（参考实现给出逐字格式）+
   「原样透传、禁重解析、禁重绘」；
5. **启发式冒充精确主方案**：必须诚实声明 + CPM 下界对照（差距% 是论文的诚实性证据，不是减分项）；
6. **门禁停机 recover 空转**：无主证据停机 = 修根因重跑（或计划 11 的 restart 人工放行），不要 recover；
7. **输入变更成本意识**：改 brief 一次 = 全新 run 一次（35–50 万 tokens）——把修复合并批次再跑；
8. **单 Agent 自审盲区**：数据/写作/评审三分离，独立 agent 交叉抓口径错误（本轮两处 bug 皆由此发现）；
9. **附件多版本并存**：中文/英文副本按内容识别，不按文件名/glob 顺序；
10. **运行中修改参考实现**：轨 A 的 coder 运行时才读文件——修复会半路生效造成「数字来源混乱」；
    参考实现必须**冻结后**再启动任何消耗性运行（冻结=哈希登记 problem.json source_files）。

```

   - 简单/标准题型 → 直接轨 A（让 coder 试，失败再降级）
   - 复杂/多隐藏结构题 → 直接参考实现（人/agent 供给）：实现 vs brief 口径逐条审计
     （活动数/链序/双设备/运输/范围/RESULT 契约）→ 冻结（哈希登记）→ 才允许消耗性运行
4. 论文生产双轨：
   - 轨 A：supervise --force（冻结参考实现后）
   - 轨 B：数据子 Agent（solver/敏感性/CPM/evidence）→ 写作子 Agent（八条 discussion/表 1–5 真实数据/零编造）
     → 评审子 Agent（实现审计 + 论文回源/一致性/诚实性）
5. 对比与决策：质量/成本/可靠性 → 07 19a
6. 沉淀：新失败模式回填本文件 §六；数值/流程回填实现计划与 README
```

  （必读文件清单/章节白名单/八条 discussion 逐条落点/零编造自查回源/诚实声明/文献真实性规则）；
  评审 Agent（口径逐条核对表 + 回源抽查 + 一致性 + 诚实性）。
- **轨 B 评审 Agent 口径核查必答项（C3 注入，2026-08-26）**：评审 Agent 输出必须逐项覆盖——
  ① 假设逐条核查（"题面明确要求"类声明须有题面原文依据；同假设内"明确要求"与"未要求"并存视为矛盾，
  跑 `scripts/check_assumption_claims.py`）；② 大差距根因（任何下界/对照差距 >15% 必须给机制性解释，
  禁止免责声明，跑 `scripts/check_gap_trigger.py`）；③ 数字溯源与敏感性口径（正文数字与脚本输出不符视为
  编造；敏感性档位必须出自实跑，跑 `scripts/check_paper_numbers.py --strict`）；④ 得分点覆盖
  （有细则/得分点清单逐条核对，无则检查题面指定交付物齐备性，见 `8-26-F类-得分点清单模板.md`）。
  轨 A 的 evaluation/paper_critic prompt 已同步注入（src/math_agent/prompts/，2026-08-26）。
- **轨 B 求解脚本产出规范（五条，B 类轻量版，2026-08-26 用户确认）**——数据 Agent 的求解脚本必须满足，
  评审 Agent 逐条核验：
  1. **口径参数化**：口径相关假设（允许同类分摊、取整规则、进场运输、不可抢占、双设备异步等）必须做成
     脚本**顶层参数/常量**，禁止写死在求解逻辑里；参数默认值与 brief 裁决一致并注明出处
     （mcm51-b 教训：假设 9 写死在构造式启发式里，纠正成本 = 整轮重算；参数化后 = 改一个开关）。
  2. **分歧双跑**：brief/方向生产裁决过并保留备选口径的分歧点，必须产出**两组数字 + 对比表**
     （主口径 vs 备选口径，含差值与百分比），作为 evidence 的一部分——备选口径下结果会差多少，
     必须成为可引用的数据，而不是赛后才发现的盲区。
  3. **诊断明细**：输出必须含：每工序耗时明细（可回溯到表 1-5 每一行）、设备利用率、瓶颈识别
     （最长链/占用率最高设备）；RESULT 行格式统一（`RESULT: baseline=ours makespan=…` 全关键值可 grep）。
  4. **evidence 格式**：每个关键数字 → 来源文件+行号（evidence.md）；输出文件与论文数字一一对应。
  5. **哈希登记**：脚本定稿后登记 sha256（problem.json source_files 或 run 产物），作为可复算锚点；
     修改脚本须重登记并重估全部数字（轨 B 数字 100% 回源的前提）。
- **双轨实验约定（G 类，2026-08-26）**：① 至少一轨带**独立口径复核**——第二读者（不同模型/人）重新读题
  产出竞争口径集，与主口径对比后再定稿；② 互补评审结论必须声明**同源盲区**（双轨共享 brief 与求解口径时，
  只能比较执行质量，不能作为建模正确性证据；mcm51-b A/B 互补评审未触达假设 9 即同源所致）。

## 十一、8-26 C 题（mcm51-c）第二批实操经验（2026-08-26）

> 来源：`docs/8-26-C题记录.md`（C 题全流程：轨 B 主会话+子 agent + 轨 A 参考实现整合真跑）。
> 本节约束：只保留**可迁移操作经验**；题目细节与过程日志见归档记录；8-26 已落地改造（B 类五条 / C3 / G 类 / D 类闸门）已并入 §十速查，不重复。

### 11.1 流程操作经验（第二批，mcm51-c 实测）

- **子 agent 分工与产物回流**：按小问分组（Q1+Q2 / Q3 / Q4+Q5，方法族相近 + 无跨组硬依赖）；每组固定工作目录 `runs/<题号>-skill-v1/solve/<分组>/`——这是**回流锚点，必须在 prompt 里写死路径**；prompt 必须**自包含**（子 agent 看不到主会话上下文：必读文件 / 数据路径 / 环境约束 / 格式一次性给全）。
- **派发后确认状态（A 档新增，2026-08-26）**：后台派子 agent 后，返回「started subagent」**不等于真的在跑**——A1/A3 首次派发停在 `[ready]` 没执行，`send_message` 唤醒后才转 `[running]`。派发后要 `list_agents` 确认状态是 running，再进入等待。
- **主会话交叉核验（抓 Q1 bug 的关键机制，强烈建议保留）**：不信子 agent 自报「整模型指标」——Q1 子 agent 整模型 RMSE=2mm（自报好）但表 1.1 四点偏离 B 达 26–184mm；只有用**独立锚点**（数据画像 F1 的 5 个 B 同刻读数）逐格核验关键交付表才能发现。教训：**交付表逐格核验，不能只看汇总指标**；改进方向：每问锚点预先登记在 brief/data_notes，可脚本化。
- **子 agent 反模式三件套与对策**（实测）：

  | 反模式 | 表现 | 对策 |
  |--------|------|------|
  | polish 循环 | 反复重跑同一 buggy 代码、只改图不改数、数分钟不推进 | 监控「文件时间戳 + 关键值不变」，`interrupt_agent` 中断 |
  | 抵抗返工 | evidence 里为 bug 辩护（「不同参数化」），不主动改 | interrupt + `send_message` 重发**带数值判据**的返工指令 |
  | stale 中间文件 | refine 后输出文件一度是旧值 | 以子 agent 最终报告为准，不核验中间文件；收尾自检「输出文件与报告一致」 |

- **环境预检必须前置（本次差点翻车）**：venv 只有 numpy/scipy/pandas/matplotlib/openpyxl，**无 sklearn/ruptures/statsmodels**；认知地图却写 GBDT/SHAP/贝叶斯变点。启动求解前 `importlib.util.find_spec` 查库，把结果写进求解 prompt（「只许 numpy/scipy」+ 替代映射：变点→自实现 BinSeg、鲁棒回归→scipy.optimize、SHAP→偏相关+增量R²、GBDT→线性+爆破二值特征）。已做成 cli.py `--dry-run` 预检（A3，WARN 不阻断）。
- **数据驱动对撞（本批最有价值的流程发现）**：旧流程各家先凭经验列方法族（方法名 PK）；新流程**先把 EDA 做完 → EDA 证据包喂给第二家 → 第二家做「数据驱动的候选淘汰」→ 消化出认知地图**。收益：GPT 淘汰贝叶斯变点/小波/GBDT（过度或依赖 sklearn），对撞从「方法名 PK」升级为「数据证据淘汰」，收敛到「决策点」而非「方法名」。改进：EDA 证据包做成方向生产固定中间产物；对撞提示词默认「先淘汰、后选主」。
- **等待与节奏**：子 agent 完成会主动通知，主会话收到通知后一次性处理（汇总 evidence → 跑 check → 评审）；**不做 busy-polling**（每 20–60s 查文件浪费轮次）。
- **check 工具题目类型适配**：`check_gap_trigger`（下界 vs makespan）是调度题专用；预测题（C 题）无 makespan，适配为「备选口径/预测误差差异 >15% 触发口径核查」。

### 11.2 返工指令判据（批次 5：主会话处方被数据纠正）

- 返工指令的验收判据应指向**要消除的病灶**（「自由三参数退化、跳变点崩掉、表 1.1 偏差须到个位数 mm 以下」），**不要死定一个数值处方**。
- 实例：主会话写死「必须 β1=1」，子 agent 用 4 种方式实测 B~A 斜率 = 0.8807–0.8817（r=0.9996 是相关不是斜率），β1=1 在跳变谷底残留 5–37mm；最终 **B = 0.8817·A − 0.5245**，表 1.1 五点偏差 ≤0.038mm。
- 正确写法：「约束增益为一个固定值，其值由数据实测 B~A 斜率决定」。

### 11.3 论文生产流程反思（批次 6，用户提出）

- **分段书写 vs 单 agent 全篇**：单 agent 同时承载 9 discussion + 11 红线 + 3 evidence + 5 交付表，上下文极长、**前后口径漂移风险高**（本次 writer 靠自检纠 2 处）；分段式（按 5 问分 + 摘要/假设/结论/附录各一段）可并行聚焦，但引入跨段一致性问题——迭代方向：**分段 writer_section + 一个「主编」agent 拼装 + check 闸门兜底**，优于单 agent 全篇。
- **写作对「实验验证」最不重要（但证据链封边不能丢）**：方向对不对/数字对不对/口径有没有翻车由对撞、求解、check 闸门、评审负责，polished prose 贡献最小可省。边界：mcm51-b 表 9 造数就发生在论文阶段——「写作不重要」成立的前提是 `check_paper_numbers` 仍在。迭代：验证用「最小论文」（摘要 + 交付表 + 数字 + 诚实声明），交付前再精写。

### 11.4 轨 A 参考实现整合与真跑结论（批次 8/9）

- **整合机制（可复用，已实测）**：① coder 只注入 brief 的 `red_lines` + `formula_notes`（`render_coder_brief`），**不注入 `data_notes`** → solver/参考实现条目必须放 formula_notes + red_lines；② `_read_problem_spec` 把相对 `data_dir` 解析为绝对路径；③ RESULT 门禁：`RESULT: baseline=ours <ascii>=<数值>`，≥4 指标，禁 %/字符串/nan/inf，指标名避开 cost/count/rate；④ 血缘门禁：wrapper AST 需 loader 调用 + 真实附件名，运行时 audit hook 记录 → wrapper 需列出 `DATA_FILES=[附件中文名]` 或 glob；⑤ `exec` 共享命名空间 → reference 可直接用 wrapper 的 `data_dir`。
- **真跑结论（核心验证达成）**：coder 精确按 `formula-reference` exec 参考实现（wrapper 三件套全对），`model_code_consistency` **score 9/10、approved、has_primary=true**，论文摘要关键数字全对。**下游 4 缺口**：① 补充图自写错数（参考实现「一体式」vs pipeline「每图独立一段代码」**粒度错配**）；② 敏感性节点失败（blueprint 指标名 ≠ RESULT 字段名）；③ 有效对照方案 0（只给主方案没给对照/基线）；④ paper_critic 7/10 + LaTeX 溢出（1–3 连锁）。
- **结论与决策**：「brief 注入 + 参考实现」主方案代码生成环节跑通，但「整条轨 A 自动出高质量论文」未跑通；若要让轨 A 出好论文，参考实现需提供**分图代码、对照方案、与 blueprint 指标名对齐的 RESULT 字段**。**用户决策（8-26）：轨 A 出好论文降级为不重要，仅记录**（决策登记 07）。

### 11.5 评审两层防线（批次 7）

- 主会话交叉核验（抓 β1 数值 bug）与评审 agent（抓「数字正确但表述误导」：百分比基准 14.38%→16.8%、少 66%→少 40%、Hampel 0.68 语义、失效引用）是**两层不同防线**，不可互相替代——评审对「数字正确但表述误导」有独立价值。
- mcm51-b 三类逃逸模式（「题面明确要求」无原文 / 大 gap 当诚实声明 / 数字无溯源）在 C 题**均未出现**——数据语义三裁决进假设且分级正确、关键数字 100% 回源、四张表逐格对齐、gap 均有机制解释。
