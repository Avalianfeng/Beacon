# D-008 · T-19 冻结资产直接执行（跳过 coder LLM 生成）

- 日期：2026-08-27（P-02 批准）｜ 状态：accepted → ✅ 已执行（A-13，commit `72ee4a5`）
- 决策编号：07 决策表 D-008

## 背景

- S9 流水线历史上 2 个**停机根因**：coder 对 reference 目录 `listdir()` 遍历失败（权限/结构变化）崩溃；read-only 资产被 coder 当普通代码读写。
- 存在冻结参考实现（如 `problems/mcm51-b/source/reference_solver.py`）时，coder 仍让 LLM **重新生成一份代码**：烧 token（brief-v1 54 万 tokens 量级中 coder 占大头）、产生变体漂移（每次 run 代码不同）、可能抄错。
- `docs/19-解题验证线路设计.md` §四·§五 已有完整方案设计，但该文 2026-08-27 标 superseded 后方案悬而未决。
- 原则 8 反对无依据生成：有确定性资产却让 LLM 重写，属于体系内浪费。

## 决策

**采纳**：coder 检测 `problem.json` source_files / `reference.json` 登记的冻结资产 → **sha256 哈希校验** → 命中则直接 runner 执行确定性 wrapper，**generate 零 LLM**；哈希不匹配/路径失败 = **失败闭环**（明确报错停机，不回退 LLM 生成）。队列缩为 1 条 primary，timeout=600。

## 后果

- **正面**：2 个停机根因归零（wrapper 不 listdir reference/）；省 token（有参考实现时零 LLM 生成）；可复现（哈希锁：执行=登记的那一版）；变体漂移消除；失败语义明确。
- **负面**：资产登记**错误时"可复现地错"**——机制保证可信与可复现，不保证正确性；改代码必须更新 problem.json 哈希登记（否则失败闭环）。正确性兜底 = 赛后校准（`report_calibration_diff`）+ `check_paper_numbers`（D-012）+ 前置方向质量（brief/playbook）。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 先原型再全量 | 方案已有完整设计（docs/19），额外真跑成本无信息增量 |
| 不采纳（维持现状） | 持续烧 token + 停机风险；有确定性资产却让 LLM 重写违反原则 8 |
