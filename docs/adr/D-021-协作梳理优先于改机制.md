# D-021 · 协作梳理优先于改机制（agent 协作协议 + 三问判定准则）

- 日期：2026-08-27（用户拍板）｜ 状态：accepted → 已执行
- 决策编号：07 决策表 D-021

## 背景

- A-08（清单型表装配）讨论中用户质疑：「正文一部分+附录全量」交给 agent 临时脚本即可，为什么一定要 Beacon 完成？并指出更根本的问题：**agent 与 Beacon 的协作能力是否存在欠缺**。
- 验证发现 `check_paper_numbers --evidence` 已支持任意 md/txt/json 证据文件（白名单提取）——agent 临时脚本落盘的清单文件可直接进白名单，红线覆盖已具备。
- 历史模式问题：「觉得需要就改」——遇到缺口就给 Beacon 加机制（A-08 即此模式），而非先梳理协作边界。

## 决策

**协作梳理优先于改机制**：

1. 新建 `docs/agent协作协议.md`（contract）——职责边界（agent/Beacon/D 盘）、协作接口清单（已有 9 项）、**三问判定准则**；
2. 三问判定准则（新需求先问）：
   ① 是机械/确定性职责吗（可复现、哈希、装配、闸门）→ Beacon 做机械件；
   ② 是红线相关吗（数字溯源/证据一致/口径核查）→ Beacon 提供机械校验件；
   ③ agent 临时脚本 + 现有接口能否覆盖 → 能则不建新机制，只写约定；
3. 首轮判定落地：**A-08/B-01 取消**（agent 临时脚本 + `--evidence`）；A-04/A-07/A-10 降级（协议/agent 承担）；A-05 保持协议层；A-11/A-02/A-03/A-12 保留（机械职责）。

## 后果

- **正面**：协作边界有单一权威文档；新缺口有判定流程，不再凭感觉加机制；03 池瘦身（取消/降级非机械职责任务）；agent 临时脚本产出有参考约定（落盘/登记/白名单/附录）。
- **负面**：取消的机制若未来证明高频需要（如每次题都手拼清单），需重新按三问判定——协议不禁止，只是提高改机制的门槛。
- **兜底**：三问判定结果可推翻（登记 D-xx + ADR 留痕）。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 维持 A-08（Beacon 内建清单装配） | 三问③=能覆盖；机制价值弱（"装配什么"取决于 agent 输出格式，不可预知） |
| 什么都不梳理 | 每次遇到缺口重复争论；协作边界无权威文档 |
