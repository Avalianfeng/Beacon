# ADR 索引（Architecture Decision Records · 决策详情文件）

> **定位**：`docs/adr/` 存放**体系级决策的详情文件**（背景/后果/备选方案长文），让决策可回查、可追溯、可评审。
> **关系**：[07-待决策与超范围](../实现计划-8-20/07-待决策与超范围.md) = 唯一决策登记表（D-xx 编号，索引行）；本目录 = 决策详情文件；[8-27-完整图景/02-决策台账](../8-27-完整图景/02-决策台账.md) = 图景摘要；`docs/log/` = 时间线。
> **历史决策（D-001~D-018）不迁移**（07 表内长行保留）；其中 D-008 / D-016 已补写为示范文件（见下）。

## 触发标准（什么决策写 ADR）

同时满足（与 07 三条件判定一致）且**需要长文背景**（07 表行放不下）：

1. 难以逆转（架构/方向级）；
2. 有真实取舍（多方案对比、否决了备选）；
3. 影响多个文档/后续工作。

普通决策（机械/小修/纯文档）只在 07 表登记，不写 ADR。

## 模板

```markdown
<!-- doc: type=decision status=active updated=YYYY-MM-DD -->
# D-0NN · 标题

- 日期 / 状态 / 决策编号（07 表行）

## 背景        — 动机、证据（runs/文档编号）、问题现状
## 决策        — 拍板内容（一句话可引用）
## 后果        — 正面（收益）/ 负面（代价与风险）+ 兜底机制
## 备选方案    — 否决过的选项 + 否决理由（防复燃）
## 关联        — 任务（03 池 ID）/ 文档 / 后续验证
```
