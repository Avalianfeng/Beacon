# D-020 · 恢复 Beacon 产完整论文职责 + A-01 原义

- 日期：2026-08-27（用户纠偏）｜ 状态：accepted → 已执行
- 决策编号：07 决策表 D-020（D-019 被本决策取代，标 superseded）

## 背景

- D-019 曾把「prose 归 D 盘」并作废 A-01（骨架→终稿 prose 展开）——**该决策系误读**：
  1. 把「mcm51-c 轨 B 终稿由外部 agent 写」（双轨对比实验的一个数据点）推广为「prose 以后都归 D 盘」；
  2. 误用 D-005（讲**执行方式**：无人值守 → 分阶段协作）论证**产出物**（不产论文）——两者不是一回事。
- 文档中的原始定位（证据）：
  - 总纲 L59：交接物 = `paper.md`（**骨架/终稿**）——prose 展开后即终稿，Beacon 产出的就是论文本体；
  - 总纲 L107：「T-xx 待实现项（brief extract/数据探查命令/**骨架→终稿 prose** 等）按需慢慢推进」——A-01 本来就是待实现项；
  - 18 文档轨 A run6：「全流程首次跑通……writer/evaluation……paper.md/tex/pdf 已产出」——**体系产完整论文的能力已真跑验证**（degraded 但本体由体系产出）；
  - 18 文档 L135：轨 A/B 为对比实验，轨 A（体系产论文）仍是主路径候选。

## 决策

**恢复 Beacon 产完整论文的职责**。真实工作流（用户澄清）：

1. 前置工作（探索/brief/口径裁决）完成后，**agent 按方向写代码 + 数据计算结果**；
2. 将**明确的方向性内容**（brief 等）注入体系跑；
3. 遇到问题回来检查：是**体系的问题**还是**方向/计算可以改进**——二者**互相协作**；
4. 继续跑到**产出完整论文**；
5. 做区别对照：**数据与科学度用 agent 跑的版本，论文本体用 Beacon 自己产出的**，作为 D 盘改动依据；
6. D 盘只做**拆开 + 小改造**（Word 化等），不重写论文。

A-01 恢复原义 = **骨架→终稿 prose 展开机制**（操作面接入 writer 能力，P0/P1）；B-02 恢复；契约 T-11 恢复「待实现」；评估机制（S7 review-check / paper_critic）围绕完整论文保留。

## 后果

- **正面**：职责与文档原始定位一致（18/19/总纲）；评估机制（S7/L4/check_paper_numbers）重新有意义；A-01 成为操作面补齐论文产出的正当缺口。
- **负面**：prose 展开机制需实现/接线（原 D-019 曾想绕过）；体系产 prose 的数字红线需严格（check_paper_numbers 把关，D-012 已有）。
- **保留**：D-005 的执行方式结论不变（分阶段协作，不无人值守）；D 盘论文化精修（Word 化/小改造）不变。
